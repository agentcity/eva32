# AI-фабрика EVA32

Рабочий процесс как в `orioncode` и `distributed-db`: задача — файл, агент —
исполнитель, отчёт — приёмка.

## Иерархия

```
Юрий  ──ставит задачу──▶  Сарон (архитектор)
                             │  пишет ai/tasks/NNNN-*.md, декомпозирует
                             ▼
                         субагенты (до 8 одновременно)
                             │  делают, отчитываются в задаче
                             ▼
                         Сарон принимает: проверяет критерии, ставит статус
                             │
                             ▼
                         отчёт Юрию
```

## Правила

1. **Задача = файл** `ai/tasks/NNNN-<слаг>.md` с YAML-фронтматтером по шаблону
   `ai/tasks/_template.md`. Номера не переиспользуются.
2. **Реестр** `ai/tasks/index.json` — `{id, title, status, file, assignee}`;
   обновляется в том же коммите, что и файл задачи.
3. **Статусы**: `pending` → `in_progress` → `review` → `done` | `blocked`.
4. **Ссылка в коммите**: тело каждого коммита содержит
   `Задача: NNNN` и `Refs: ai/tasks/NNNN-<слаг>.md`.
5. **Приёмка**: агент заполняет раздел «Отчёт исполнителя»; Сарон проверяет
   критерии командами и только тогда ставит `done`.
6. **Мердж** — не автоматический: изменения принимает Сарон, финальное слово
   по релизу за Юрием.

## Что считается отчётом

- что сделано (файлы, коммиты);
- чем проверено (команды и их вывод, а не «работает»);
- что осталось и какие риски;
- если критерий не выполнен — так и написать, не подгонять.

## Границы

- Агент не коммитит и не мержит: правки сдаёт, коммит делает архитектор.
- Агент не выходит за свою зону файлов (указана в задаче).
- Задача без критериев приёмки не выдаётся.
