# Голос: адаптер TTS с фолбэком (Piper)

## Проблема

Голосовой прототип работает, но TTS — заглушка/системный `say`. Для «замены Алисы»
нужен локальный нейро-TTS. Piper ставится без GPU, но требует бинаря и модели —
нужен адаптер, который не ломает работу, если их нет.

## Требования

- `eva/tts.py`: интерфейс `synthesize(text) -> bytes|path`, реализации:
  `PiperTTS` (вызов `piper` с моделью .onnx, путь из `PIPER_MODEL`/`PIPER_BIN`),
  `SystemTTS` (текущий `say`/`espeak`), `NullTTS` (для тестов).
- Автовыбор: Piper, если доступен, иначе SystemTTS; явный конфиг перекрывает.
- `scripts/voice_loop.py`: использовать адаптер, сохранить стриминг по предложениям.
- Тесты: mock-процесс, выбор реализации, отсутствие бинаря не падает.
- Скачивать модель в этом задании НЕ нужно — только код и проверка на mock.

## Критерии приёмки

[ ] выбор реализации работает (piper → system → null) (тест)
[ ] отсутствие piper не ломает голосовой цикл (тест)
[ ] стриминг по предложениям сохранён
[ ] полный Python-набор зелёный

## Контекст и ограничения

- Зона: eva/tts.py (новый), scripts/voice_loop.py, tests/test_tts.py
- Другие файлы НЕ трогать: параллельно работают пять других агентов по своим модулям.
- **Запрещено:** запускать сервер/демон, качать модели, pip install, сеть (кроме уже
  установленных пакетов), git-коммиты.
- **Отчёт пиши первым блоком в ответе**, потом детали: агенты этой сессии падают на
  финальном шаге, отчёт первым спасает работу.
- Проверка: `python3 -m unittest discover -s tests` (сейчас 1071 тест, должно быть
  зелёным и не меньше).

## Отчёт исполнителя

Сделано: `eva/tts.py` — `synthesize(text)`, реализации `PiperTTS` (бинарь + .onnx из
`PIPER_BIN`/`PIPER_MODEL`, текст в stdin), `SystemTTS` (macOS `say`, Linux
`espeak-ng`/`espeak`), `NullTTS`; автовыбор piper → system → null, явный конфиг
перекрывает; `synthesize_timed` (полное время + время до первого фрагмента).
`voice_loop.py` переведён на адаптер, стриминг по предложениям сохранён, старые имена
оставлены обёртками. 33 теста.

Проверено на mock-процессе: успех, код 1, таймаут, отсутствие файла, битый
`PIPER_BIN` (автовыбор не падает), явный piper без бинаря → `TTSUnavailable`,
`--tts null` → exit 3 без traceback.

Риски: реальный Piper не запускался (нет бинаря/модели) — качество и скорость не
измерены; частоты 22 кГц у Piper против 16 кГц у `say`; `espeak` проверен только на
уровне команды.
