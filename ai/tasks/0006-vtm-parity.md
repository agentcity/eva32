# Сверка C-рантайма с Python-эталоном (parity)

## Проблема

Пока C и Python не сошлись на одном числе, ВТМ не считается работающей:
расхождение в логитах невозможно отладить без эталона.

## Требования

- Синтетический `.vtm` (128×128, случайные триты, фиксированный seed) исполняется
  и C-интерпретатором, и Python-эталоном; выходы совпадают в пределах 1e-5.
- Сверка по операциям отдельно: TMV, RMSN, SM, SILU, ROPE.
- Один реальный слой Qwen 1.5B (веса из `.trit`) даёт логиты, близкие к HF-эталону.

## Критерии приёмки

[ ] C и Python дают одинаковый выход на синтетике (число в отчёте)
[ ] Расхождение по операциям измерено и записано
[ ] Битый `.vtm` отвергается обоими

## Контекст и ограничения

Зависит от 0002 и 0003. Зона: `tests/vtm_parity/` + минимальные правки в своей зоне.
