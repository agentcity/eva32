# Кэш промпта в C-ABI

## Проблема

0081 добавила кэш префикса в ядро (`vtm_cache_prefix` / `vtm_run_cached`), но
`api.c` и `kv_store.c` вызывают `vtm_reset` на каждый запрос — то есть через C-ABI
кэш не работает вообще. Весь выигрыш (7,8× на префиксе 128 токенов) остаётся внутри
тестов.

## Требования

- `vtm_api_open(..., &opts)` получает опцию `cache_prefix` (по умолчанию выключена —
  не менять поведение без флага).
- При включённой опции `vtm_api_generate` использует `vtm_run_cached`, а не полный
  прогон; между запросами кэш **не сбрасывается**.
- Инвалидация при `vtm_api_session_load` (состояние машины меняется) и при смене
  бэкенда.
- Замер: два запроса с общим префиксом 100 токенов через C-ABI — время второго
  запроса до/после (числа в отчёте).
- Тест: ответы с кэшем и без совпадают побитово.

## Критерии приёмки

- [ ] второй запрос с тем же префиксом быстрее (число в отчёте)
- [ ] побитовое совпадение ответов с кэшем и без
- [ ] `make test` и полный Python-набор зелёные
