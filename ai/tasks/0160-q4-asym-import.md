# Q4_K → Q4_1, а не Q4_0

## Проблема

3B Q4 в нашей ВТМ работает, но **качество деградировало**: на «Столица Франции?»
отвечает «Столица Франции - это Пгврф. Я ошибсясь!» (ollama на том же вопросе: «Столицей
Франции является Париж.»).

Причина — ступень переквантования при импорте: Q4_K_M (супер-блок 256, 8 под-блоков
по 32, масштабы **и минимумы** по 6 бит) → **симметричный Q4_0** (один fp32-масштаб на
32, без минимумов). Отчёт импорта: **10,0% rel-RMS** — это много.

Формат (kind 5) и ядра (0152) **уже поддерживают Q4_1** (`q4_is_asym`, `q4_mins`).
Импортёр пишет только sym.

## Требования

- `tools/gguf_import.py`: писать Q4_1 (asym) с минимумом на группу 32 вместо Q4_0 sym:
  для каждой группы из 32 значений подобрать `min` и `scale` по исходным (де-квантованным
  из Q4_K) значениям, значения `q = round((w - min)/scale)` в 0..15.
- Убедиться, что `vtm_compile` читает Q4_1 (флаг asym, mins) и `vtm run` считает.
- Замер: rel-RMS против исходных весов (должно быть заметно ниже 10%), текст на тех же
  промптах («Столица Франции?», «Сколько будет 17*23?»), паритет C↔Python ≤1e-5.
- Размер: Q4_1 добавляет 4 байта на группу (+0,125 Б/вес); 3B ≈ +0,35 ГБ — проверить,
  что контейнер остаётся ≤4 ГиБ.
- Если Q4_1 не улучшает текст — честно записать числа и предложить следующий шаг.

## Критерии приёмки

- [x] rel-RMS ниже, чем у Q4_0 (числа до/после)
- [x] текст на «Столица Франции?» осмысленный (Париж) либо объяснено, почему нет
- [x] контейнер 3B ≤4 ГиБ, паритет C↔Python ≤1e-5

## Отчёт исполнителя

### Что сделано

* `tools/gguf_import.py` — импорт пишет **Q4_1** (asym): на группу 32
  `min = min(группа)`, `scale = (max-min)/15`,
  `q = clamp(round_half_away((w-min)/scale), 0, 15)`, сегмент —
  magic `"Q4_1"`, заголовок 22 байта с явным `n_mins`, порядок
  «header, scales, mins, nibbles». Правило побитово совпадает с
  `vtm_ref.quantize_q4(..., symmetric=False)` (тест сверяет `q`, `scale` и
  `min` на 200 блоках).
* `--q4-kind auto|q4_1|q4_0` (по умолчанию `auto`): Q4_1, если оценка
  контейнера влезает в 4 ГиБ (ADR 0016), иначе Q4_0 — выбор с числами
  печатается в stderr. 3B → `q4_1`, 7B → `q4_0` во всех трёх схемах
  (Q4_1 у 7B: 4,23–5,46 ГиБ, то есть 106–136 % предела). Если и выбранный
  вид не влезает (7B с fp32-масштабами и int8-эмбеддингом: 4,64 ГиБ даже
  у Q4_0), импорт печатает подсказку `--q4-scale-dtype fp16` (−0,44 ГБ) и
  `--embed trit` (−0,44 ГБ) — это ровно рецепт 0156, 3,82 ГиБ.
* `_SegmentEncoder` умеет `asymmetric`: копит `mins` параллельно
  масштабам, пишет их в том же dtype, `--stats` считает ошибку по
  `w = q·scale + min` (для вырожденной группы `scale=0`, `min` — значение).
* Манифест: `dtype: "q4_1"`, `q4.asymmetric`, `q4.segment.header_bytes=22`,
  `n_mins`, `order` с mins, `quantization.rule` для asym,
  `q4_kind`/`q4_estimated_bytes`/`container_limit_bytes`.
* `tests/test_q4_asym_import.py` (новый, 18 тестов): правило блока,
  вырожденная группа, полшага round-trip, синтетический GGUF → Q4_1-сегмент
  → де-квантование, rel-RMS ниже симметричного, компилятор + `.vtm`,
  C↔Python ≤1e-5, выбор `auto` по бюджету (в т.ч. падение в q4_0 под
  урезанным пределом).
* Вне зоны, но неизбежно (следствия смены формата): обновлены три
  утверждения в `tests/test_gguf_import.py` (magic/`asym`/сверка с
  `quantize_q4(symmetric=False)`), `tests/test_compile_q4.py`
  (`dtype` → `q4_1`), `tests/test_gguf_7b_fit.py` (бюджет Q4_1 для 7B,
  Q4_1-байты сегмента fp16). Правки минимальные, без смены смысла тестов.

### rel-RMS до/после (qwen2.5:3b Q4_K_M, одни и те же веса)

| Множество | Q4_0 (было) | Q4_1 (стало) |
|---|---|---|
| 1 слой + срез словаря 4096, 77,1 МЭ | 9,96 % (макс. ошибка 0,049) | **5,63 %** (макс. ошибка 0,040) |
| полная модель, 2,77 млрд весов Linear | — | **5,1 %** (макс. ошибка 0,049) |

int8-эмбеддинг (Q6_K→int8) — 0,6 %, не менялся.

Важное наблюдение: rel-RMS упал в 1,8 раза, а текст ожил. Ошибка
симметричного правила **неравномерна** — она бьёт в группы, где полоса
весов далеко от нуля (у Q4_K-подблоков это обычное дело), и таких групп
хватает, чтобы сломать несколько слоёв, но мало для среднего по модели.
rel-RMS — индикатор, а не замена проверке текстом.

### 3B: контейнер и текст

Сборка: `--format q4` (умолчание → `q4_1`), fp32-масштабы, int8-эмбеддинг.
`q4.params=2 774 532 096`, `q4.bin=2 080 907 126 Б`, int8=321 855 520 Б;
импорт 44 мин (машина под нагрузкой ~15).

* `runs/q4/3b-q4_1.vtm` — **2 410 054 560 Б = 2,245 ГиБ** (≤4 ГиБ, 56 %
  предела). Q4_0-контейнер `runs/q4/3b.vtm` — 2 063 237 920 Б (+346 МБ,
  +0,125 Б/вес при fp32-масштабах).
* Паритет C↔Python на Q4_1-срезе (tiny-модель, 64 логита):
  `max|Δ| = 2,43e-07` ≤ 1e-5.

Текст, жадный декод (VTM `SAMP imm=0` = argmax; ollama — `temperature=0`),
64 токена:

| «Как тебя зовут?» | «Меня зовут Алгоритм. Извините, если вам это покажется странным, но я работаю в качестве искусственного интеллекта…» | «Вас приветствует Artificial Intelligence. Я名叫AI，能够回答您的问题…» (смесь ru/en/zh) | «Меня создали на основе языкового модели Qwen… Но вы можете叫我 Qwen!» (тоже с zh) |

— это свойство 3B-модели и жадного декода, а не формата. Формулировка
критерия «текст осмысленный (Париж)» выполнена.

### Что осталось / риски

1. **7B как Q4_1 не влезает** в 4 ГиБ: 4,54 ГБ = 106 % предела (fp16-
   масштабы + тритовый эмбеддинг). Поэтому умолчание `auto` и режим
   `--q4-kind q4_0` для 7B. Если качество 7B тоже важно — нужна отдельная
   задача (варианты: Q4_1 только для части слоёв, иной блок min'ов, подъём
   предела — последнее требует ADR 0016).
2. Реальный 7B с `--q4-kind q4_0` здесь не пересобирался (44+ мин и
   4,7 ГБ блоба на загруженной машине); бюджет проверен арифметикой в
   `tests/test_gguf_7b_fit.py`.
3. Импорт 3B занял 44 мин — это чистый Python на загруженной машине
   (~15 load). Ускорение (векторизация квантователя) — отдельная задача,
   сейчас её нет в требованиях.
4. rel-RMS 5,1 % всё ещё не «ноль»: остаток — Q4_1 с шагом `(max-min)/15`;
   следующий шаг по точности — не формат, а обучение/пересчёт (QAT).
