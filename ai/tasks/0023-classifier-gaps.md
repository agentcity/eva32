# Промахи классификатора

## Проблема

Замер гибрида (`python3 tools/eval_hybrid.py`) даёт 94% точности маршрутов. Все три
промаха — big→small, то есть сложный вопрос ушёл в дешёвую модель:

1. «Придумай план запуска продукта за 30 дней» — нет маркера «придумай».
2. «Напиши SQL-запрос: топ-10 клиентов по выручке» — «напиши» есть, но SQL не распознан.
3. «Какая столица Австралии?» — вопрос на общие знания, без маркеров.

## Требования

- Добавить маркеры творческих/структурных задач: «придумай», «составь», «спланируй»,
  «sql», «запрос», «формул», «таблиц», «схем».
- Распознавать вопросы на общие знания: «столица», «сколько будет», «кто такой»,
  «в каком году», «переведи на» — это big, потому что скиллов и каталога там нет.
- Не сломать обратное: «сколько стоит тариф Старт» обязан остаться skill.
- Пороги и маркеры — по-прежнему из конфига, не хардкодом.

## Критерии приёмки

- [x] Точность маршрутов на `eval/hybrid_golden.jsonl` ≥ 96% (было 94%)
- [x] Ни один промах не стал скиллом там, где скилла нет
- [x] `python3 -m unittest discover -s tests` зелёный
- [x] В отчёте — таблица «вопрос → было → стало»

## Контекст и ограничения

- Зона: `eva/classifier.py`, `tests/test_classifier.py`, `eval/hybrid_golden.jsonl`
  (только добавление строк, не правка ожиданий под ответ).
- Не подгонять набор под код: если пример размечен неверно — обосновать и исправить
  ожидание отдельной строкой в отчёте.

## Отчёт исполнителя

Сделано: правила task/structural/general_knowledge в `eva/classifier.py`, маркеры
из конфига, 32 теста.

Результат: точность 47/50 → **50/50 на старом наборе**, и **60/60 на расширенном**.

Замер после расширения набора (архитектор добавил 10 строк и обновил BASELINE):
| метрика | было | стало |
|---|---|---|
| точность | 47/50 = 94% | **60/60 = 100%** |
| скиллы | 22/22 | 24/24 |
| цена | 112,92 ₽/1000 | 188,20 ₽/1000 |

Цена выросла осознанно: это цена *правильных* маршрутов, а не регрессия —
идеальный маршрут по разметке тоже 188,20, то есть гибрид совпал с идеалом.
Экономия против «всегда большая» осталась 63%.

Агент честно упёрся в чужую зону: добавить строки в набор он не мог (baseline в
tests/test_eval_hybrid.py), поэтому откатил их и передал список. Архитектор внёс
строки и пересчитал baseline — так и должно работать.
