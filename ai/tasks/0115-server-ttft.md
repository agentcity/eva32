# Сервер: TTFT и прогрев модели

## Проблема

Метрики уже считают TTFT, но модель на первом запросе грузится и считает промпт по
токену — первый пользователь получает минуту ожидания. Нужен прогрев при старте и учёт
того, что prefill доминирует.

## Требования

- Прогрев: при старте сервера (если задан `EVA_VTM_MODEL`) — загрузить модель и прогнать
  короткий prefill, чтобы страницы mmap и арена были готовы; логировать время прогрева.
- Метрики: разделить `ttft_ms` на prefill-часть и время до первого токена после prefill;
  счётчик `warmup_ms`.
- Заголовок/поле `X-Prefill-Tokens` в ответе (или в метриках), чтобы видеть, сколько
  токенов промпта посчитано.
- Тесты без сокета: прогрев вызывается, метрики заполняются.

## Критерии приёмки

[ ] прогрев при старте логируется и не блокирует приём (тест)
[ ] метрики показывают prefill отдельно от TTFT
[ ] Python-набор зелёный

## Отчёт исполнителя

Сделано: `warmup_local_model()` — при `EVA_VTM_MODEL` собирает бэкенд, делает open +
encode + generate(1 токен), пишет `warmup_ms` в метрики; любая ошибка → WARNING, сервер
стартует. Прогрев идёт после bind, поэтому сбой не может отменить старт.
Метрики: `prefill_tokens` (по длине промпта), `prefill_ms` и `ttft_after_prefill_ms`
(p50/p95/p99), `warmup_ms` и блок `warmup`; прогрев не считается запросом. Заголовок
`X-Prefill-Tokens` на JSON и SSE (работает и при обрыве потока).

**Числа прогрева:** demo (117 КБ) — 187 мс; форма 1.5B (345 МБ) — **1226 мс холодный,
394 мс повторный, 716 мс через конструктор**. То есть старт платит ~0,7–1,2 с один раз
вместо первого пользователя. Битый путь → ok=false + WARNING за 13,7 мс; чужой
токенизатор (vocab 128) → ok=false за 22,9 мс, сервер создаётся.

Проверено: 74 теста (метрики + лимиты), полный набор 1618 OK.

Оговорки: прогрев синхронный (0,2–1,2 с старта; фоновый вариант — отдельной задачей);
прогревочный бэкенд отдельный от того, что создаст router на первом запросе — выигрыш в
page cache mmap и загрузке libvtm, но арена C-контекста не переиспользуется;
`prefill_ms`/`ttft_after_prefill_ms` = None, пока router не отдаёт границу prefill
(заведена 0120); без `tokenizer.json` прогрев идёт по ids [1,2,3].
