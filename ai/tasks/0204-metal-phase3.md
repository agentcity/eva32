# Декод на GPU: убрать простои между слоями

## Где мы
- фаза 1: GPU GEMV 7,8 ток/с против CPU 20,8 — 181 командный буфер на токен;
- фаза 2: один буфер на серию (145 на токен, 4 ожидания/слой), батчевый GEMM
  prefill 2,0× — декод всё равно 8,5;
- CPU-декод 16–20 ток/с (memory-bound 33–47 ГБ/с), батч упирается в 65 GMAC/с.

## Что должно измениться в фазе 3
1. **Один командный буфер на слой, без промежуточных ожиданий.** Все матрицы
   слоя (q/k/v/o, gate/up/down) кодируются подряд; CPU ждёт один раз — на
   attention/норму. Сейчас 4 ожидания на слой.
2. **Attention, RMSNorm, RoPE, SiLU — на GPU** (MSL-ядра), чтобы CPU не разрывал
   конвейер между матрицами. Тогда весь токен — один граф из ~6 dispatches на
   слой, CPU только сэмплирует.
3. **Double buffering**: пока GPU считает слой N, CPU не простаивает (готовит
   слой N+1) — либо, если всё на GPU, два токена в полёте (batching 2).
4. **Один MTLCommandBuffer на несколько слоёв** (там, где нет зависимости от CPU:
   q/k/v/gate/up можно кодировать вперёд).

## Критерии приёмки
- [ ] декод `VTM_BACKEND=metal` **≥30 ток/с** (CPU 20,8; сейчас metal 8,5)
- [ ] **≥1,5× к CPU-декоду** в парном замере в одном окне
- [ ] точность: argmax 3/3, Δlogits ≤1e-2
- [ ] откат на NEON при ошибке Metal, без Metal — прежние числа
- [ ] `auto` переключается на metal ТОЛЬКО если декод и prefill оба быстрее CPU
- [ ] `make test`, `--check`, TSan, Python-набор зелёные
