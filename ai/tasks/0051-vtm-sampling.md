# Сэмплинг: temperature, top-k, top-p, повтор

## Проблема

SAMP умеет один вариант — похоже, argmax. Для ассистента нужны temperature, top-k,
top-p и штраф за повторы, иначе модель будет зацикливаться.

## Требования

- `imm` у SAMP — номер стратегии: 0 argmax, 1 temperature, 2 top-k, 3 top-p.
- Параметры в мете контейнера: temperature, top_k, top_p, repetition_penalty.
- Детерминизм: при temperature 0 и argmax результат побитово одинаков при повторах.
- Штраф за повторы по окну последних N токенов.
- Тесты на каждую стратегию: распределение, границы, детерминизм.

## Критерии приёмки

[ ] argmax детерминирован (3 запуска — один токен)
[ ] temperature 0 == argmax
[ ] top-k 1 == argmax; top-p 1.0 не отсекает ничего
[ ] штраф за повторы меняет выбор зацикленного примера
[ ] `make test` зелёный

## Контекст и ограничения

- Зона: src/vtm/interp.c, src/vtm/vtm.h, tests/vtm/test_vtm.c
- Другие файлы не трогать: параллельно работают другие агенты.
- Сборка: `cd src/vtm && make test`; флаги `-Wall -Wextra -Werror`.
- Не ломать существующие тесты и поведение без флагов.
- Не коммитить: сдавать правки и отчёт.

## Отчёт исполнителя

**Сделано.** `SAMP` получил четыре стратегии (`imm`): 0 argmax (поведение
v0.1 не изменилось), 1 temperature, 2 top-k, 3 top-p; `imm` вне 0..3 —
`VTM_E_UNSUPPORTED`. Параметры — из меты контейнера: `temperature`, `top_k`,
`top_p`, `repetition_penalty`, `repetition_window`, `sample_seed` (ключ ищется
на любом уровне вложенности, при отсутствии/порче — дефолт). Штраф за
повторы действует во всех стратегиях: токен из окна последних N
сгенерированных штрафуется один раз (CTRL), затем температура, затем
top-k/top-p. `temperature <= 0`, `top_k == 1`, `top_p <= 0` и стратегия 0
переводят выбор в argmax, который ГПСЧ не потребляет, — отсюда побитовый
детерминизм. ГПСЧ — xorshift64* с засевом splitmix64, алгоритм зафиксирован
в `docs/vtm.md` и повторён в `tools/vtm_ref.py`; состояние (ГПСЧ, кольцо
последних 256 токенов, разобранные параметры) живёт в `struct vtm`,
`vtm_reset()` возвращает сэмплер в начало (сброс замечается по счётчику
`vtm_generated()`; в `vtm_internal.h` добавлен `vtm_samp_reset()` для явного
вызова из `vtm_reset()` — loader.c вне зоны задачи).

**Файлы.** `src/vtm/interp.c`, `src/vtm/vtm.h`, `src/vtm/vtm_internal.h`
(состояние сэмплера; расширено архитектором), `tests/vtm/test_vtm.c`,
`tools/vtm_ref.py` (SAMP приведён к той же конвенции и алгоритму),
`docs/vtm.md` (§ «Сэмплинг»), новый `tests/test_vtm_sampling.py`
(паритет C↔Python).

Критерии: argmax детерминирован (3 прогона и 3 загрузки — один токен);
temperature 0, top-k 1 побитово равны argmax; top-p 1.0 даёт ту же
последовательность, что чистая temperature; штраф за повторы меняет
зацикленный пример (argmax без штрафа — `2 2 2 2 2 2`, с penalty 4.0 и окном
2 — `2 0 2 2 0 2`, окно 0 — снова `2 2 2 2 2 2`). Тесты распределения:
temperature {0, ln2} → 2/3 и 4/5, top-k 2 из 5 равных → ровно два токена,
top-p 0.5/0.6 → ядро из 2/3 токенов. Дополнительно `test_vtm` прогнан под
ASan+UBSan — чисто.

**Риски.** (1) ГПСЧ-поток общий на машину: воспроизводимость гарантирована
для одинакового seed и одинаковой последовательности вызовов; при разных
путях хоста (сколько раз вызван SAMP) поток расходится — это ожидаемо.
(2) Потокобезопасности нет (как и у `vtm_last_error()`): одну машину нельзя
использовать из двух потоков. (3) `imm` вне 0..3 теперь ошибка: контейнеры,
собранные старым Python-эталоном с `imm = температура × 1000`, надо
перекомпилировать (компилятор `vtm_compile.py` пишет `imm = 0`). (4)
Один malloc на сэмпл размером `n * 24` байт (кандидаты + веса): для словаря
150k — ~3.6 МБ на токен; при нехватке памяти — `VTM_E_NOMEM`, не падение.
(5) `src/vtm/README.md` («Соглашения v0.1», «Ограничения») всё ещё говорит
«SAMP — только greedy»: файл вне зоны, обновить отдельной задачей. (6)
`vtm_sampling_params()` парсит мету линейно — не для горячего цикла.
