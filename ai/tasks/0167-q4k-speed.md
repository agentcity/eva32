# Вернуть скорость нативному Q4_K

## Проблема

Нативный Q4_K (0165) дал rel-RMS 0 к весам ollama, но **потерял скорость**:

| | Q4_1 (переквант) | Q4_K (нативный) |
|---|---|---|
| декод | 6,1 ток/с | **2,6 ток/с** |
| prefill 128 токенов | 17 с | **73 с** |

Причины: (а) в NEON-ядрах Q4_K/Q6_K накопление в **f64** (так получался паритет),
(б) батчевых ядер для kind 6/7 нет вовсе.

## Требования

1. **f32-накопление в NEON** с допустимой точностью: f32 даёт max|Δ| ≈ 1,07e-6 —
   это по-прежнему ≤1e-6…1e-5. Сделать основным, f64 оставить эталоном;
   `VTM_Q4K_STRICT=1` возвращает f64.
2. **Батчевый prefill для kind 6/7** (по образцу 0162): строка деквантизуется один раз
   на пачку, вектор по токенам.
3. Цель: декод ≥5 ток/с, prefill 128 токенов ≤25 с (сейчас 73 с).
4. Точность: паритет C↔Python ≤1e-6 или ≤1e-5 с обоснованием; вывод модели не меняется.
5. Замеры до/после: `runs/q4/3b-q4k.vtm`, декод и prefill 64/128/256.

## Критерии приёмки

- [ ] декод ≥5 ток/с, prefill 128 ≤25 с
- [ ] точность в допуске, вывод тот же
- [ ] `make test`, `--check` зелёные
