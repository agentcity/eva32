# «Включи запись сказки» — с живой интонацией

## Зачем
Синтез не передаёт интонацию, а актёрская запись — передаёт. Там, где есть
**свободная** запись, лучше включить её, чем читать.

## Требования
1. **Поиск записей**: Wikimedia Commons (audio + PD/CC), Archive.org (только
   явная лицензия CC0/CC-BY/PD — фильтровать по `licenseurl`, НЕ брать
   «все права защищены»). Сохранять локально в
   `plugins/fairy-tales/audio/<slug>.ogg` (или .mp3), ≤3 МБ на сказку.
   В `audio/credits.md` — автор, источник, лицензия.
2. **Начать с малого**: 3–5 записей (например «Сказка о царе Салтане»,
   народные сказки в исполнении чтецов), остальные — без записи.
3. **Плагин**: команда «включи запись сказки», «поставь аудиосказку»,
   «сказку в исполнении» → `answer` возвращает текст-подтверждение и
   побочное действие: запуск `afplay` (список argv, без shell) с локальным
   файлом; «стоп»/«выключи» — terminate процесса.
4. **Если записи нет** — честно: «Записи этой сказки у меня нет, могу
   рассказать сама» и НЕ падать.
5. **Сервер/приложение**: воспроизведение идёт на Mac (afplay), поэтому
   приложение просто получает подтверждение; голосовая озвучка ответа не
   нужна (иначе будет говорить поверх записи) — вернуть признак
   `{"text": ..., "silent": true}`, сервер не шлёт `/api/tts` для такого ответа.
6. Тесты: распознавание фраз, запуск/остановка (мок subprocess), отсутствие
   записи, `silent` доходит до клиента, лицензии в credits.
7. Живая проверка: «включи запись сказки» → процесс afplay запущен (проверить
   `pgrep afplay`), затем «выключи» → процесс живёт/умер, ответ корректен.
   Если песочница не даёт звук — отметьте честно, важен факт запуска.

## Критерии приёмки
- [x] 3–5 записей CC/PD с credits
- [x] «включи запись сказки» запускает локальный файл
- [x] «выключи»/«стоп» останавливает
- [x] нет записи → честный ответ, без падения
- [x] `silent` не даёт двойной озвучки
- [x] тесты и полный набор зелёные

## Отчёт исполнителя

**Записи.** Четыре записи LibriVox с Archive.org, Public Domain Mark 1.0
(явный `licenseurl = http://creativecommons.org/publicdomain/mark/1.0/`,
`rights` пустой, «all rights reserved» нет):

| Файл | Сказка | Источник | Размер |
|---|---|---|---|
| `audio/kot-petuh-i-lisa.mp3` | «Кот, петух и лиса» (Афанасьев, вып. 2) | `russianfairytales2_2103_librivox` | 1,57 МБ |
| `audio/tsarevna-lyagushka.mp3` | «Царевна-лягушка», другой вариант (вып. 2) | `russianfairytales2_2103_librivox` | 2,92 МБ |
| `audio/baba-yaga.mp3` | «Баба-яга», первая сказка (вып. 2) | `russianfairytales2_2103_librivox` | 2,79 МБ |
| `audio/teremok.mp3` | «Теремок мышки» (вып. 3) | `russianfairytales3_2412_librivox` | 1,22 МБ |

Автор, чтецы, прямые ссылки, лицензия и SHA-256 — в `audio/credits.md`.

**Плагин.** В `answer` добавлена отдельная аудио-ветка до выбора сказки:
«включи запись сказки», «поставь аудиосказку», «сказку в исполнении» →
локальный `afplay <audio/<slug>.mp3>` (список argv, `start_new_session=True`,
без shell), ответ `{"text": "Включаю запись «…».", "silent": true}`.
«Выключи»/«стоп сказку»/«останови запись» → `SIGCONT` → `terminate` → `kill`
по таймауту; голое «выключи» останавливает запись, только если она играет,
иначе команда уходит плагину музыки. Старт под замком: две колонки сервера,
одновременно спросившие одну сказку, запускают один `afplay`, а не два. Нет
записи — «Записи сказки «…» нет, могу рассказать сама» (обычная строка,
`silent` не выставляется). Нет `afplay`/файл не открылся — честный отказ.

**Сервер.** Словарь плагина теперь несёт `silent`: `_coerce_plugin_reply`
пробрасывает признак, SSE `delta` и `done` получают `silent: true`.
Встроенный клиент страницы по `silent` показывает текст, но не отправляет его
в `/api/tts` и не ставит в очередь озвучки. `images` (0221) не затронуты.

**Проверки.** `tests/test_tale_audio.py` — 23 теста: фразы, argv/`Popen`,
старт/стоп с моком, дубль от двух колонок, нет записи, нет `afplay`, файл
больше 3 МБ, credits/лицензии/размеры, `silent` в SSE `delta`/`done`.
Живой прогон через настоящий `chat_server` + реальный `default_registry`:
«включи запись сказки» → `pgrep -fl afplay` показал один процесс
`/usr/bin/afplay .../tsarevna-lyagushka.mp3`; «выключи» → процесс завершён
(`pgrep` пуст), ответ «Выключила запись.»; для «про колобка» — честный текст
без процесса. Полный набор: `Ran 2931 tests ... OK (skipped=85)`.

**Ограничения.** Звук в песочнице не прослушать на слух — проверен факт
запуска и жизни процесса `afplay`; `silent` поддержан веб-страницей чата.
Приложение `apps/eva` вне зоны задачи: если его SSE-клиент сам зовёт
`/api/tts`, ему нужно так же уважать `silent`.
