# Окно контекста: эталон и доки

## Проблема

Задача 0076 добавила кольцевое окно контекста в C (KVW пишет в `pos % win`, ATTN
читает последние win ключей). Но:

- `tools/vtm_ref.py` окна не знает — C и Python **разойдутся**, как только позиция
  достигнет ctx. Паритетные тесты этого не видят, потому что работают в пределах ctx;
- `docs/vtm.md` всё ещё утверждает, что ATTN аллоцирует `scores[ctx]` и тайлинга нет.

## Требования

- `vtm_ref.py`: реализовать то же кольцо и `context_window` из меты; тест паритета
  на последовательности длиннее ctx (C ↔ Python побитово/1e-6).
- `docs/vtm.md`: описать блочный attention (блок 64, онлайн-softmax), кольцевое окно,
  что ROPE считается по глобальной позиции, и что позиция >= ctx больше не ошибка.
- Проверить, что `tools/bench_vtm.py` не опирается на старое поведение (там был
  комментарий).

## Критерии приёмки

- [ ] паритет C↔Python на 2×ctx токенах проходит
- [ ] в docs/vtm.md нет утверждений про malloc scores и отсутствие тайлинга
- [ ] `make test` и `python3 -m unittest discover -s tests` зелёные
