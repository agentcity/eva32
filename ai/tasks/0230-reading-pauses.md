# Слишком быстро для ребёнка

## Проблема
Ева читает сказку в темпе обычного ответа: фразы идут встык, между абзацами
паузы нет. Ребёнок не успевает следить.

## Требования (приложение, macOS)
1. **Пауза между фразами** в озвучке: после каждой воспроизведённой фразы —
   тишина, по умолчанию 350 мс; после абзаца (`\n\n`) — 900 мс.
2. **Режим сказки**: если ответ — от плагина сказок (в ответе есть картинки
   или сервер пометил источник `plugin`), паузы умножаются на 1,5–2
   (≈600 мс / 1500 мс) — «сказка читается медленнее».
3. **Настройка** в окне настроек: «Скорость чтения сказок» — «обычная» /
   «медленная» (по умолчанию «медленная»), сохраняется в UserDefaults
   (`eva.talePace`), применяется без перезапуска.
4. **Не ломать обычный чат**: короткие ответы читаются как раньше (пауза
   между фразами меньше, режим сказки не включается).
5. **Стоп/новый вопрос** — пауза прерывается немедленно.
6. Самотест `--selftest-pauses`: расчёт паузы по тексту (конец фразы, абзац,
   режим сказки), прерывание стопом, отсутствие пауз при выключенной озвучке.

## Критерии приёмки
- [x] между фразами слышимая пауза, между абзацами — заметно длиннее
- [x] режим сказки включается автоматически и усиливает паузы
- [x] настройка «медленная/обычная» работает без перезапуска
- [x] стоп прерывает паузу сразу
- [x] сборка и самотесты зелёные

## Отчёт исполнителя

**Какие паузы.** После каждой доигравшей фразы `VoicePlayer` держит тишину
0,35 с; если фраза закрывала абзац — 0,9 с. Абзац определяется не по тексту
фразы (нарезка обрезает переводы строк), а по самой границе разреза:
`PhraseSplitter` теперь отдаёт `SpokenPhrase(text:paragraph:)` и считает два
перевода строки подряд в хвостовых пробелах вырезанного куска и ведущих
пробелах остатка. Абзац может прийти разрезанным между двумя SSE-кусками
(первый кончается одним `\n`, второй начинается со второго), поэтому
последняя фраза куска с одиночным переводом строки придерживается до
следующего `delta`/`flush`; её текст входит в `pendingChars`, чтобы позиции
картинок не сдвинулись. Текстовая функция `ReadingPause.isParagraph`
осталась для `--selftest-pauses` и вызовов без флага.

**Режим сказки.** Паузы ×1,8: ≈0,63 с между фразами и ≈1,62 с между
абзацами. Признаки: SSE-событие `image` (самый ранний), `finish_reason:
"plugin"` или `source: "plugin"` в `done` (новое событие `ChatEvent.pluginAnswer`)
либо длина видимого текста от 400 символов. Короткий чат остаётся на базе.

**Настройка.** «Скорость чтения сказок» — `обычная`/`медленная` (по
умолчанию `медленная`), ключ `eva.talePace`, значения `normal`/`slow`.
Множитель применяется только к сказке: обычный чат при любой настройке идёт
по 0,35/0,9 с. `VoicePlayer` читает настройку в момент каждой паузы, поэтому
смена действует без перезапуска, в том числе посреди чтения.

**Стоп, дренаж, silent.** `PauseGate` — одна пауза за раз; `stop()`, новый
вопрос и `stopVoice()` вызывают `cancel()` и отменяют спящую `Task`, её
`onDone` не срабатывает. `isDrained` учитывает идущую паузу, поэтому
`onDrained` (follow-up микрофон) приходит только после последней паузы;
`onSpeakingChanged(false)` тоже перенесён туда, круг между фразами не мигает
`idle` и стоп-слушатель не уступает микрофон wake-ожиданию. Текст последней
фразы (`currentText`) на паузе не стирается — хвост её звука ещё может
попасть в микрофон, и эхо-защита стоп-команды должна его узнать; стирается он
только когда чтение действительно кончилось. Для `silent` (запись `afplay`)
и выключенной озвучки фраз в очереди нет — пауз нет.

**Сценарий.** `Колобок.` → 350 мс → `Покатился.` (абзац) → 900 мс → …;
в сказке на «медленной» — 630/1620 мс. В журнале на каждую паузу строка
`озвучка: пауза 350 мс`, у абзаца — `— абзац`, в сказке — `(сказка)`;
переход в сказку — `озвучка: режим сказки — паузы длиннее (картинки сказки)`.

**Файлы.** `ReadingPause.swift` (новый: `ReadingBreak`, `ReadingPause`,
`PauseGate`), `StreamText.swift` (`SpokenPhrase`, `feedPhrases`/
`flushPhrases`, флаг абзаца), `VoicePlayer.swift` (очередь фраз с флагом,
`PauseGate`, `isDrained`/`isPausing`, порог сказки, журнал), `AnswerController.swift`
(детект сказки, `isTaleAnswer`, `setTaleMode`), `ChatClient.swift`
(`ChatEvent.pluginAnswer` из `done`), `Settings.swift`
(`TalePace`, `eva.talePace`), `SettingsWindowController.swift` (попап
«Скорость чтения сказок»), `SelfTest.swift`/`LaunchOptions.swift`

пауз проверены самотестом на настоящем `PauseGate`.

**Риски.** Опрос `AVAudioPlayer.isPlaying` раз в 120 мс добавляет к паузе до
~0,12 с (на слух незаметно). Режим сказки включается не с первого символа:
по длине — после 400 символов, по `plugin` — в `done`, поэтому у длинного
ответа без картинок первые фразы могут прозвучать с короткими паузами;
у плагина сказок `image`/`done` приходят за миллисекунды, до первого звука,
так что там паузы длинные с самого начала. Последняя пауза задерживает
follow-up на 0,35–1,6 с — это требование, а не регресс. Очень длинный ответ
обычной модели (>400 символов) тоже читается как сказка. `silent`-ответы
(внешняя запись) не затрагиваются — там свой темп, задача 0231.
