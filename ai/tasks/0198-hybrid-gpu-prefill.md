# GPU выигрывает на пачке, CPU — на декоде

## Замеры 0196 (парные, одна машина)
| | simd (CPU) | metal (GPU) |
|---|---|---|
| prefill 64 токена | 19,6 ток/с (TTFT 3,27 с) | **34,0 ток/с (TTFT 1,88 с)** |
| декод | **19,4 ток/с** | 8,5 ток/с |

То есть **выигрыш GPU — только на батче** (GEMM переиспользует строку весов),
а на декоде (GEMV, 181 вызов, полоса 20–30 ГБ/с) GPU проигрывает в 2,3 раза.

## Задача: гибридный режим
1. `VTM_BACKEND=hybrid`: **батчевые операции** (prefill GEMM kind 4/6/7) идут на
   Metal, **одиночные GEMV** — на NEON. Механизм: в metal-бэкенде GEMV возвращает
   «не умею» (или env `VTM_METAL_DECODE=0`), диспетчер падает на simd; либо явная
   развилка по контексту (batch_tmv/batch_mm → metal; tmv/mm с n=1 → simd).
2. `auto` = hybrid **только если** парный замер показывает, что гибрид быстрее
   чистого simd и в prefill (≥1,3×) и в декоде (≥1,0×). Иначе auto остаётся simd,
   а hybrid — явно.
3. Единый прогон не должен терять корректность: точность (argmax 3/3, Δlogits ≤1e-2),
   откат при любой ошибке Metal → чистый simd.
4. Замеры: prefill 64/128 токенов, TTFT, декод (tok/s), CPU-время; сравнение
   simd / metal / hybrid в одном окне, парно. Размер буферов и RSS.

## Критерии приёмки
- [ ] hybrid: prefill ≥1,5× быстрее simd, декод не хуже simd (в пределах шума)
- [ ] TTFT 64 токена ≤2 с в гибриде
- [ ] точность как у simd (argmax, Δlogits), откат работает
- [ ] `auto` выставлен по замеру, решение задокументировано числами
- [ ] `make test`, `--check`, TSan, Python-набор зелёные
