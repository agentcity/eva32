# KV: кэп на суммарный размер и отказ старым бинарям

## Проблема

После 0101 KV-кэши не лежат в файле. Остались два риска: (1) помеченный тензор в
192-байтном файле может запросить calloc до 4 ГиБ; (2) бинарь до 0101 увидит offset=0 и
загрузит мусор вместо отказа.

## Требования

- Кэп на суммарный размер KV-кэшей при загрузке (константа в loader.c, например
  `VTM_MAX_KV_BYTES` с разумным дефолтом) — превышение даёт VTM_E_FORMAT с текстом.
- Признак нового вида контейнера, который старый бинарь увидит как отказ: используй
  свободное поле заголовка (посмотри формат; версию не поднимать, если можно обойтись
  флагом) — обоснуй выбор.
- Совместимость: старые контейнеры (с кэшами и без флага) читаются.
- Фаззинг `tools/fuzz_vtm.py`: 5000 мутаций без сигналов.

## Критерии приёмки

[ ] запрос KV сверх кэпа отвергается с понятной ошибкой (тест)
[ ] старый бинарь получает отказ, а не мусор (тест на флаге)
[ ] фаззинг 5000 мутаций без падений
[ ] make test и Python-набор зелёные

## Контекст и ограничения

- Зона: src/vtm/loader.c, tools/vtm_compile.py, tools/vtm_ref.py
- Другие файлы НЕ трогать: параллельно работают семь других агентов по своим зонам.
  В частности `interp.c` — 0112, `backend_*.c` — 0113, `main.c/api.c/api.h` — 0114,
  `eva/server.py` — 0115, `docs/` — 0116, `tools/ci.py` — 0117, `loader.c` — 0118,
  `prompts/` — 0119.
- **Запрещено:** pip, сеть, запуск сервера на порту, git-коммиты, скачивание моделей.
- **Отчёт пиши первым блоком ответа** — агенты этой сессии падают на финальном шаге.
- Проверка: `python3 -m unittest discover -s tests` (сейчас 1517 тестов) и, где нужно,
  `cd src/vtm && make test`.
- Если нужен API из чужой зоны (например `vtm_run_batch` из 0112) — опиши контракт в
  отчёте и используй заглушку, не правь чужой файл.
