# MoE: 30B на 16 ГБ

## Контекст
`Qwen3-30B-A3B`: 30B всего, ~3B активных (128 экспертов, top-8), attention обычный GQA.
В llama.cpp идёт 10+ ток/с на CPU/16 ГБ за счёт mmap: читаются только выбранные эксперты.
Разведка 35B — `docs/moe-recon.md` (там же гибрид gated delta, отложен).

## Объём работ
1. **Импорт GGUF MoE**: тензоры экспертов (ffn_gate/up/down на эксперта), роутер,
   shared expert; `--q4-kind` как для dense.
2. **Операция роутера**: logits → top-k (softmax) → взвешенная сумма выходов экспертов.
   Новая инструкция (`MOE`) или граф из существующих (GATHER + MM + SCAL + ADD).
3. **Разреженная загрузка**: эксперт-тензоры через mmap; madvise по выбранным (как 0161);
   кэш экспертов (LRU) — горячие держим в RAM.
4. **Компилятор**: программа на MoE-слой (роутер + top-k + эксперты).
5. **Замер**: 30B-A3B Q4 на 16 ГБ — tok/s, RSS, page faults; сверить паритет логитов
   с llama.cpp/ollama на 2–3 промптах (порог 1e-3).

## Критерии приёмки
- [ ] 30B-A3B Q4 импортируется и считает токены на 16 ГиБ (mmap, без OOM)
- [ ] паритет с ollama ≤1e-3 на 3 промптах
- [ ] скорость ≥5 ток/с (цель 10)
- [ ] `make test`, `--check`, полный набор зелёные
