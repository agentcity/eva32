# Панель метрик под чатом

## Проблема

Сейчас `tools/chat_server.py` показывает ответы и ток/с в шапке колонки. Для
сравнения моделей этого мало: непонятно, **сколько модель занимает на диске**, сколько
памяти съедает при загрузке, сколько жрёт CPU и где узкое место — загрузка, prefill
или декод.

## Требования

**1. Карточка модели** (по каждому бэкенду/модели): размер файла на диске, число
параметров, контекст, размер KV-кэша, тип хранения (trit/int8/fp16-эмбеддинг),
источник (демо / холодный экспорт / QAT), словарь, число слоёв, бит на параметр.

**2. Память:** RSS процесса после загрузки модели и пик; для VTM — дельта RSS
`chat_server` до/после загрузки (модель живёт в этом же процессе через ctypes);
для ollama — из `GET /api/ps` (`size`, `size_vram`) и/или RSS процесса.

**3. Время и нагрузка:** TTFT, время prefill, время декода, ток/с декода, общее время,
CPU-время процесса за запрос (`resource.getrusage` / `time.process_time`), число потоков
VTM (`VTM_THREADS`), загрузка системы (load average, свободная RAM, свободный диск).

**4. Per-ответ:** prompt-токены, completion-токены, попал ли в кэш префикса
(для VTM), причина остановки (EOS/лимит), маркер «холодный/тёплый» первый токен.

**5. UI:** панель **под** чатом: два столбца метрик (по модели) + строка системы.
Обновление после каждого ответа, без внешних CDN, только 127.0.0.1.

## Критерии приёмки

- [ ] `GET /api/models` отдаёт карточки (размер, параметры, KV, тип, источник)
- [ ] `GET /api/system` отдаёт load, RAM, диск, CPU
- [ ] после ответа панель показывает TTFT / prefill / декод / ток/с / RSS-дельту
- [ ] значения проверяемы: размер файла == `stat`, RSS-дельта > 0 для VTM
- [ ] тесты на моках, полный набор зелёный

## Контекст

- Зона: `tools/chat_server.py`, `tests/test_chat_server.py`, раздел в `docs/hybrid.md`.
- Не трогать `tools/chat.py`, `eva/*`, `src/vtm/*`.
- Отчёт — первым блоком ответа.

## Отчёт исполнителя

### Что сделано

- `tools/chat_server.py`:
  - разбор контейнера `.vtm` без загрузки модели (`inspect_vtm`): размер
    файла (`stat`), параметры (сумма элементов весов по таблице тензоров),
    KV-кэш (сумма `dims` тензоров `kcache`/`vcache` × размер элемента),
    контекст, словарь, слои, байты весов, бит на параметр, тип хранения
    (trit packed20/native, int8, fp16, масштабы) и источник (демо / холодный
    экспорт / QAT по мете; `vocab 128` — эвристика для демо). Разбор
    кэшируется по `(путь, размер, mtime)`;
  - `GET /api/models` — карточки моделей (числа + `loaded`, `load`, `last`),
    без абсолютных путей;
  - `GET /api/system` — load average, свободная/общая RAM (`/proc/meminfo`
    на Linux, `vm_stat` на macOS), свободный диск, RSS и пик процесса,
    `VTM_THREADS`, ядра;
  - память: RSS через `/proc/self/status` (Linux) или `proc_pidinfo`
    (macOS), пик — `getrusage`; замер «до/после» вокруг создания бэкенда в
    `ChatCliAdapter`, дельта и время загрузки отдаются в карточке и в `done`;
  - SSE: `start` получил `cold`; `done` — `prefill_ms`, `decode_ms`,
    `decode_tokens_per_second`, `finish_reason`, `first_token`
    («холодный»/«тёплый»), `cache_prefix` (оценка по общему префиксу
    промпта, `estimated: true`), `load` (RSS-дельта), `ollama` (из
    `GET /api/ps`); `end` — `cpu_ms`/`cpu_cores` (`time.process_time()`
    вокруг запроса), снимок системы, память на старте;
  - Ollama: пробник `/api/ps` (`size`, `size_vram`) подключён только к
    реальному адаптеру Ollama; заглушки тестов его не вызывают (сеть в
    тестах запрещена);
  - HTML: под чатом панель — две колонки метрик (модель + последний ответ) и
    строка системы; обновление после каждого ответа (`done` → колонка,
    `end` → система + перезапрос карточек). CSS/JS встроены, CSP не
    менялся, внешних ссылок нет.
- `tests/test_chat_server.py`: +28 тестов (итого 48 в модуле). Синтетический
  контейнер `.vtm` собирается в тесте, поэтому числа карточки сверяются с
  тем, что тест сам положил в файл (`size == stat`, параметры, KV, словарь,
  слои, контекст, бит/параметр); отдельно — источник (демо/холодный/QAT),

  `done`/`end`, кэш префикса (первый ответ/повтор/другой промпт), холодный и
  тёплый первый токен, RSS-дельта вокруг большой аллокации, `/api/ps` через

- `docs/hybrid.md`: раздел «Метрики под чатом (задача 0145)» — откуда каждое

### Что осталось / ограничения

- **prefill = TTFT.** `vtm_api_generate` не сообщает момент конца prefill,
  поэтому prefill и TTFT — одно и то же время до первого токена; разница
  декода считается как `elapsed − first_token`. Не выдумываем.
- **Кэш префикса — оценка.** C-рантайм не отдаёт счётчик попаданий; сервер
  сравнивает общий префикс текущего и прошлого промптов и помечает ответ
  `estimated: true`, в UI — «(оценка)». Если кэш выключен — «выключен».
- **Ollama:** RSS её процесса не виден (`proc_pidinfo` чужой процесс не
  показывает, `ps` в песочнице запрещён) — только `size`/`size_vram` из
  `/api/ps`; размер файла и параметры у Ollama — «—».
- **RSS-дельта может быть 0**, если аллокатор переиспользовал уже резидентные
  страницы: это не ошибка, `loaded: true` и пик процесса показывают загрузку.
- **CPU-время** — на весь запрос (два потока), а не на колонку.
- Первый ответ по модели показывает настройку кэша как «—»: она известна
  только после загрузки бэкенда; второй ответ уже показывает реальное
  значение.
- Задача остаётся в статусе `in_progress`: статус `review`/`done` ставит
  архитектор после приёмки.
