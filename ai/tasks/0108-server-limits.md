# Сервер: лимиты запросов и мягкая деградация

## Проблема

Сервер умеет авторизацию, rate limit и метрики, но не умеет: ограничивать длину промпта,
отдавать 429 с Retry-After по маршруту, деградировать при недоступной большой модели
(отвечать локальной или скиллом) и не висеть на медленной генерации.

## Требования

- Лимит длины промпта (`EVA_MAX_PROMPT_TOKENS`): превышение → 413 с текстом.
- 429 с `Retry-After` по маршруту (не глобально), счётчик в метриках.
- Деградация: если big-клиент недоступен (таймаут/ошибка) — попытка локальной модели,
  затем скилла, затем 503 с внятным текстом; в метриках отметка degraded.
- Таймаут генерации на запрос (`EVA_REQUEST_TIMEOUT`).
- Тесты: 413/429/503 и порядок деградации на фейковых клиентах.

## Критерии приёмки

[ ] 413 при длинном промпте, 429 с Retry-After, 503 при полном отказе (тесты)
[ ] порядок деградации big → локальная → скилл → 503 проверен
[ ] метрики отражают деградацию
[ ] Python-набор зелёный

## Контекст и ограничения

- Зона: eva/server.py, tests/test_server_limits.py
- Другие файлы НЕ трогать: параллельно работают семь других агентов по своим зонам.
- **Запрещено:** pip, сеть (кроме случаев, где явно разрешено), запуск сервера на порту,
  git-коммиты, скачивание моделей.
- **Отчёт пиши первым блоком ответа** — агенты этой сессии падают на финальном шаге.
- Проверка: `python3 -m unittest discover -s tests` (сейчас 1365 тестов) и, где нужно,
  `cd src/vtm && make test`.
