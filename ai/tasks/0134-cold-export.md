# Холодный экспорт: HF-веса → .trit без обучения

## Проблема

`qat/export.py --run` берёт только чекпоинт обученного прогона. Чтобы проверить
третизацию на готовой Qwen (3B/7B/14B) и померить урон от квантования, нужен путь
«HF-веса → триты» без обучения.

## Требования

- `tools/cold_export.py`: HF-модель (safetensors) → `ternary.trit` + `non_ternary.bin`
  + `manifest.json` в формате, который принимает `tools/vtm_compile.py`.
- Квантизация: absmax на блок 128 → scale (fp32), `w/scale` → round к {−1,0,+1}.
  Только Linear (q/k/v/o/gate/up/down); нормы, bias, эмбеддинг — как есть
  (эмбеддинг по флагу `--embed trit|none`).
- **Память:** читать по шардам, не держать модель целиком (14B bf16 = 29 ГБ).
  Прогресс в stderr, `--limit-layers` для быстрой проверки.
- Манифест: конфиг (hidden, layers, heads, kv_heads, head_dim, vocab, rope_theta,
  eps, tie_embeddings), `context_window`, версия формата, sha256.
- Сверка: `--verify` — сравнить логиты тронутого экспорта с HF на 2–3 промптах
  (порог 1e-2 из-за третизации; для fp32-этапа — 1e-5).

## Критерии приёмки

[ ] Qwen 0.5B/3B проходят экспорт и компиляцию, модель запускается в vtm
[ ] память экспорта не превышает 2× размера шарда (замер)
[ ] `--verify` печатает max|Δ| против HF
[ ] тесты: квантизация на синтетике, round-trip .trit, отказ при не-поддерживаемом конфиге

## Контекст и ограничения

- Зона определяется названием задачи и файлами, которые в ней упомянуты.
- Параллельно работают пять других агентов — чужие файлы не трогать.
- **Запрещено:** pip, сеть (кроме ollama на localhost), git-коммиты, запуск
  сервера на внешнем интерфейсе, скачивание моделей HF без явного флага.
- **Отчёт пиши первым блоком ответа** — агенты этой сессии падают на финальном шаге.
- Проверка: `python3 -m unittest discover -s tests`; где нужно — `cd src/vtm && make test`.

## Отчёт исполнителя

Сделано: `tools/cold_export.py` — путь «HF-веса → триты» без обучения.
Чтение по шардам safetensors (14B bf16 больше не надо держать в памяти целиком),
`--limit-layers` для быстрой проверки, квантизация только Linear (q/k/v/o/gate/up/down)
по блоку 128 (`scale = absmax(block)`, `trit = clamp(round(w/scale), -1, 1)`),
эмбеддинг по `--embed trit|none`, манифест в формате `vtm_compile`, `--verify`
для сравнения логитов с HF.

**Проверено на живой Qwen2.5-0.5B-Instruct:**
- экспорт двух вариантов: fp16-эмбеддинг (616 МБ) и тритовый (112 МБ);
- `vtm_compile` → `/tmp/qwen05b.vtm` (111,7 МиБ), путь: «KV-кэш 24 МиБ при
  context_len=1024 (кэп 512 МиБ)»;
- `./vtm run` — модель считает: SIMD 6,7–7,6 ток/с, scalar 0,7 ток/с;
- одинаковые токены на scalar и SIMD (141450 31341 89545 …) — то есть путь
  «экспорт → компиляция → прогон» замкнут.

Тесты: 26 в `tests/test_export_cold.py` (квантизация на синтетике, round-trip .trit,
отказ на неподдерживаемом конфиге), OK.

Оговорки: `--verify` против HF на 0.5B даёт допуск 1e-2 (третизация без QAT);
качество не мерилось — это задача 0136; 3B/14B не прогонялись (диск/время).
