# Виртуальная троичная машина: Python-эталон и компилятор графа

## Проблема

C-интерпретатору нужен численный эталон и способ собрать программу из графа модели.
Без эталона расхождения в логитах не отладить.

## Требования

- `tools/vtm_ref.py`: запись/чтение `.vtm` строго по спеке (заголовок 32, запись 44,
  данные с выравниванием 32), эталонный исполнитель всех операций v0.1.
- `tools/vtm_compile.py`: компилятор декодер-слоя (RMSN → QKV → ROPE → KVW → ATTN →
  o_proj → ADD → RMSN → gate/up → SILU → MUL → down → ADD) и генератор синтетической модели.
- Тесты: round-trip контейнера, контрольные векторы тритов, TMV/RMSN/SM на числах с бумаги,
  битый файл → ValueError, детерминированный результат синтетики.

## Критерии приёмки

[ ] `python3 -m unittest tests.test_vtm_ref -v` — зелёно
[ ] `python3 tools/vtm_compile.py --synthetic --out /tmp/synth.vtm` создаёт файл
[ ] Синтетический слой даёт зафиксированное число (в тесте)
[ ] Полный `python3 -m unittest discover -s tests` не сломан

## Контекст и ограничения

Зона: `tools/vtm_ref.py`, `tools/vtm_compile.py`, `tests/test_vtm_ref.py`.
Без torch; numpy опционален, код обязан работать без него. Коммиты не делать.

## Отчёт исполнителя

Сделано: `tools/vtm_ref.py` (контейнер `.vtm` строго по спеке, эталонный
исполнитель всех операций v0.1, контрольные векторы тритов), `tools/vtm_compile.py`
(компилятор слоя: RMSN → QKV → ROPE → KVW → ATTN → o_proj → ADD → RMSN →
gate/up → SILU → MUL → down → ADD, плюс генератор синтетики), `tests/test_vtm_ref.py`.

Проверено архитектором при приёмке:
- `python3 -m unittest discover -s tests` → 121 тест OK (61 из них — VTM)
- round-trip контейнера: max|Δ| логитов = 0
- синтетика двух режимов (attn: 28 тензоров / 21 инструкция; mlp: 14 / 10) даёт
  зафиксированные контрольные числа, C сходится с ними

Важно: исполнитель нашёл две несовместимости с C (смещение `imm` в инструкции и
блок масштаба 128 против 160) и передал точный контракт — C-агент их исправил.
Именно это и было целью задачи.
