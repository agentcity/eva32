# Веб-адаптер: сравнение двух моделей рядом

## Проблема

Для оценки «насколько умна» нужно видеть два ответа рядом: наша тритовая
против Qwen. Скрипт этого не даёт — нужна страница.

## Требования

- `tools/chat_server.py`: минимальный сервер (stdlib, без зависимостей) на
  localhost: `GET /` — страница, `POST /api/chat` — SSE-стрим.
- Выбор двух бэкендов (vtm + ollama) и моделей; один вопрос — два ответа **рядом**,
  с временем и ток/с у каждого.
- Никаких внешних CDN: один HTML-файл со встроенным CSS/JS.
- Не слушать наружу (127.0.0.1), порт по `--port`, закрытый список бэкендов.
- Тесты: страница отдаётся, API отвечает на мок-бэкенде.

## Критерии приёмки

[ ] страница отдаётся на 127.0.0.1, два ответа рядом
[ ] SSE-стрим работает для обоих бэкендов
[ ] нет внешних запросов (проверка: в HTML нет http-ссылок)
[ ] тесты на моках

## Контекст и ограничения

- Зона определяется названием задачи и файлами, которые в ней упомянуты.
- Параллельно работают пять других агентов — чужие файлы не трогать.
- **Запрещено:** pip, сеть (кроме ollama на localhost), git-коммиты, запуск
  сервера на внешнем интерфейсе, скачивание моделей HF без явного флага.
- **Отчёт пиши первым блоком ответа** — агенты этой сессии падают на финальном шаге.
- Проверка: `python3 -m unittest discover -s tests`; где нужно — `cd src/vtm && make test`.

## Отчёт исполнителя

Сделано: `tools/chat_server.py` — локальная страница сравнения двух моделей.
Сервер слушает только 127.0.0.1 (`--port`), один вопрос уходит в оба бэкенда
параллельно, ответы стримятся рядом (SSE: start/delta/done/error/end + [DONE]).

- `GET /` — одна HTML-страница, CSS/JS встроены, внешних ссылок и CDN нет
  (CSP `default-src 'none'`), ровно один `<style>` и один `<script>`;
- `GET /api/backends` — закрытый реестр (vtm, ollama), без путей и токенизаторов;
- `POST /api/chat` — клиент присылает только `backend` и `model` из реестра,
  неизвестное → 400 до открытия потока; `use_system` подмешивает
  `prompts/system.assistant.md` одинаково обеим моделям; max_tokens 1..1024;
- переиспользует `tools/chat.py` (`build_backend`, `OpenAIChatBackend`, `StreamEvent`).

Проверено: 20 тестов (моки), `curl` страницы — 200, 15 770 байт, 0 внешних ссылок;
живой SSE с работающей Ollama (VTM 4,81 ток/с, Ollama 24 токена) и с остановленной
(одна колонка отдаёт done, другая error, поток завершается). Полный набор 1905 OK.

Оговорки: список моделей статический (`--ollama-model` расширяет); `runs/tiny` и
`demo` — gitignored артефакты; для реальной модели нужен её `tokenizer.json`;
сервер без аутентификации, только loopback.
