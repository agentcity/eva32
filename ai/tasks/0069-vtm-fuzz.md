# Волна 4: фаззинг и санитайзеры в CI

## Проблема

Проверено 7 обрезаний файла. Случайные байткоды, операнды, регистры и мета не
проверялись; ASan/UBSan гоняли вручную, в CI их нет.

## Требования

- `tools/fuzz_vtm.py`: мутации валидного контейнера (байты заголовка, таблицы,
  программы, меты) + прогон `vtm run --tokens 1 --max-new 1`; ищет падения (сигналы,
  коды >= 128) и таймауты. Размер: 5000 мутаций по умолчанию, `--iterations`.
- Санитайзеры: цель `make sanitize` (ASan+UBSan, `-O1 -g`) для `test_vtm` и прогона
  демо; результат — в отчёте.
- Зафиксировать найденное: если мутация ломает — завести задачу, а не «иногда падает».
- Документ: что фаззим, сколько итераций, что не найдено.

## Критерии приёмки

[ ] 5000 мутаций без сигналов и без подвисаний (время прогона в отчёте)
[ ] `make sanitize` собирается и проходит на demo/model.vtm
[ ] найденные дефекты либо исправлены, либо записаны задачами с воспроизведением
[ ] раздел в docs/vtm-perf.md с числами

## Контекст и ограничения

- Зона: tools/fuzz_vtm.py, tests/vtm/fuzz_interp.c, docs/vtm-perf.md (раздел «проверки»)
- Другие файлы НЕ трогать: параллельно работают семь других агентов по строго
  разным файлам. Пересечение зон запрещено.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- Не менять поведение без новых флагов.
- Не коммитить: сдавать правки и отчёт.

## Отчёт исполнителя

Сделано: `tools/fuzz_vtm.py` (мутации по секциям, 5000 итераций за 19,8 с,
0 сигналов, 0 таймаутов), `tests/vtm/fuzz_interp.c` (in-process фаззер), раздел в
docs/vtm-perf.md, артефакты в `fuzz-findings/`.

**Найден настоящий дефект:** ATTN с 2-D K/V-кэшем и `imm=INT_MAX` — signed overflow
`q_start+q_len`, отрицательный `key_count` проходил проверку «больше ctx», malloc
получал отрицательную длину → **SIGBUS** (exit 138). Минимальный repro сохранён,
sha256 08d0b55d…. Исправлено архитектором (задача 0075), регрессионный тест добавлен.

Санитайзеры: ASan/UBSan прогоны чистые, кроме известного unaligned TRT1 из 0060
(backend_scalar.c), который закрывается `-DVTM_UNALIGNED_LOADS=0`.
