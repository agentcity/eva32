# Быстрая проверка целостности

## Проблема

Проверка sha256 контейнера (задача 0066) стоит **6,15 с на 1,3 ГБ**: портативный C99
SHA-256 даёт 0,21 ГБ/с, тогда как hashlib/OpenSSL на той же машине — 2,39 ГБ/с.
Для сервера это разовая цена, но каждый CLI-запуск на настоящей модели ждёт её заново.

## Требования

- Один из вариантов (выбрать по замеру):
  1. аппаратный SHA: SHA-NI на x86 (через `__builtin_cpu_supports("sha")`), ARMv8
     crypto extensions на ARM, с откатом на портативную реализацию;
  2. кеш проверки: рядом с контейнером файл `<model>.vtm.shaok` с mtime+size+inode,
     при совпадении — не хешировать (но помнить: кеш не защищает от подмены файла тем,
     кто может писать в каталог).
- Замер до/после на 1,3 ГБ; цель — < 1 с.
- Поведение при несовпадении — как сейчас (VTM_E_INTEGRITY, без падения).

## Критерии приёмки

- [ ] проверка 1,3 ГБ занимает < 1 с (число в отчёте), при этом подмена байта всё ещё ловится
- [ ] откат на портативную реализацию работает (тест)
- [ ] `make test` и полный Python-набор зелёные

## Контекст и ограничения

- Зона: `src/vtm/loader.c` (или новый `src/vtm/sha256.c`), `src/vtm/Makefile`, тесты.
- Делать после аренды: сейчас этот путь не на критическом пути (модель грузится раз).
