# ATTN: блочный attention с онлайн-softmax + окно контекста

## Проблема

Профиль (0071) показал: на ctx=2048 attention занимает 87% прохода (0,231 мс/шаг),
при ctx=512 — 61%. ATTN считает наивно: массив scores на весь ключевой диапазон,
двухпроходный softmax, без блокировки. Это первое узкое место после включения SIMD.

## Требования

- Блочный проход по ключам с онлайн-softmax (running max/sum), без массива на всю
  длину: память O(блок), а не O(ctx).
- Окно контекста: при позиции >= ctx — сдвиг (ротация K/V), позиции для ROPE
  корректны; диалог длиннее ctx не падает и не теряет последние токены.
- Численно совпадает с текущим ATTN в пределах 1e-5 (тест на 5 конфигурациях).
- Замер до/после на ctx 512/2048 (мс/шаг) — числа в отчёте.
- Если окно не выходит — сдай тайлинг, окно оставь как невыполненное.

## Критерии приёмки

[ ] max|Δ| против прежнего ATTN < 1e-5 (тест)
[ ] пиковая память ATTN не зависит от ctx (замер/оценка)
[ ] ctx=2048: ускорение замерено числом
[ ] генерация 2×ctx токенов без ошибки (окно)
[ ] make test и полный Python-набор зелёные

## Контекст и ограничения

- Зона: src/vtm/interp.c, src/vtm/vtm.h, src/vtm/vtm_internal.h, tests/vtm/test_vtm.c
- Другие файлы НЕ трогать: параллельно работают три других агента по строго разным файлам.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- По умолчанию теперь `VTM_BACKEND=auto` (SIMD, если доступен).
- **Отчёт пиши первым блоком в ответе**, потом код: агенты этой сессии падают в конце.
- Не коммитить: сдавать правки и отчёт.

## Отчёт исполнителя

Сделано: блочный ATTN (блоки по 64) с онлайн-softmax — `scores[ctx]` больше не
аллоцируется, память O(head_dim+64); окно контекста через кольцевую запись
`pos % win` с глобальными ROPE-позициями; защита 0075 сохранена.

Проверено архитектором: `make test` зелёный, 1061 тест Python зелёный, генерация
**16 токенов при ctx=8** проходит (21 390 ток/с), фикстура imm=INT_MAX даёт
«ATTN: q_start=2147483647 вне диапазона», а не SIGBUS.

Числа исполнителя: ATTN 2,4× (demo ctx2048 0,472→0,191 мс) и 3,0× (8h/2kv/d64
1,913→0,627 мс), max|Δ| = 0 против наивного эталона на 5 конфигурациях. Полный
проход: simd 1,55× @512 и **2,04× @2048**.

Не сделано и записано: `tools/vtm_ref.py` не знает окно (C и Python разойдутся
только при позиции >= ctx), `docs/vtm.md` устарел в части ATTN — заведена 0080.
