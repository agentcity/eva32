# ATTN: блочный attention с онлайн-softmax + окно контекста

## Проблема

Профиль (0071) показал: на ctx=2048 attention занимает 87% прохода (0,231 мс/шаг),
при ctx=512 — 61%. ATTN считает наивно: массив scores на весь ключевой диапазон,
двухпроходный softmax, без блокировки. Это первое узкое место после включения SIMD.

## Требования

- Блочный проход по ключам с онлайн-softmax (running max/sum), без массива на всю
  длину: память O(блок), а не O(ctx).
- Окно контекста: при позиции >= ctx — сдвиг (ротация K/V), позиции для ROPE
  корректны; диалог длиннее ctx не падает и не теряет последние токены.
- Численно совпадает с текущим ATTN в пределах 1e-5 (тест на 5 конфигурациях).
- Замер до/после на ctx 512/2048 (мс/шаг) — числа в отчёте.
- Если окно не выходит — сдай тайлинг, окно оставь как невыполненное.

## Критерии приёмки

[ ] max|Δ| против прежнего ATTN < 1e-5 (тест)
[ ] пиковая память ATTN не зависит от ctx (замер/оценка)
[ ] ctx=2048: ускорение замерено числом
[ ] генерация 2×ctx токенов без ошибки (окно)
[ ] make test и полный Python-набор зелёные

## Контекст и ограничения
