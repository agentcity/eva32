# Волна 1: C-ABI для сервера — колбэк и отмена

## Проблема

Сейчас ВТМ — это CLI. Сервер на Python не может её вызвать иначе как через
subprocess, а стриминг и отмена через процесс — костыль. Нужен нормальный C-ABI.

## Требования

- `api.h`: `vtm_api_open(path, opts)`, `vtm_api_generate(ctx, prompt_ids, n, cb, user)`,
  `vtm_api_cancel(ctx)`, `vtm_api_close(ctx)`, `vtm_api_last_error(ctx)`.
- Колбэк: `int (*cb)(const int32_t *ids, size_t n, void *user)`; возврат ≠0 — остановка.
- Отмена из другого потока: атомарный флаг, проверяется между токенами; генерация
  завершается корректно, а не по SIGSEGV.
- Один контекст = одна машина + буферы; повторное использование после reset.
- Собрать в libvtm.a (добавить api.o в Makefile), тест на C: 3 токена, отмена после
  первого, повторный запуск после reset.
- Python-обвязка НЕ нужна (это в eva), но ABI должен быть стабильным (extern "C").

## Критерии приёмки

[ ] libvtm.a содержит api.o; `make test` зелёный
[ ] тест: generate с колбэком даёт >=2 токена; cb вернул 1 — остановились
[ ] тест отмены: флаг из «другого потока» (pthread) останавливает генерацию
[ ] повторный generate после reset даёт тот же ответ
[ ] valgrind/ASan-прогон теста чистый (если доступно)

## Контекст и ограничения

- Зона: src/vtm/api.c, src/vtm/api.h, src/vtm/Makefile, tests/test_vtm_api.c
- Другие файлы НЕ трогать: параллельно работают семь других агентов по строго
  разным файлам. Пересечение зон запрещено.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- Не менять поведение без новых флагов.
- Не коммитить: сдавать правки и отчёт.
