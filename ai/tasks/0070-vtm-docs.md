# Волна 4: спецификация ВТМ к текущему состоянию

## Проблема

За месяц ВТМ обросла: контейнер v0.2, мета, тритовые эмбеддинги, сэмплинг с ГПСЧ,
чат-шаблон, SIMD, mmap. Документы частично устарели или противоречат коду.

## Требования

- Сверить `docs/vtm.md` с кодом: опкоды и их imm, поля меты (все ключи и дефолты),
  формат v0.2, layouts тритов, контракт sэмплинга и ГПСЧ, EMB из trit/fp16.
- `src/vtm/README.md` — привести к текущему (убрать «SAMP только greedy», «v0.1»).
- Добавить раздел «что не реализовано» с честным списком (окно, потоки, кеш промпта).
- Проверка: скрипт, который сверяет имена опкодов из docs с таблицей в коде (по
  крайней мере количество и имена).

## Критерии приёмки

[ ] в docs/vtm.md нет утверждений, противоречащих коду (проверено по чек-листу)
[ ] все ключи меты перечислены с дефолтами
[ ] раздел «не реализовано» есть и честен
[ ] скрипт сверки опкодов проходит

## Контекст и ограничения

- Зона: docs/vtm.md, docs/vtm-perf.md, src/vtm/README.md
- Другие файлы НЕ трогать: параллельно работают семь других агентов по строго
  разным файлам. Пересечение зон запрещено.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- Не менять поведение без новых флагов.
- Не коммитить: сдавать правки и отчёт.
