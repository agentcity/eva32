# 4B умнее, но думает в 4 раза дольше

## Замеры (мои, тёплый процесс, одинаковый промпт ~300 токенов)
| модель | первый токен | параметров |
|---|---|---|
| 3B Qwen2.5 | **7,02 с** (43 ток/с) | 3,09 млрд |
| 4B Qwen3 | **31,14 с** (10 ток/с) | 4,02 млрд |

Разница параметров — 1,3×, а prefill — 4,4×. Значит дело не в размере, а в
пути исполнения. Подозрения:
1. **QK-norm (RMSH)** у Qwen3 не поддержан в батчевом/Metal-пути → per-token
   фолбэк на часть графа;
2. 4B: 8 KV-голов против 2 у 3B → внимание при prefill дороже (но O(n²) при
   n≈300 не даёт 4×);
3. head_dim/раскладка KV в 4B может ломать векторный путь;
4. tied lm_head + vocab 151 936: lm_head на пачке считается для всех токенов
   (0214 отмечал ~0,5 с на 250 токенов у 3B).

## Требования
1. Профиль 4B prefill по операциям (`--trace-summary`, VTM_BATCH_TRACE):
   GEMM/attention/RMSN/RoPE/lm_head — где 4B теряет время против 3B.
2. Проверить, попадает ли RMSH в батчевый путь, и если нет — добавить
   батчевый RMSH (CPU и Metal).
3. Убрать лишние проходы: lm_head только для последнего токена пачки (без
   изменения семантики SAMP — либо через флаг, либо через отдельный вызов).
4. Цель: prefill 4B ≈ 3B × 1,3–1,5, т.е. 250 токенов ≤5 с (сейчас 13–31).
5. Точность: argmax совпадает, Δ≤1e-5 (или документированный допуск).
