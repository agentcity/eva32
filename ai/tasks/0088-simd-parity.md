# Паритет SIMD

## Проблема

После переключения на `VTM_BACKEND=auto` (1570828) `tools/parity_random.py` стал
красным: 42/50 конфигураций, худшее max|Δ| = 1,05e-04 при пороге 1e-5. Причина —
SIMD-ядра переупорядочивают суммирование, округление другое. На скалярном бэкенде
расхождение ровно 0.

Сейчас паритетные пробы форсируют `VTM_BACKEND=scalar` (`VTM_PARITY_BACKEND`
переопределяет), то есть гарантия «бит-в-бит» относится только к скалярному пути.
Это честно, но не задокументировано и не измерено систематически.

## Требования

- Измерить распределение расхождения SIMD по 50 случайным конфигурациям: max, p95,
  медиана; отдельно для TMV/MM/ATTN (какая операция даёт вклад).
- Проверить, не влияет ли расхождение на **argmax** (то есть на реальные ответы):
  сколько конфигураций меняют выбранный токен при расхождении 1e-4.
- Записать в `docs/vtm.md` и `docs/quantization.md`: паритет побитовый — скаляр;
  SIMD — приближённый, с измеренными числами и вердиктом «влияет/не влияет на ответы».
- Если argmax где-то меняется — это баг, а не допуск: завести задачу.

## Критерии приёмки

- [x] распределение расхождения SIMD (50 конфигураций) — числа в отчёте
- [x] проверено влияние на argmax (число смен токена)
- [x] в документах явно сказано, какой бэкенд даёт побитовый паритет

## Отчёт исполнителя

Сделано: `tools/parity_simd.py` (прогон одного контейнера двумя бэкендами:
распределение Δ, смены argmax, запас отрыва, `--per-op`, `--json`, код 1 при смене),
`parity_random.py` получил `--backend`/`--compare-backends`, 63 теста, раздел в
`docs/quantization.md` и краткая версия в `docs/vtm.md`.

**Результат (50 конфигураций, scalar vs auto, arm64/NEON):**
- Δ: медиана **6,11e-06**, p95 2,62e-05, максимум **1,049e-04**;
- побитово равны 0/50; вне 1e-5 — 8/50; ≥1e-4 — 1/50;
- **смен argmax 0/50**, top-5 не изменился;
- структурный критерий: самый узкий отрыв top1–top2 = 8,69e-03 при Δ=3,8e-06
  (отношение 2279×); у худшей по Δ конфигурации — 0,254 при 1,049e-04 (2421×).
  Ни одной конфигурации с отрывом < 2Δ (условие, при котором переворот возможен).

Вердикт: SIMD-расхождение на argmax не влияет; порог 1e-5 применим только к скаляру.
Баг-задачи не требуется.

Контроль: scalar против Python-эталона — max|Δ| = 0 на всех 50, argmax совпал 50/50.

Оговорки: числа сняты на arm64/NEON (на AVX2 порядок тот же, конкретные Δ другие);
конфигурации маленькие, поэтому «запас 41×» индикативен для 1.5B, но структурный
критерий верен всегда.
