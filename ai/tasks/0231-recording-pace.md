# Готовая запись тоже частит

## Проблема
Актёрские записи (0223) играются через `afplay` в обычном темпе — для ребёнка
быстро. У `afplay` есть `-r <rate>` (1.0 — обычный темп, 0.85 — медленнее,
без изменения тона) и `-v` (громкость).

## Требования
1. **Темп записи по умолчанию 0.9** (на 10 % медленнее) — детский режим.
2. **Команды** в плагине сказок: «медленнее» → −0.05 (минимум 0.75),
   «быстрее» → +0.05 (максимум 1.15), «обычный темп» → 1.0; ответ числом
   («Читаю на 90 процентах скорости»).
3. **Применение**: коэффициент хранится в состоянии плагина и передаётся в
   `afplay -r`; смена темпа во время игры — перезапуск записи с новой
   скоростью и **той же позиции** (позицию считать по прошедшему времени ×
   старый темп; если позицию восстановить нельзя — честно начать сначала и
   сказать).
4. Не ломать: «выключи», «включи запись сказки», дубли колонок.
5. Тесты: argv содержит `-r` с ожидаемым значением, команды меняют темп в
   пределах, «медленнее» на минимуме не уходит ниже 0.75, перезапуск с
   позицией, обычный чат не затронут.
6. Живой прогон: «включи запись сказки» → `pgrep afplay` показывает процесс
   с `-r 0.9`; «медленнее» → новый процесс с `-r 0.85`.

## Критерии приёмки
- [x] записи идут на 0.9 по умолчанию
- [x] «медленнее/быстрее/обычный темп» работают, границы соблюдены
- [x] позиция при смене темпа сохраняется (или честный откат с сообщением)
- [x] тесты плагина зелёные (40/40), набор без чужого `tests/test_tale_images.py`
      — 2930 OK; 10 падений в нём — незавершённая 0228 (картинок меньше 6),
      к этой задаче не относятся

## Отчёт исполнителя

**argv.** `_play_audio` (и перезапуск) запускают только
`subprocess.Popen([AFPLAY, "-r", _format_rate(rate), str(path)],
start_new_session=True)`: `-r 0.9` по умолчанию, путь — последний элемент,
`-r` и значение идут сразу после бинарника. Громкость осталась системной
(`osascript`), в argv afplay не добавлялась. `_format_rate` печатает
`0.9 / 0.85 / 1.0` (без «0.90»), `_clamp_rate` держит 0.75…1.15 с шагом 0.05
без хвостов float.

**Темп.** `DEFAULT_RATE = 0.9`, `MIN_RATE = 0.75`, `MAX_RATE = 1.15`,
`RATE_STEP = 0.05`, `NORMAL_RATE = 1.0`. Темп — состояние плагина
(`_audio_rate`, свойство `audio_rate`), поэтому он действует и на следующую
запись. Команды (`_answer_pace`, регэкспы `_PACE_SLOWER_RE`,
`_PACE_FASTER_RE`, `_PACE_NORMAL_RE`):

| Команда | Что отвечает |
|---|---|
| «медленнее», «помедленнее», «читай медленнее» | «Читаю на 85 процентах скорости» |
| «быстрее», «побыстрее», «читай быстрее» | «Читаю на 95 процентах скорости» |
| «обычный темп», «нормальная скорость» | «Читаю на 100 процентах скорости» |
| на границе | «Медленнее уже нельзя: читаю на 75 процентах скорости» / «Быстрее уже нельзя…» |

Вне игры темп запоминается: «Хорошо, буду читать на 85 процентах скорости».
Ответ во время игры — `{"text": …, "silent": true}` (Ева не говорит поверх
записи). Чтобы не перехватывать обычный чат, без играющей/только что
игравшей записи команда принимается, только если в ней есть темп/чтение и
нет «сказка/история/музыка»: «Расскажи медленно сказку про репку» остаётся
просьбой сказки, «Включи музыку быстрее» — зоной music.

**Позиция при смене темпа.** Позиция = `смещение + (now − старт) × старый
темп` (0.9 за секунду проходит 0.9 секунды файла), свойство
`audio_position`. `afplay` не умеет начинать файл с середины (проверено:
`-t` — это длительность, а не старт; других ключей нет). Поэтому плагин:
`afinfo` → частота дискретизации и длительность; `afconvert --offset
<кадры> -f WAVE -d LEI16 <mp3> -o <временный WAV>` — обрезка начала во
временный файл в `TMPDIR`; `afplay -r <новый темп> <временный WAV>`.
Временный WAV удаляется при «выключи», при следующей смене темпа и при
завершении/падении afplay. Если `afinfo`/`afconvert` не справились, запись
начинается сначала, временный файл не остаётся (проверено), а ответ честно
добавляет: «…Начну запись сначала — не получилось сохранить место». Если
afplay вообще не перезапустился: «Темп — 85 процентов, но перезапустить
запись не получилось» (без `silent`, запись уже не играет).

**Не сломано.** «Выключи»/«стоп сказку» по-прежнему гасят процесс
(`SIGCONT` → `terminate` → `kill`), метка «только что остановили» даёт двум
колонкам один ответ. «Включи запись сказки» работает как раньше; повтор того
же слага не плодит второй `afplay`; смена темпа гасит старый процесс и
оставляет ровно один новый (`pgrep` это показал). `_play_audio` для повторов
сохранён (та же сигнатура, проверка «уже играет этот слаг»). Порядок в
`answer`: стоп → темп → выбор сказки → громкость.

**Тесты** (`tests/test_tale_audio.py`, было 23 — стало 40, все зелёные):
argv содержит `-r 0.9`; «медленнее»/«быстрее» дают `-r 0.85`/`-r 0.95` и
перезапуск с позицией (проверяется и `audio_position` = 27.0 при 30 с на
0.9, и секунды, переданные в обрезку); границы 0.75/1.15 (пять «медленнее» и
восемь «быстрее» не выходят за них, на границе Popen не вызывается);
«медленнее» на минимуме не ниже 0.75; «обычный темп» → `-r 1.0`; честный
откат при недоступной обрезке; обычный чат не затронут (в т.ч. «Расскажи
медленно сказку», «Включи музыку быстрее», «Поезд едет быстрее»); временный
WAV удаляется на «выключи»; `afconvert --offset` считается в кадрах.
