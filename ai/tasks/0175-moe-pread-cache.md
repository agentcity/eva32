# pread вместо страничных отказов

## Проблема
Полная 30B MoE: 18,55 ГБ контейнер, 16 ГиБ RAM. Каждый токен трогает ~1,5 ГБ через
mmap; замер: 19,21 с на токен, **sys 10 с** — это 355 984 page fault и 137 619 reclaim
(страницы по 16 КБ, ~94 тыс. на токен). Паттерн случайный (8 экспертов из 128 на слой),
readahead не работает.

## Требования
- В `MOE` (interp.c): выбранные эксперты читать **явным `pread`** крупными кусками
  (256 КБ–1 МБ) в собственный кэш, а не через mmap-страницы.
- Кэш: фиксированный бюджет `--moe-cache-mb` (по умолчанию 3072), LRU по экспертам;
  слоты выровнены, повторное использование без malloc на токен.
- Опционально: асинхронная предзагрузка следующего слоя (один поток).
- Замер: ток/с, sys-время, page faults до/после на полной 30B
  (`runs/q4/qwen3-30b-a3b.vtm`), плюс RSS и попадания кэша.
- Цель: ≥0,8 ток/с (сейчас 0,21); sys-время хотя бы вдвое меньше.

## Критерии приёмки
- [ ] ток/с ≥0,8 на полной 30B (или честное объяснение потолка)
- [ ] page faults снижены, sys-время измерено
- [ ] argmax совпадает с mmap-путём на 3 промптах
- [ ] `make test`, `--check` зелёные
