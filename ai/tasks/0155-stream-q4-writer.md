# Потоковая запись Q4

## Проблема

Полный 3B Q4 не собирается: `vtm_ref.decode_q4_segment_ex` возвращает `list[int]`
(2,77 млрд значений ≈ 22 ГиБ указателей), а `pack_q4` в `write_vtm` материализует
ещё один такой список — пик ~45 ГиБ на машине с 16 ГиБ.

Сам контейнер влезает: 3B Q4 ≈ 1,92 ГиБ (u32-смещения), 7B ≈ 3,9 ГиБ при fp16-масштабах.

## Требования

- `tools/vtm_ref.py`: запись Q4 **потоково** — чанки по группам 32 (или по строкам),
  без промежуточных `list[int]` на весь тензор.
- `decode_q4_segment_ex` — вариант с итератором/чанками, который не держит весь тензор;
  старый API сохранить для мелких тестов (или сделать тонкой обёрткой).
- Пик памяти на 3B ≤ 2 ГиБ, на 7B ≤ 3 ГиБ; замер в отчёте.
- Проверка: полный 3B Q4 (импорт 0153 → компиляция → контейнер) собирается,
  C запускает 1 токен, паритет с Python ≤1e-5; файл ≤ 4 ГиБ (ADR 0016) или
  документированный отказ для 7B с fp32-масштабами.
- Не менять формат: байты контейнера должны совпадать с текущим побайтово
  (сверка sha256 на срезе).

## Критерии приёмки

- [x] полный 3B Q4 собран, C считает токен, паритет ≤1e-5
- [x] пик RSS ≤ 2 ГиБ (замер)
- [x] байты контейнера совпадают с текущим путём (sha256 на срезе)
- [x] 7B: либо собран, либо отказ с числами (fp32 vs fp16-масштабы)

## Отчёт исполнителя

Сделано: `tools/vtm_ref.py` — ленивые окна (memoryview) вместо `list[int]` для
Q4/INT8, потоковая запись контейнера чанками 1 МиБ с digest на лету, список-API
сохранён для мелких тестов; 16 новых тестов (`tests/test_q4_stream.py`), полный
набор 2238 OK.

**Полный 3B Q4 собран:** импорт из ollama (q4_K_M) → компиляция → **1,92 ГиБ**
контейнер → наш C-рантайм считает токены. Байты контейнера побайтово совпали со
старым путём (sha256 на срезе и на tiny-фикстурах), паритет C↔Python 1,435e-6.

Пик памяти: было ~45 ГиБ (списки), стало 3,95 ГиБ footprint; остаток — не в
писателе, а в `load_export` (`vtm_compile.py` читает q4.bin целиком дважды).
Правка на mmap (5 строк) даёт footprint 108 МиБ при том же sha256 — измерена,
но была вне зоны; применяю сам.

**7B не влезает (отказ с числами):** 7,07 млрд Q4-весов. fp32-масштабы + int8-эмбеддинг
= 116% от 4 ГиБ; fp16-масштабы + int8-эмбеддинг = 105,7%; влезает только fp16-масштабы
+ тритовый эмбеддинг (95%). Ни флага fp16-масштабов, ни trit-эмбеддинга в импортёре
нет — задача 0156.

**Скорость — главная проблема:** 3B Q4 в нашем рантайме идёт **4,2 с/токен**
(0,2 ток/с) против ~20 у ollama: Q4-ядра скалярные, без NEON и батчинга.
Задача 0157.
