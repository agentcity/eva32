# Квантованные эмбеддинги сквозь путь

## Проблема

Задача 0036 нашла: `qat/export.py` не квантует эмбеддинги — даже при
`quantize_embeddings: trit` они уходят в `non_ternary.bin` как fp32-мастер. То есть
обученная модель с троичными эмбеддингами на диск ляжет **fp16/fp32**, и вся
экономия, ради которой затевался эксперимент 0027, исчезнет на экспорте.

Плюс рантайм: `EMB` в ВТМ умеет fp32/fp16/bf16, но не триты — то есть даже
положенные в контейнер тритовые эмбеддинги сейчас не прочитать.

## Требования

- `qat/export.py`: при `quantize_embeddings: trit` таблица словаря квантуется тем же
  правилом (absmax по блоку 128) и пишется **в `ternary.trit`** отдельным сегментом
  с именем `model.embed_tokens.weight`; в манифесте — запись с `kind: trit`.
  При `int8` — int8-тензор + масштабы (новый kind 4 в контейнере).
  При `none` — как сейчас, fp32 в `non_ternary.bin`.
- `tools/vtm_compile.py`: если эмбеддинги тритовые — `EMB` берёт их из тритового
  тензора; `tied lm_head` через MM должен работать с тритовой таблицей.
- `src/vtm/interp.c`: `EMB` читает тритовый тензор (LUT243) и int8-тензор.
- `docs/vtm.md`: kind 4 = int8 (если вводим) и правило «эмбеддинги могут быть в trit/int8».

## Критерии приёмки

- [x] экспорт с `trit` даёт `ternary.trit`, содержащий таблицу словаря; размер
      экспорта меньше, чем при `none` (числа в отчёте)
- [x] `EMB` из тритового тензора возвращает те же значения, что расквантование в Python (1e-6)
- [x] tied lm_head работает с тритовой таблицей (тест)
- [x] `python3 -m unittest discover -s tests` и `cd src/vtm && make test` зелёные
- [x] int8: либо реализован, либо явно записано «отложено, причина» — без тишины

## Контекст и ограничения

- Зона: `qat/export.py`, `tools/vtm_compile.py`, `src/vtm/interp.c`,
  `src/vtm/vtm.h`, `docs/vtm.md`, `tests/test_embeddings_e2e.py`.
- НЕ трогать `src/vtm/main.c` (параллельно 0040) и `src/vtm/loader.c` (стабилен после 0035).
- torch на машине нет: чистые функции (квантование, манифест, компиляция) тестируются
  на fake-тензорах, как это делал 0029.
- Реальный прогон QAT — на аренде (0027), не здесь.

## Отчёт исполнителя

Сделано: тритовая таблица словаря пишется первым сегментом `ternary.trit`,
манифест помечает её `kind: trit`, компилятор эмитит `EMB` по тритовому тензору,
tied lm_head — MM по той же таблице; в C `EMB` читает строку через LUT243, MM
считает по тритам без материализации. 10 тестов, полный набор 697 зелёный.

Размеры: синтетика 128×128 — экспорт 37 776 Б против 99 486 Б (62% меньше);
Qwen 1.5B по формату — сегмент 48,0 МиБ против 890,2 МиБ fp32 (−94,6%).

Отложено с причиной: int8-эмбеддинги (нужен kind 4) — заведена задача 0044,
и раннер эксперимента 0027 исправлен: int8-ветка больше не падает, а помечается
«экспорт отложен», качество при этом всё равно измеряется.
