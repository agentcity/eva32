# u64-смещения (ADR 0019)

## Проблема
Контейнер v0.2 хранит offset/size в u32 → предел 4 ГиБ (ADR 0016). Полная
Qwen3-30B-A3B в Q4 — **19,3 ГБ**, в один `.vtm` не влезает. 14B Q4 (8,6 ГиБ) тоже
ждёт этого.

## Требования (по ADR 0019)
- Запись тензора 52 → 60 байт (offset, scale_offset, размеры — u64), версия 3.
- `tools/vtm_ref.py`: запись/чтение v0.2 и v0.3; пишем v0.2, пока контейнер ≤4 ГиБ,
  v0.3 — только когда иначе нельзя (выбор печатается в stderr).
- `src/vtm/loader.c`: разбор обеих версий; v0.3 старыми бинарями отвергается с текстом.
- `tools/vtm_compile.py`: `--container-version auto|2|3`.
- Проверка: 14B Q4 (или синтетика 5 ГиБ) собирается, грузится, считает токен;
  старые v0.2 читаются без изменений (полный набор тестов зелёный).
- Замер: размер файла и время сборки для 5-гигабайтного контейнера.

## Критерии приёмки
- [ ] контейнер >4 ГиБ пишется и читается, C считает токен
- [ ] v0.2 совместим (все прежние тесты), v0.3 отвергается старым бинарём с текстом
- [ ] `auto` выбирает версию по размеру
- [ ] `make test`, полный набор, docs зелёные
