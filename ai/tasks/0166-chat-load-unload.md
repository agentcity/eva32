# Загрузка модели в память: кнопка, статус, реальный объём

## Проблема

Сейчас первый запрос в чате платит за загрузку модели (2,24 ГиБ 3B Q4_1 с диска —
это 10–20 с искажения TTFT). Ollama держит модель в памяти и показывает `size_vram`;
у нас в панели «загружена» появляется только после ответа, а кнопок нет.

Из-за этого сравнение скорости с ollama нечестное: наш TTFT включает загрузку.

## Требования

1. **Кнопки «Загрузить» / «Выгрузить»** у каждой ВТМ-модели (в панели под чатом и/или
   в шапке колонки).
2. **Статус:** «в памяти» / «не загружена», фактический объём (дельта RSS процесса
   `chat_server` после загрузки), время загрузки, сколько запросов обслужено.
3. **TTFT без загрузки:** при загруженной модели TTFT считается только по генерации;
   первый запрос после загрузки помечается отдельно (`cold`/`warm`).
4. **Автовыгрузка по бездействию** (по умолчанию выключена; `--keep-alive N` секунд,
   0 — держать всегда) — как у ollama, но по нашему решению.
5. API: `POST /api/load`, `POST /api/unload`, поля `loaded`, `rss_bytes`, `load_ms`
   в `/api/models`; неизвестная модель — 400.
6. Ничего не ломать: если модель не загружена, запрос её загружает (текущее поведение).

## Критерии приёмки

- [x] кнопка грузит модель: статус «в памяти», RSS-дельта > 0, время загрузки видно
- [x] выгрузка освобождает память (RSS падает)
- [x] TTFT при загруженной модели заметно меньше, чем при первом запросе (числа)
- [x] `--keep-alive` работает, по умолчанию выключен
- [x] тесты на моках, полный набор зелёный

## Отчёт исполнителя

Сделано: `POST /api/load` и `POST /api/unload`, кнопки «Загрузить»/«Выгрузить» в шапке
каждой ВТМ-колонки, статус в карточке: `loaded`, `rss_bytes` (реальная дельта RSS
процесса `chat_server`), `load_ms`, `requests`, `unload{freed, unload_ms}`. Ollama —
400 `load_unsupported` (её памятью управляет её процесс), выгрузка занятой модели — 409.

**Главное открытие:** `VtmBackend.open()` только mmap-ит файл и читает заголовки —
веса приходят в память на первом forward. Поэтому «Загрузить» = factory + open() +
прогрев одним токеном через все слои (`warmed=true`); без прогрева первый запрос всё
равно платил page-in.

**Числа (3B Q4_1, 2,24 ГиБ, 16 ГиБ, машина под нагрузкой):**
| сценарий | TTFT | из них загрузка |
|---|---|---|
| первый запрос без предзагрузки | 21,67 с | 9,29 с |
| «Загрузить» (кнопка) | load_ms 5,79 с, RSS +2,33 ГБ | — |
| запрос 1 при загруженной | 14,60 с (prefill 92 ток) | нет |
| **запрос 2, тот же вопрос** | **1,08 с** (кэш префикса, 13,5×) | нет |
| «Выгрузить» | 32,7 мс, freed 1,89 ГиБ | — |

`--keep-alive N`: по умолчанию выключен (None), 0 — держать всегда, N>0 — выгрузка по
простою (сторож не трогает занятую модель). TTFT в SSE разделён: `load_ms` (загрузка
этого запроса) и `ttft_gen_ms` (чистая генерация).

64 теста chat_server (было 48), полный набор 2336 OK. Оговорки: замеры шумные
(соседний агент держал 10 ядер), «в памяти» = резидентные страницы mmap (ОС может
вытеснить), macOS удерживает часть освобождённых страниц.
