# Волна 1: целостность контейнера (sha256)

## Проблема

Манифест содержит sha256 файлов, но загрузчик его не сверяет: изменённый байт в
данных даст молча мусорные логиты. Обрезанный файл ловится, испорченный — нет.

## Требования

- Писатель (`vtm_ref.write_vtm`): кладёт sha256 секции данных в заголовок/meta.
- Загрузчик: сверяет хеш при загрузке; при несовпадении — VTM_E_INTEGRITY с текстом,
  без падения. Флаг `VTM_SKIP_HASH=1` для отладки (с предупреждением).
- `qat/export.py`: пишет sha256 в manifest (уже пишет для файлов) и в мету контейнера.
- Тест: подменить один байт в data-секции → загрузка отвергается; подменить в meta →
  тоже; нормальный файл грузится.
- Стоимость: замерить время хеширования 1,3 ГБ (sha256 ~1-2 ГБ/с) и решить, делать
  ли это всегда или по флагу `--verify`.

## Критерии приёмки

[ ] испорченный байт данных → внятная ошибка, exit 1
[ ] нормальный контейнер грузится, хеш совпадает
[ ] время проверки для 1,3 ГБ замерено (число в отчёте)
[ ] `make test`, `discover -s tests` зелёные

## Контекст и ограничения

- Зона: src/vtm/loader.c, tools/vtm_ref.py, qat/export.py, tests/test_container_hash.py
- Другие файлы НЕ трогать: параллельно работают семь других агентов по строго
  разным файлам. Пересечение зон запрещено.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- Не менять поведение без новых флагов.
- Не коммитить: сдавать правки и отчёт.
