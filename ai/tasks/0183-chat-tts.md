# Чат говорит вслух

## Что уже есть
`eva/tts.py` — адаптер синтеза: Piper (если установлен) → системный `say` (macOS)
→ `espeak` (Linux) → пустой движок. Контракт `synthesize(text) -> bytes | Path`.
Проверено: `say -o out.wav --data-format=LEI16@22050 "…"` даёт корректный RIFF/WAVE,
который браузер проигрывает без конвертации.

## Требования
1. **Серверный endpoint** `POST /api/tts` `{text, voice?}` → `audio/wav`
   (Content-Type `audio/wav`, `Cache-Control: no-store`). Текст чистится: без
   markdown-разметки, без `<think>…</think>`, без URL и лишних пробелов; лимит
   длины (например 600 символов) → 400 с понятным текстом.
2. **Клиент**: галочка «озвучивать» у колонки; ответ **разбивается на фразы**
   по `. ! ? …` и переводам строк, каждая фраза синтезируется сразу по мере
   прихода текста и ставится в очередь воспроизведения (первая — как пришла,
   не ждём конца ответа).
3. **Управление**: «стоп» останавливает и речь, и генерацию; новый вопрос
   очищает очередь; конец ответа — доигрывает остаток.
4. **Деградация**: если TTS недоступен (нет `say`/`piper`), галочка показывает
   «голос недоступен» и чат работает как раньше.
5. Не ломать стриминг: текст печатается независимо от аудио.

## Критерии приёмки
- [x] `/api/tts` возвращает WAV (проверить RIFF-заголовок) и чистит разметку
- [x] галочка озвучивает ответ по фразам, первая фраза — без ожидания конца
- [x] стоп/новый вопрос корректно глушат звук
- [x] без TTS — понятное сообщение, чат работает
- [x] тесты на моках, полный набор зелёный, JS `node --check`

## Отчёт исполнителя

Сделано (зона: `tools/chat_server.py`, `tests/test_chat_server.py`,
`docs/hybrid.md`; `eva/*`, `src/vtm/*`, `tools/chat.py` не тронуты):

1. **`POST /api/tts`** в `tools/chat_server.py`: `{text, voice?}` → `audio/wav`
   (`Content-Type: audio/wav`, `Cache-Control: no-store`). `clean_tts_text()`
   убирает `<think>…</think>` (и незакрытый), markdown-ссылки/`*`/`#`/backtick/
   `~`, URL, схлопывает пробелы; лимит 600 символов после чистки → 400
   `text_too_long`, пусто после чистки → 400 `empty_text`. Синтез — ленивый
   импорт `eva/tts.py` через `default_tts_speech` (Piper → say/espeak → null);
   пустые байты/не-WAV/исключение адаптера → 503 `voice_unavailable` с текстом
   «голос недоступен». `ChatHTTPServer`/`create_server` принимают `tts=`
   (тесты подставляют заглушку), боевой путь — `eva/tts.py`.
2. **Клиент**: галочка «озвучивать» в шапке каждой колонки + плашка
   `tts-note`; кнопка «Стоп». Ответ режется на фразы по `. ! ? …` (с пробелом
   после или в конце пришедшего куска) и переводам строк, длинные фразы —
   по словам до 600. Первая фраза сразу уходит в `POST /api/tts`, синтез
   остальных идёт параллельно, играют последовательно через **один**
   `new Audio()` (очередь промисов). Конец ответа сбрасывает буфер фраз в
   очередь и доигрывает остаток. «Стоп» и новый вопрос: `AbortController` +
   очистка очереди, `URL.revokeObjectURL`, рост поколения (запоздавшие ответы
   синтеза отбрасываются). Ошибка синтеза → «голос недоступен» у колонки,
   чат/стрим не затронуты; 400 по фразе (например, строка только из URL)
   пропускается без выключения голоса.
3. **Тесты** (`tests/test_chat_server.py`, +17): WAV/заголовки/no-store, чистка
   think/markdown/URL, незакрытый think, лимит 600, пустой текст, битые
   payload/voice, 503 при исключении/null/не-WAV, чат при этом стримится;
   страница — галочки, один `Audio`, наличие `/api/tts`, node-тесты сплиттера
   (первая фраза до конца потока, переводы строк, нарезка длинной фразы).
4. **docs/hybrid.md** — раздел «Озвучка ответов (задача 0183)»: контракт,
   таблица чистки, очередь/стоп, деградация, команды проверки.
