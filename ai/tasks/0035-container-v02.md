# Контейнер v0.2

## Проблема

Задача 0028 нашла блокер: `dims` в записи тензора — u16 (макс 65 535), а словарь
Qwen — 151 936. Таблицу эмбеддингов и lm_head физически некуда положить, поэтому
настоящая модель в `.vtm` не поедет. Решение — ADR 0011.

## Требования

- Версия формата 2: `dims` — u32×4, запись тензора 52 байта.
- `tools/vtm_ref.py`: writer и reader на v0.2; v0.1 отвергается с понятной ошибкой.
- `src/vtm/loader.c` + `vtm.h` (+ `vtm_internal.h`): чтение v0.2, отказ на v0.1.
- `docs/vtm.md`: обновить раскладку и версию.
- Тесты: запись/чтение тензора с размерностью 151 936; отказ на v0.1; круг
  write→read для обычной модели.

## Критерии приёмки

- [ ] `python3 -m unittest discover -s tests` зелёный
- [ ] `cd src/vtm && make test` зелёный
- [ ] тензор с dims 151936 пишется, читается и проверяется по длине
- [ ] файл v0.1 отвергается с сообщением «формат v0.1 не поддерживается»
- [ ] C и Python сходятся на пересобранной синтетике (max|Δ| ≤ 1e-6)

## Контекст и ограничения

- Зона: `tools/vtm_ref.py`, `src/vtm/loader.c`, `src/vtm/vtm.h`,
  `src/vtm/vtm_internal.h`, `docs/vtm.md` (раскладка), `tests/test_vtm_ref.py`.
- Параллельно работает агент 0029 в `tools/vtm_compile.py` — его не трогать;
  он использует `vtm_ref.write_vtm`, поэтому смена формата подхватится сама.
- Не менять заголовок (32 байта) и расположение секций.
