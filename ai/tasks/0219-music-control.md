# Музыка голосом, как у Алисы

## Задача
«Включи музыку», «включи группу Кино», «следующая», «пауза», «громче»,
«выключи музыку» → Ева управляет воспроизведением на Mac и отвечает коротко.

## Что уже есть
Способность **`answer`** в плагинах (0218): `plugins/<id>/plugin.py` объявляет
`capability: ["answer"]` и `answer(ctx, question) -> str | None`; сервер зовёт
до модели и, если есть текст, не генерирует.

## Требования
1. **Плагин** `plugins/music/` с `capability: ["answer"]` (и `permissions`:
   `filesystem` — только музыкальные каталоги, если нужны; сеть — только если
   радио).
2. **Управление Music.app на macOS** через `osascript` (без сторонних API):
   - play/pause/next/previous, громкость ±10, mute;
   - поиск и запуск: `tell application "Music" to play (first track whose name contains "Кино")` —
     аккуратно: сначала плейлист/исполнитель, потом трек; при отсутствии —
     честное «не нашла в библиотеке»;
   - сейчас играет → «Играет: <исполнитель> — <название>».
3. **Интернет-радио** (если время): публичные потоки (например Radio Record,
   Европа Плюс) через `afplay`/`AVPlayer` — только прямые URL, без ключей.
   Отметить в docs, какие станции зашиты.
4. **Распознавание**: «включи музыку», «включи что-нибудь», «включи Кино»,
   «поставь джаз», «пауза», «продолжи», «следующая», «предыдущая», «громче»,
   «тише», «выключи музыку», «что играет» — 20+ фраз, с отказом на
   «включи свет» (не наша зона → None).
5. **Короткий ответ** (1 предложение) + `speak` через TTS.
6. Тесты `tests/test_music_control.py`: распознавание фраз, маппинг в
   AppleScript (мок subprocess), отказы, «не нашла трек», отсутствие Music.app.
7. Живая проверка на этой машине: `osascript` доступен; проверить, что
   команда реально управляет (или честно отчитаться, что Music.app закрыт).

## Критерии приёмки
- [ ] 20+ фраз распознаются, чужие — нет
- [ ] AppleScript-команды корректны (мок-тесты), без инъекций (экранирование)
- [ ] «включи Кино» ищет в библиотеке, при отсутствии — честный ответ
- [ ] «пауза/громче/тише/выключи» работают
- [ ] тесты и полный набор зелёные

## Отчёт исполнителя

**Статус: готово** (код, тесты, docs). Живое управление Music.app на этой
машине проверить нельзя: macOS не выдала разрешение автоматизации (см. ниже);
плагин при этом отвечает честным текстом, а не падает и не вешает чат.

### Что сделано

- `plugins/music/plugin.json` — `id: music`, `capabilities: ["answer"]`,
  `priority: 30`, `permissions.network` — только хосты радио, `filesystem: []`.
- `plugins/music/plugin.py` — `answer(ctx, question) -> str | None`:
  - `play` / `pause` / `next track` / `previous track` / `stop`;
  - громкость `sound volume` ±10, clamp 0…100; mute = 0, unmute = 50;
  - поиск: плейлист по имени → трек по имени → трек по исполнителю
    (`whose name contains` / `artist contains`), затем `play`;
  - «что играет» → `Играет: <исполнитель> — <название>`;
  - всё через `/usr/bin/osascript` списком аргументов, **без** `shell=True`;
    запрос — один AppleScript-литерал с экранированием `\` и `"`;
  - `subprocess.run(timeout=5)`; отказ TCC (`-1743`, `-10004`, «нарушение
    прав»), таймаут, `-1728` и отсутствие `osascript` различаются по тексту;
  - радио: `/usr/bin/afplay <url>` (тоже без shell), «пауза» → `SIGSTOP`,
    «продолжи» → `SIGCONT`, «выключи» → terminate; при мгновенном падении
    afplay ответ «Не получилось включить радио», а не «играет».
- `tests/test_music_control.py` — 35 тестов: 40 фраз, чужие фразы, маппинг в
  AppleScript, ±10, экранирование и отсутствие shell, «не нашла», «что
  играет» (playing/paused/stopped), TCC/таймаут/FileNotFound, радио,
  манифест и проводка `PluginRegistry.answers()`.
- `docs/plugins.md` — способность `answer` в таблице и раздел «Музыка:
  плагин music» (фразы, AppleScript, радио, TCC).
- `config/plugins.json` — `music` добавлен в `enabled` (рядом с
  `fairy-tales`); это вне формальной зоны, но иначе плагин не активен.
- `tests/test_plugins.py` — в ожидаемый набор bundled-плагинов добавлен
  `music` (иначе падал общий тест; тоже вне формальной зоны).

### Фразы

Включение: «включи музыку», «включи что-нибудь», «поставь/вруби/запусти
музыку/плеер». Поиск: «включи Кино», «поставь группу Кино», «включи песню
Кино», «хочу послушать Кино», «включи джаз». Управление: «пауза», «поставь на
паузу», «приостанови», «продолжи», «продолжи музыку», «играй дальше»,
«следующая/следующий трек/дальше», «предыдущая/предыдущий трек/назад»,
«выключи музыку», «останови музыку», «стоп». Звук: «громче», «сделай громче»,
«прибавь звук», «увеличь громкость», «тише», «убавь звук», «заглуши»,
«включи звук». Состояние: «что играет», «что сейчас играет», «какая песня
играет», «что за музыка». Радио: «включи радио», «включи радио дфм», «включи
европу плюс», «включи наше радио». Не наша зона → `None`: «включи свет»,
«выключи свет», «включи телевизор», «выключи плиту», «поставь будильник»,
«который час», «расскажи сказку», «как дела», «что такое джаз».

### Живая проверка (macOS 26.2)

```
osascript -e 'tell application "Music" to player state'
→ rc=1, stderr: ... "Произошло нарушение прав. (-10004)"
```
Music.app запущен (`pgrep -x Music`), но TCC-разрешение «управлять Music» не
выдано (ранее запрос висел >60 с, сейчас сразу отказ). Плагин на реальном
`PluginContext`:

```
'что играет'   -> 'macOS не разрешила управлять Music.app — включите автоматизацию в настройках.' (0.22 с)
'пауза'        -> тот же честный текст (0.18 с)
'включи свет'  -> None (0.00 с, osascript не зовётся)
```

`PluginRegistry` с временным `enabled=["music"]`: `answers() -> ['music']`,
`run_answer("включи свет") -> None`, `run_answer("что играет") -> честный
отказ`; исключений и `last_error` нет.

Радио: прямые URL отвечают (`Европа Плюс` — 200 `audio/mpeg`, `DFM` — 200
`audio/aac`, `Наше Радио` — 200 `audio/mpeg`). В этой среде `afplay` не
открывает сетевой поток (`AudioFileOpen failed ('wht?')`), хотя скачанный
локально тот же поток играет (`rc=0`), — похоже на сетевую изоляцию
sandbox/headless. Плагин это ловит через 0.3 с и отвечает «Не получилось
включить радио: поток не открылся»; afplay-процесс не остаётся.

### Проверки

```
python3 -m unittest tests.test_music_control -q   # 35 OK
python3 -m unittest discover -s tests -q          # 2876 OK, 73 skip
```

### Риски

1. **TCC.** Без ручного подтверждения «терминал/сервер хочет управлять
   Music» управление Music.app невозможно; плагин деградирует честно, но
   музыка не заиграет. Нужно один раз подтвердить диалог в GUI-сессии.
2. **afplay и сеть.** В headless/sandbox этой машины `afplay` не открывает
   HTTP-потоки; радио заработает только там, где afplay имеет сеть. URL
   проверены curl'ом, но слышимого радио здесь нет.
3. **Radio Record.** Старый `rr96.aacp` отдаёт 404, новый HLS `m3u8`
   afplay не открывает — станция не включена; в списке Европа Плюс, DFM,
   Наше Радио.
4. **Поиск.** `whose contains` на большой библиотеке может быть медленным;
   при нескольких совпадениях играет первый — не обязательно «лучший».
5. **Вне зоны.** Пришлось тронуть `config/plugins.json` и
   `tests/test_plugins.py` (включение и bundled-набор); при конфликте с
   параллельной 0218 их надо объединить, а не откатывать.
