# eva ↔ ВТМ: локальный бэкенд через C-ABI

## Проблема

Гибрид умеет «маленькая модель» только как HTTP-клиент. Своя ВТМ уже имеет C-ABI
(0067) с колбэком стриминга и отменой, но из Python её никто не зовёт. Без этого
«своя модель» в архитектуре — только на бумаге.

## Требования

- `eva/backends/vtm_backend.py`: ctypes-обвязка над libvtm.a/libvtm.so
  (`vtm_api_open/generate/cancel/close/last_error`), поток колбэка → генератор
  строк/чанков, отмена из другого потока Python.
- Токенизация: вызвать `src/vtm/vtm` не как процесс, а через `tokenizer.json` —
  если проще, используй существующий `eva`-путь токенизации (посмотри, что есть).
- Конфиг: `EVA_VTM_MODEL=path`, `EVA_VTM_BACKEND=auto`, `EVA_VTM_THREADS`.
- Тесты без GPU: на `demo/model.vtm` — генерация, стриминг по одному токену, отмена,
  повторный запрос, ошибка при отсутствии файла. Если библиотеки нет — skip с внятным
  сообщением.
- Никакого запуска демона: только in-process через ctypes.

## Критерии приёмки

[ ] генерация через ctypes на demo/model.vtm даёт токены (тест)
[ ] стриминг: чанки приходят по одному, склейка == полный ответ
[ ] отмена из другого потока прекращает генерацию (тест)
[ ] `python3 -m unittest discover -s tests` зелёный

## Контекст и ограничения

- Зона: eva/backends/ (новый пакет), eva/backends/vtm_backend.py, tests/test_eva_vtm_backend.py
- Другие файлы НЕ трогать: параллельно работают пять других агентов по своим модулям.
- **Запрещено:** запускать сервер/демон, качать модели, pip install, сеть (кроме уже
  установленных пакетов), git-коммиты.
- **Отчёт пиши первым блоком в ответе**, потом детали: агенты этой сессии падают на
  финальном шаге, отчёт первым спасает работу.
- Проверка: `python3 -m unittest discover -s tests` (сейчас 1071 тест, должно быть
  зелёным и не меньше).

## Отчёт исполнителя

Сделано: пакет `eva/backends/` — ctypes-обвязка над C-ABI ВТМ
(`vtm_api_open/generate/cancel/close/last_error`), автосборка `.dylib` из `libvtm.a` в
кэш, чистый Python-BPE из `tokenizer.json` (без запуска процесса `vtm`), стриминг через
поток-воркер и очередь, отмена из любого потока, `chat()/stream_chat()` в форме
`eva.clients`. 35 тестов.

Проверено исполнителем: генерация на `demo/model.vtm` даёт 3 токена, повтор
детерминирован; `stream_text` склеивается в `decode(ids)`; частичный UTF-8 (`0xD0`)
не рвётся; отмена из другого потока → `VtmCancelled`, контекст после отмены работает;
без библиотеки тесты уходят в skip с внятным текстом.

Риски: автосборка `.so` на Linux из не-PIC объектов может не слинковаться (лечится
`EVA_VTM_LIB`); `EVA_VTM_MAX_TOKENS=64` может превысить контекст демо-модели;
`chat()` использует переносимый шаблон, а не чат-шаблон модели; один контекст = одна
генерация (`VtmBusy`). В `eva/router` бэкенд не подключён — передаётся как
`deps["small"]`.
