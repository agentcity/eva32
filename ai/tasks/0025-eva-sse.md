# SSE-стриминг в сервере

Контракт — `docs/hybrid.md`, решение — `docs/adr/0009-hybrid-router.md`.

## Проблема

Сейчас `stream=true` возвращает 400. В чате это значит: пользователь ждёт весь ответ и
только потом видит текст, хотя локальная модель отдаёт первые токены за 50–200 мс.

## Требования

- `POST /v1/chat/completions` с `stream=true` → `text/event-stream`, чанки в формате OpenAI:
  `data: {...}\n\n`, финальный `data: [DONE]`.
- Каждый чанк: `choices[0].delta.content`, `finish_reason` в последнем.
- Работает с инжектированным роутером: если роутер умеет отдавать по частям — стримим,
  если нет — отдаём ответ одним чанком (честно, без имитации).
- Заголовки `Cache-Control: no-cache`, `Connection: keep-alive`; ошибки до первого чанка — обычный JSON.

## Критерии приёмки

[ ] `python3 -m unittest tests.test_server -v` зелёный
[ ] `curl -N` получает чанки и `[DONE]`
[ ] роутер без стриминга отдаёт один чанк (не падает)
[ ] не-стриминговый запрос работает как раньше

## Контекст и ограничения

- Зона: eva/server.py, tests/test_server.py (только добавление тестов стрима)
- Другие файлы не трогать: параллельно работают другие агенты.
- Только stdlib, без сети в тестах, без установки пакетов.
- Не коммитить: сдавать правки и отчёт.
