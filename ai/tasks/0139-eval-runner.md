# Прогон golden через бэкенд: уровень ума числом

## Проблема

`tools/eval_competence.py` умеет оценивать ответы, но нет раннера, который
получает эти ответы от выбранного бэкенда (ollama/vtm) и печатает проценты по
категориям.

## Требования

- `tools/eval_competence_run.py`: `--backend ollama|vtm|openai`, `--model`,
  `--golden eval/golden_competence.jsonl`, `--out runs/eval/<id>.jsonl`.
- Сохранять ответы (для ручного просмотра) и печатать таблицу по категориям +
  список провалов с причинами.
- Ограничение по времени/токенам, ретраи, параллельность.
- Отчёт в `docs/golden.md`: как мерить новую модель.

## Критерии приёмки

[ ] `--backend ollama --model qwen2.5:7b` печатает проценты по 9 категориям
[ ] ответы сохранены в runs/eval
[ ] провалы перечислены с причиной

## Контекст и ограничения

- Зона определяется названием задачи и файлами, которые в ней упомянуты.
- Параллельно работают пять других агентов — чужие файлы не трогать.
- **Запрещено:** pip, сеть (кроме ollama на localhost), git-коммиты, запуск
  сервера на внешнем интерфейсе, скачивание моделей HF без явного флага.
- **Отчёт пиши первым блоком ответа** — агенты этой сессии падают на финальном шаге.
- Проверка: `python3 -m unittest discover -s tests`; где нужно — `cd src/vtm && make test`.

## Отчёт исполнителя

Сделано: `tools/eval_competence_run.py` — прогон 72 строк golden через бэкенд.
`--backend ollama|vtm|openai|mock`, `--model`, `--golden`, `--out`, `--workers`,
`--max-tokens`, `--timeout`, `--retries`, `--temperature`. Сохраняет ответы в
`runs/eval/<бэкенд>-<модель>-<время>.jsonl` (файл совместим с
`tools/eval_competence.py --answers`), печатает таблицу по 9 категориям и все
провалы с причинами; ретраи только на таймаут/429/5xx; preflight даёт код 2 без
трейсбека, если бэкенда нет.

**Живые числа qwen2.5:3b (Ollama, все 72 строки, 0 ошибок):** 60/72 = 83,3% —
reasoning 8/8, clarify 6/8, marketing 8/8, writing 2/8, client 7/8, language 7/8,
behavior 8/8, limits 6/8, client_questions 8/8.

**Важно:** минимум 3 из 12 провалов — артефакты чекера, а не модели. После
исправления чекера (0140: императивы «уточни/сообщите», сравнение по основе слова,
синонимы профессий) та же модель даёт **65/72 = 90,3%**. Остаток — реальные
провалы writing (лимиты длины 140 слов и «не задан вопрос»).

19 тестов; независимая перепроверка нетронутым оценщиком совпала.
