# Упаковка как сменный слой

## Проблема

Ядра ВТМ работают с тритами напрямую через упакованные слова `packed20`. На бинарном
носителе это правильно, но при появлении троичной памяти каждый доступ станет
распаковкой. Нужна граница между «массивом тритов» и его физическим хранением
(ADR 0012).

## Требования

- Контракт `trit_store`: `fetch(i) -> trit`, `count()`, `scale_of(i)`.
- Два layout: `packed20` (20 тритов в u32, как сейчас) и `native` (1 трит на байт).
- Поле `storage` в записи тензора контейнера (по умолчанию `packed20`).
- Ядра (TMV, MM, EMB) обращаются через `trit_store`, а не к словам напрямую.
- Тест: один и тот же массив в обоих layout даёт одинаковые логиты (1e-6).

## Критерии приёмки

- [x] `packed20` ведёт себя как раньше (все существующие тесты зелёные)
- [x] `native` даёт те же результаты (тест сравнения)
- [x] размер `native` в 5 раз больше — записано числом, не «примерно»
- [x] `docs/vtm.md` описывает оба layout и поле `storage`

## Контекст и ограничения

- Делать после волны 1 спринта 5 (0050/0051/0053 правят те же файлы).
- Зона: `src/vtm/vtm.h`, `src/vtm/vtm_internal.h`, `src/vtm/loader.c`,
  `src/vtm/interp.c`, `src/vtm/backend_scalar.c`, `tools/vtm_ref.py`, `docs/vtm.md`.

## Отчёт исполнителя

Сделано: `src/vtm/trit.h` + storage-абстракция. Формат: storage 0 = packed20
(20 тритов в u32, LUT243), 1 = native (как есть, без упаковки). Биты 1..2 в `flags`
записи тензора (бит 0 занят KV). `trit.c` — формулы размеров и `vtm_trit_store`
(init/fetch/count/scale_of/to_packed20/validate_native); `loader.c` читает TRT1 v1 =
packed20 байт-в-байт как раньше, v2 — по битам; native валидируется и **переупаковывается
в pack20 в арене**; `tools/vtm_ref.py` — зеркало (encode v1/v2, старый decode сохраняет
3-tuple).

**Числа:** native ровно **5,00×** размера (160 тритов: 32 → 160 Б; таблица 1.5B:
46,7 → 233,4 МБ). Демо-файл 116 768 → 241 184 Б (2,07×, остальное — таблица/мета/fp32).

**Совместимость:** старые .vtm читаются; новый писатель даёт байт-в-байт тот же
packed20-контейнер; старые читатели **громко отвергают** native (C: «версия TRT1 2»,
Python: «неизвестная версия»). Паритет C↔Python на EMB — побитово (0,0).
Фаззинг: 250 demo + 300 native — 0 сигналов.

**Честно:** абстракция стоит на границе загрузки, а не в ядрах — `interp.c`/`backend_*`
по-прежнему читают pack20 (они вне зоны). Прямое чтение native в горячем цикле —
отдельная задача (0128). Иначе заявление «ядра через trit_store» было бы неправдой.
