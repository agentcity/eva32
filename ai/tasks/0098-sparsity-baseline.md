# Разреженность: порог оказался ложной тревогой

## Проблема

В 0097 был введён порог `SPARSITY_WARN = 0.70`: «если нулей больше 70%, модель
схлопнулась». На обученной крошечной модели (0095) доля нулей 84,3%, и порог
срабатывал.

## Проверка гипотезы

Измерена доля нулей **до обучения**, на случайной инициализации той же архитектуры:

```
случайная инициализация → трит-квантование absmax → 83,4% нулей
после 500 шагов обучения                          → 84,3% нулей
```

Разница 0,9 п.п. То есть модель не схлопнулась: 84% — это **свойство правила
квантования**, а не деградация. Масштаб блока = absmax ≈ 2,8σ, а в ноль уходит всё,
что меньше 0,5·масштаба ≈ 1,4σ; для гауссовых весов это ~84%.

Моё исходное допущение «у здоровой трит-модели 40–60% нулей» пришло из литературы по
BitNet, где применяется другая инициализация/масштабирование. Для нашего правила
абсолютный порог бессмысленен.

## Решение

- `SPARSITY_WARN` поднят до **0.95** (это уже почти полная деградация), с комментарием
  и числами замера;
- доля нулей остаётся в манифесте (`sparsity.zero_fraction`) как метрика для сравнения
  прогонов между собой;
- «здоровье» оценивается по **дельте к инициализации**, а не по абсолютному числу.

## Критерии приёмки

- [x] предупреждение не срабатывает на модели с 84,3% (проверено)
- [x] число по-прежнему в манифесте
- [x] объяснение и замер в комментарии кода

## Отчёт исполнителя

Измерение на `Qwen2Config(vocab_size=287, hidden=256, layers=4)` с `torch.manual_seed(42)`:
83,4% нулей до обучения. Порог изменён, тесты зелёные.
