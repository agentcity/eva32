# Сессии KV: снимок и восстановление по ADR 0008

## Проблема

Сейчас диалог не переживает перезапуск процесса: KV живёт только в памяти. Для
сервера нужны сессии — сохранить состояние разговора и продолжить позже.

## Требования

- `vtm_api_session_save(ctx, path)` / `vtm_api_session_load(ctx, path)`.
- Формат: заголовок (магия, версия, ctx, dims), кадры K/V по слоям, trailer с
  sha256. Запись — temp + fsync + rename (ADR 0008, правило 1).
- Чтение: обрезка оборванного хвоста (правило 2) — недописанная сессия не ломает
  загрузку, восстанавливается до последнего целого кадра.
- Лимит: `max_sessions_bytes` с LRU-вытеснением (правило 3) — опционально, хотя бы
  API-заглушка с честным «не реализовано».
- Тест: сохранить после 3 токенов, загрузить в новую машину, продолжить — ответ
  совпадает с непрерывным прогоном.

## Критерии приёмки

[ ] save/load: продолжение после загрузки совпадает с непрерывным прогоном (тест)
[ ] оборванный файл сессии восстанавливается до последнего целого кадра (тест)
[ ] запись атомарная (temp+fsync+rename) — видно в коде и в тесте на обрыв
[ ] make test и полный Python-набор зелёные

## Контекст и ограничения

- Зона: src/vtm/api.c, src/vtm/api.h, новый src/vtm/kv_store.c, src/vtm/Makefile, tests/test_vtm_session.c
- Другие файлы НЕ трогать: параллельно работают три других агента по строго разным файлам.
- Сборка: `cd src/vtm && make test`; `-Wall -Wextra -Werror`.
- По умолчанию теперь `VTM_BACKEND=auto` (SIMD, если доступен).
- **Отчёт пиши первым блоком в ответе**, потом код: агенты этой сессии падают в конце.
- Не коммитить: сдавать правки и отчёт.
