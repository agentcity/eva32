# Сказка с картинками в приложении

## Что уже есть
Сервер отдаёт SSE-событие `{"type":"image","side":N,"url":"/media/fairy-tales/<slug>/NN.jpg","alt":"…"}`
между текстовыми `delta` (0221), файлы лежат в `plugins/fairy-tales/images/`,
`GET /media/...` отдаёт JPEG с `Cache-Control`.

## Требования
1. **Разбор SSE** в `apps/eva/Sources/ChatClient.swift`: новое событие `image`
   (url, alt) → колбэк/делегат в `AnswerController`.
2. **Показ**: картинка появляется в окне ответа (в большом окне и в компактном
   круге — хотя бы в большом), по ходу текста, с плавным появлением; при
   следующей картинке — смена (кроссфейд); по концу ответа — остаётся последняя.
3. **Загрузка**: `URLSession` с base URL сервера, кэш в памяти (NSCache по url),
   повтор при ошибке один раз, без блокировки UI.
4. **Голос и картинка не мешают друг другу**: показ не должен считаться
   «озвучкой» (круг speaking/idle не дёргается от картинок).
5. **Настройка** «Показывать картинки сказок» (по умолчанию включено), в
   настройках рядом с озвучкой.
6. **Тесты**: парсер SSE image-событий (юнит в `apps/eva/Sources/SelfTest.swift`
   или отдельный `--selftest-images`), проверка игнора при выключенной настройке,
   отсутствие падений на битом URL.
7. `tools/build_eva_app.sh` собирает; `--selftest-chat "расскажи сказку про
   колобка"` печатает число image-событий (4) — проверка контракта.

## Критерии приёмки
- [ ] картинки видны в приложении при чтении сказки
- [ ] при выключенной настройке — только текст
- [ ] ошибка загрузки не ломает ответ
- [ ] сборка и самотест зелёные
- [ ] `docs/voice-app.md` обновлён

## Отчёт исполнителя

**Что видно в приложении.** Ответ сказки печатается как раньше, а справа от
текста появляется колонка с иллюстрацией (190 pt): первая картинка плавно
проявляется за 0,35 с, следующая сменяет её кроссфейдом, последняя остаётся на
экране до нового вопроса (новый вопрос очищает колонку, текст снова занимает
всю ширину). Порядок показа — порядок SSE-событий, даже когда файлы качаются
вразнобой: события нумеруются, а на экран попадают строго по очереди. Колонка
собрана вручную (`NSView` + констрейнты), потому что `NSStackView` вынимает
hidden-виды из иерархии и констрейнт «высота картинки = высота текста» падал с
«no common ancestor» — проверено и исправлено. В компактном режиме на круге
ничего не рисуется (окно ответа скрыто), картинки ждут в нём и видны после
разворота; падений нет. Показ картинок не трогает `speaking`/`idle`: круг
меняется только от микрофона и озвучки.

**Загрузка.** `URLSession` в фоне от базового адреса сервера
(`URL(string:relativeTo:)`, только http/https), кэш в памяти `NSCache` по URL
(до 32 картинок / 64 МБ), один повтор через 0,3 с при ошибке, проверка
JPEG/PNG/GIF по заголовку. Ошибка загрузки — просто нет картинки: текст, статус
и озвучка продолжаются (`картинка: не загрузилась …`). UI не блокируется:
загрузка и декодирование идут вне главного актора, на главный возвращается
только готовый `NSImage`.

**Настройка.** «Показывать картинки сказок» (`eva.showTaleImages`, по умолчанию
`true`) — в окне настроек сразу под «Озвучивать ответы голосом», применяется
без перезапуска: снятая галочка убирает уже показанную картинку и игнорирует
следующие `image`-события (в журнале `картинка: пропущена — настройка …`).

**Silent (0223).** `ChatClient` разбирает `"silent": true` из `delta` и `done`
и отдаёт отдельным событием `.silent(true)` **раньше** текста, чтобы озвучка не
успела начаться. `AnswerController` ставит флаг и проверяет
`shouldSpeak(voiceOn:silent:)`: ни `delta`, ни `flush` не уходят в `/api/tts`;
на `finished` очередь всё равно закрывается (`endStream`), поэтому follow-up
открывается сразу, а `AppDelegate` не держит круг в «думаю» (`awaitingAudio`
снимается по `isSilentAnswer`). Текст показывается как обычно. В журнале:

```
озвучка: пропущена (silent) — ответ уже озвучен записью на сервере
озвучка: пропущена (silent) — в /api/tts не отправлено ни одной фразы
sse finished: … картинок 0, озвучка пропущена (silent)
```

**Самотесты.**

* `--selftest-images` (новый, без сети/TCC): разбор `image` (side 0/1, без url,
  пустой url, битый JSON, `[DONE]`), `silent` из `delta`/`done` и его порядок,
  правило `shouldSpeak`, сборка URL от адреса сервера (относительный,
  абсолютный, без base, `file://`, `javascript:`, `http://` без хоста),
  кэш и заголовки картинок, недоступный URL (2 попытки, `nil` за 0,33 с),
  вид `TaleImageView` (показ/смена/очистка) и окно ответа (картинка видна,
  колонка 190 pt; `beginAnswer` убирает её). Все проверки зелёные.
* `--selftest-chat "расскажи сказку про колобка"` → `image-событий: 4`
  (файлы 01–04, alt из плагина).
* `--selftest-chat "включи запись сказки"` → две строки
  `silent: ответ озвучен записью`, `озвучка: пропущена (silent)`.
* Регрессии: `--selftest-text`, `--selftest-stop`, `--selftest-followup`,
  `--selftest-wake`, `--selftest-compact` — все зелёные.
* Сборка `bash tools/build_eva_app.sh` — 0 ошибок, 0 предупреждений
  (Swift 6 strict concurrency; `MainActor.assumeIsolated` в `@Sendable`
  completion анимации, `nonisolated`/`Sendable` для загрузки и кэша).
* Живой прогон (`--ask … --no-voice`, слушатели выключены аргументами
  `-eva.wakeWord NO …`, чтобы не поднимать микрофон): 4 иллюстрации скачаны и
  показаны по порядку (№1–№4), в окне справа цветная картинка 190×580;
  при `-eva.showTaleImages NO` — `картинка: пропущена …` и только текст.
  Живой silent-прогон с включённой озвучкой: ни одной строки
  `озвучка: синтез`, круг `thinking → idle`, запись на сервере остановлена
  командой «выключи запись».

**Файлы.** `apps/eva/Sources/ChatClient.swift` (события `image`/`silent`),
`AnswerController.swift` (порядок картинок, silent, загрузка),
`TaleImage.swift` (новый: URL, кэш, загрузчик, вид с кроссфейдом),
`MainWindowController.swift` (колонка картинки), `AppDelegate.swift`
(проводка, круг), `Settings.swift` + `SettingsWindowController.swift`
(галочка), `SelfTest.swift` + `LaunchOptions.swift` (`--selftest-images`,
счётчики), `docs/voice-app.md`. `tools/chat_server.py`, `plugins/*`, `eva/*`,
`src/vtm/*` не тронуты.

**Установка** (песочница не пишет в `~/Applications`; собрано в
`build/EVA.app`). Сначала выйдите из запущенной Евы (статус-бар → «Выход»),
затем:

```bash
rm -rf ~/Applications/EVA.app && cp -R build/EVA.app ~/Applications/EVA.app
open ~/Applications/EVA.app
```

После пересборки macOS может заново спросить микрофон/распознавание: ad-hoc
подпись меняет cdhash (это ожидаемо, см. `docs/voice-app.md`).
