# Загрузка контейнера через mmap: память 2×→1×

## Проблема

Файл читается целиком в буфер, потом копируется в арену: для 1.5B это 2,6 ГБ вместо
1,3. На сервере с несколькими моделями это решающая разница.

## Требования

- mmap файла в режиме read-only; тензоры читаются из отображения без копирования.
- Для тритовых тензоров — работать по указателю на сегмент (распаковка на месте);
  для fp16/bf16 — либо отображение, либо копия в fp32 (замерить, что выгоднее).
- Платформы: macOS и Linux; на Windows — фолбэк на прежний fread с честным сообщением.
- Ошибки: файл изменился, mmap не удался, madvise — всё через VTM_E_*, без падений.
- Замер памяти: RSS до/после на demo и на синтетике 512 МБ.

## Критерии приёмки

[ ] `make test` зелёный, результаты совпадают с прежними
[ ] RSS при загрузке большого контейнера ≤ 1,1× размера файла (числа в отчёте)
[ ] фолбэк работает, если mmap недоступен (тест с флагом)
[ ] `python3 -m unittest discover -s tests` зелёный

## Контекст и ограничения

- Зона: src/vtm/loader.c, src/vtm/vtm_internal.h, tests/vtm/test_vtm.c (новые тесты в конце)
- Другие файлы НЕ трогать: параллельно работают другие агенты (0059 — interp.c,
  0060 — loader.c, 0063 — main.c/tokenizer). Пересечение зон запрещено.
- Сборка: `cd src/vtm && make test`; флаги `-Wall -Wextra -Werror`.
- Не менять поведение без новых флагов.
- Не коммитить: сдавать правки и отчёт.
