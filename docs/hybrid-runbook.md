# Рунбук гибрида: запуск, настройка, метрики

Операционная часть к контракту [docs/hybrid.md](hybrid.md) и решению
[ADR 0009](adr/0009-hybrid-router.md): как поднять гибрид, подключить его из orioncode
и понять, куда ушли деньги.

Не зафиксированное контрактом сверено с кодом на 2026-11-18; что осталось — раздел 9.

## 1. Что запускается

Один процесс, за ним три источника: скиллы (0 ₽, из каталога), малая модель
(локально, дёшево), большая модель (по API, дорого). Наружу — `POST /v1/chat/completions`
и `GET /health`, только stdlib Python, без внешних пакетов.

## 2. Настройка `.env`

Секреты — только в `.env` (он в `.gitignore`), в репозиторий кладётся `.env.example`.
Провайдер большой модели задаётся переменными, не кодом (`docs/hybrid.md`, правило 3).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `EVA_SMALL_BASE` | `http://127.0.0.1:8001/v1` | база OpenAI-совместимого API малой модели |
| `EVA_SMALL_KEY` | пусто | ключ малой модели (локальной — любой) |
| `EVA_SMALL_MODEL` | `eva-small` | имя малой модели |
| `EVA_BIG_BASE` | пусто | база API большой модели — из панели провайдера |
| `EVA_BIG_KEY` | пусто | ключ большой модели |
| `EVA_BIG_MODEL` | пусто | имя большой модели |
| `EVA_MAX_COST_RUB` | `5.0` | бюджет на запрос, ₽ (`none` — без лимита) |
| `EVA_BIG_PRICE_PROMPT` / `_COMPLETION` | `0.4` / `1.2` | ₽ за 1000 токенов — по ним считается цена |
| `EVA_SMALL_TIMEOUT` / `EVA_BIG_TIMEOUT` | `30` / `60` | таймаут вызова, сек |

Значения — из `eva/config.py` (сверено 2026-11-18); там же `EVA_*_RETRIES`,
`EVA_MAX_TOKENS` и пороги классификатора. Пустые `EVA_BIG_BASE`/`EVA_BIG_MODEL`
означают «большой модели нет»: всё, что не скилл, уйдёт в малую.

```bash
cd /path/to/eva32
cp -n .env.example .env
$EDITOR .env          # заполнить EVA_* и ключ большого провайдера
```

Ключ большого провайдера не попадает ни в лог, ни в `logs/eva.jsonl`.

## 3. Запуск и первый ответ

```bash
python3 -m eva.cli ask "сколько стоит тариф Старт" --explain
python3 -m eva.cli serve --port 8000
```

`ask --explain` печатает ответ с маршрутом и ценой — быстрая проверка, что скиллы
и модели на месте, без HTTP. `serve` держит процесс на переднем плане.

Порт `8000` тут уже занят прод-`vLLM` (его же проверяет `make status`), поэтому
локально удобнее `--port 8010`: флаг из контракта, маршрутизация от порта не зависит.

## 4. Проверка после старта

```bash
curl -sS http://127.0.0.1:8000/health
curl -sS -X POST http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"eva-hybrid","messages":[{"role":"user","content":"сколько стоит тариф Старт"}]}' \
  | python3 -m json.tool
```

`/health` отвечает 200, если процесс жив. В ответе кроме `choices[0].message.content`
есть поле `eva` с маршрутом, скиллом и ценой — его читают разделы 5–6.

## 5. Подключение из orioncode

Для orioncode гибрид — обычный OpenAI-провайдер, отдельный клиент не нужен:

- **base URL** — `http://127.0.0.1:8000/v1` (или адрес машины с `serve`); есть и `/v1/models`;
- **API key** — любая непустая строка: сервер `Authorization` не проверяет (сверено 2026-11-18);
- **model** — любое имя, оно лишь возвращается в ответе, маршрут выбирается сам; по
  умолчанию `eva-hybrid`.

Аккаунт провайдера заводится один раз; маршрут гибрид выбирает сам, клиент об этом
не знает. Поле `eva` дополнительное: клиент, который его не знает, его игнорирует.

Если orioncode ходит из контейнера, `127.0.0.1` — сам контейнер, а не хост: нужен
адрес хоста (`host.docker.internal`) или общая сеть. Частая причина «недоступен».

## 6. Маршруты и стоимость

Три источника, по возрастанию подробности: поле `eva` в ответе (маршрут
`skill`/`small`/`big`, скилл, `cost_rub`); `logs/eva.jsonl` — строка на ответ (время,
маршрут, скилл, токены, рубли, латентность); агрегат по логу — отчёт по маршрутам и дням.

```bash
tail -n 5 logs/eva.jsonl
python3 tools/usage_report.py --path logs/eva.jsonl
```

Много `big` на простых вопросах — классификатор уводит в облако лишнее (дорого);
много `small` на сложных — наоборот, качество. Доля `skill` растёт с наполнением
каталога. Цена на 1000 запросов — цифра для решения «выгоден ли гибрид», её и
сравнивают с «всегда большая модель»; цена = токены/1000 × `EVA_*_PRICE_*`.

## 7. 429, таймауты и прочие отказы

Фолбэки заданы в `eva/policy.py` (`docs/hybrid.md`): малая → большая при
ошибке/таймауте, большая → малая при 429 и превышении `EVA_MAX_COST_RUB`. Ретраи с
backoff уже внутри клиента — повторять запрос снаружи не нужно.

| Симптом | Вероятная причина | Действие |
|---|---|---|
| 429 от большой модели | лимит/слоты провайдера | ответ уже отдан малой; смотреть долю `big`; при частых 429 — бюджет или классификатор |
| таймаут малой модели | локальная модель не поднята | `curl` по `EVA_SMALL_BASE`, поднять/перезапустить её |
| «перегружена, секунду» | ретраи исчерпаны, пришёл `ClientError` | штатный фолбэк; искать серию подряд в `logs/eva.jsonl` |
| обрыв по бюджету | `EVA_MAX_COST_RUB` меньше цены запроса | поднять бюджет осознанно или отдать вопрос малой модели |
| 401 | ключ большой модели | ошибка конфигурации — править `.env`, ретраить бессмысленно |

429 — не ошибка гибрида, а сработавшая политика. Разбирать нужно не код ответа, а
`reason` маршрута: фолбэк на каждом втором запросе = конфиг или классификатор.

## 8. Замер

```bash
python3 tools/eval_hybrid.py
python3 -m unittest tests.test_eval_hybrid -v
```

Замер идёт с заглушками моделей: ни сети, ни ключей, ни денег. Печатает точность
маршрутов, долю скиллов и цену на 1000 запросов; тест фиксирует метрики от регрессии.
Замеры бандла (`make dev`, `make eval`) — про качество текста, а не про маршруты.

## 9. Что сверить до боевого запуска

- значения по умолчанию и пороги — `eva/config.py` (сверено 2026-11-18);
- URL баз малой и большой модели — панель провайдера, не догадка;
- `tools/eval_hybrid.py` — ещё пишется (`tools/usage_report.py` уже есть);
- флаги `--explain` у `ask` и `--port` у `serve` — `eva/cli.py`.

Пока пункт не сверен, поведение считается неизвестным, а не «работает по
умолчанию»: в гибриде неизвестная переменная стоит денег молча.
