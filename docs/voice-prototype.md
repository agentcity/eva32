# Голосовой прототип: ASR → eva → TTS

- Статус: рабочий прототип, проверен на macOS (Apple Silicon)
- Задача: [`ai/tasks/0032-eva-voice.md`](../ai/tasks/0032-eva-voice.md)
- Решение: [`docs/adr/0010-voice-pipeline.md`](adr/0010-voice-pipeline.md)
- Код: [`scripts/voice_loop.py`](../scripts/voice_loop.py)
- Тесты: [`tests/test_voice_loop.py`](../tests/test_voice_loop.py)

## Что сделано

Собран измеряемый конвейер из готовых частей:

```
WAV ──▶ whisper.cpp ──▶ текст ──▶ eva.router (скиллы) ──▶ текст ──▶ say -v Milena
                                                                    │
                                                                    ▼
                                                              WAV 16 кГц ──▶ afplay
```

Ключевые решения прототипа:

| Решение | Причина |
|---|---|
| ASR подключается, только если whisper.cpp собран | в задаче запрещена долгая сборка; без ASR остаётся `--text` |
| Отвечают только скиллы, модели **не вызываются** | проверка не должна запускать ollama; скилл «Сколько стоит тариф Старт» отвечает детерминированно |
| `say` синтезирует WAV, затем играет `afplay` | позволяет замерить первый фрагмент TTS и сохранить/проверить файл; живой `say` без файла заговорил бы чуть раньше |
| Текст ответа чистится перед озвучкой | `[1]`, markdown и `₽/мес` не должны читаться вслух как мусор |

Модели не вызываются ни при каком маршруте: если вопрос не покрыт скиллом,
скрипт вызывает только `eva.router.decide` (без сети), печатает `small`/`big`
и честно сообщает, что модель не запускалась.

## Как запустить

### Проверить голос

```bash
say -v '?' | grep Milena
# Milena              ru_RU    # Здравствуйте! Меня зовут Милена.
```

### Без ASR: только текст

```bash
python3 scripts/voice_loop.py --text "Сколько стоит тариф Старт"
```

Скрипт печатает вопрос, маршрут, ответ, текст для озвучки и тайминги. По
умолчанию синтезирует WAV и играет его через `afplay`.

Полезные варианты:

```bash
# Не производить звук (замеры и CI)
python3 scripts/voice_loop.py --text "Сколько стоит тариф Старт" --no-play

# Сохранить ответ в WAV 16 кГц/моно/16 бит
python3 scripts/voice_loop.py --text "Сколько стоит тариф Старт" \
    --out /tmp/reply.wav --no-play

# Машинный результат: JSON с таймингами
python3 scripts/voice_loop.py --text "Сколько стоит тариф Старт" --json --no-play

# Другой голос / темп
python3 scripts/voice_loop.py --text "..." --voice Milena --rate 190
```

### С ASR: WAV на входе

Вход — несжатый PCM WAV 16 кГц, моно, 16 бит. Быстрый способ сделать тестовый
WAV тем же `say`:

```bash
say -v Milena -o /tmp/request.wav --file-format=WAVE --data-format=LEI16@16000 \
    "Сколько стоит тариф Старт"
```

Запуск:

```bash
python3 scripts/voice_loop.py --wav /tmp/request.wav \
    --whisper-bin ./whisper.cpp/build/bin/whisper-cli \
    --model ./whisper.cpp/models/ggml-small.bin
```

Пути можно не указывать: скрипт ищет бинарник в `PATH`, `WHISPER_BIN` и типовых
каталогах (`whisper.cpp/build/bin/...`), модель — в `WHISPER_MODEL`, `models/`,
рядом с whisper.cpp и в кеше. Если whisper.cpp нет, скрипт завершается с кодом
2 и печатает команды сборки — без traceback.

### Сборка whisper.cpp (не запускалась в этой задаче)

Сборка долгая, поэтому она только описана. На macOS с Apple Silicon:

```bash
git clone https://github.com/ggml-org/whisper.cpp
cd whisper.cpp
cmake -B build -DGGML_METAL=ON
cmake --build build -j --config Release
bash models/download-ggml-model.sh small
```

Результаты:

- бинарник: `whisper.cpp/build/bin/whisper-cli` (старое имя — `main`);
- модель: `whisper.cpp/models/ggml-small.bin`.

Размеры моделей (примерно): `base` — 142 МиБ, `small` — 466 МиБ, `medium` —
1,5 ГиБ. Для русского на Apple Silicon разумный старт — `small`; если качество
не устроит, `medium` (медленнее примерно в 2–3 раза).

Скрипт вызывает whisper.cpp так:

```bash
whisper-cli -m MODEL -f INPUT.wav -l ru -nt -np -otxt -of /tmp/transcript
```

`-nt` убирает таймкоды, `-np` — служебные распечатки, `-otxt` пишет
`/tmp/transcript.txt`. Если файла нет, текст разбирается из stdout.

## Как считаются тайминги

| Поле | Что измеряется |
|---|---|
| `asr_ms` | запуск whisper.cpp и получение текста; при `--text` — `—` |
| `route_ms` | `eva.skills.try_skills` + `eva.router.answer`/`decide` (включая повторную проверку скилла внутри router) |
| `tts_synth_ms` | `say` от запуска до выхода: полный синтез WAV |
| `tts_first_fragment_ms` | появление в WAV первых аудиоданных после 4-КиБ заголовка `say`; нижняя оценка «когда заговорил бы живой say» |
| `play_start_ms` | запуск процесса `afplay` до возврата `Popen`; нижняя оценка старта звука (без учёта буферизации плеера) |
| `play_total_ms` | полное воспроизведение, включая длительность речи |
| `first_sound_ms` | `asr + route + tts_synth + play_start` — фактический путь до первого звука в этой схеме (с полным синтезом) |
| `live_estimate_ms` | `asr + route + tts_first_fragment` — ориентир для live `say` без промежуточного файла |

Важно: прототип сначала синтезирует **весь** ответ, потом начинает играть.
Для коротких ответов это почти не заметно, для длинных — заметно. Живой `say`
(и потоковый TTS по предложениям, как в ADR) заговорил бы раньше; колонка
`Ориентир live say` показывает эту оценку.

### Выводы по числам

- **Маршрут + скилл** — 2,4–4,5 мс, на три порядка меньше бюджета ADR (<10 мс).
- **TTS** — 0,88–1,18 с на синтез, первый фрагмент — 0,75–1,03 с. Основное
  время уходит на загрузку голоса/синтез `say`, а не на маршрут.
- **До первого звука без ASR** — около **1,02 с** (файловая схема); ориентир
  live `say` — около **0,88 с**.
- **Оценка с ASR**: ADR ждёт 0,3–0,5 с для `small` на фразу 5 с. Итог ожидаемо
  **1,32–1,52 с**, то есть в бюджете ADR 1,0–1,8 с. Это оценка, а не замер:
  whisper.cpp на машине не собран.
- Длинный ответ озвучивается целиком за 15,5 с; для голосового ассистента
  нужен потоковый TTS по предложениям, иначе ответ «Старт» звучит слишком
  долго.

## Что не проверено

- **ASR вообще не запускался**: whisper.cpp не собран, модели нет. Команда
  сборки описана, но не выполнялась (запрет задачи). Реальное качество
  распознавания русского, скорость на Metal и поведение на доменных словах
  («Старт», «Профи») не измерены.
- **HTTP-путь** (`python3 -m eva` + запрос к `/v1/chat/completions`) не
  подключён: прототип вызывает `eva.router` напрямую. Это следующий шаг, если
  голосовой цикл должен работать с живым сервером.
- **Микрофон и VAD** не реализованы: на входе готовый WAV. Конец фразы не
  определяется.
- **Перебивание (barge-in)** не реализовано: пока `afplay` играет, новый звук
  не глушится.
- **Потоковый TTS** не реализован: синтезируется весь ответ целиком.
- **Субъективное качество голоса** агентом не оценивалось; проверено, что
  `say` создаёт корректный WAV 16 кГц/моно и `afplay` его проигрывает.
- **Точность первого звука**: `play_start_ms` — это запуск `afplay`, а не
  показание акустики; первый фрагмент TTS — первые байты аудио, а не звук в
  динамике.
- **Linux/Windows** не поддерживаются: TTS завязан на macOS `say`/`afplay`.
- **Длинные WAV и таймауты** отдельно не нагружались; есть ограничители
  `--asr-timeout`, `--tts-timeout`, `--play-timeout`.

## Риски

1. **Качество русского ASR.** `small` может путать названия тарифов и числа.
   Если ошибки будут мешать, варианты: `medium`, доменный промпт/словарь,
   облачный ASR как явная опция (дверь в ADR оставлена).
2. **Задержка TTS на длинных ответах.** Сейчас первый звук ждёт полного
   синтеза. Для ответов скилла это ~1 с и 15 с речи; нужен streaming TTS по
   предложениям.
3. **`say` и голос Milena.** Голос может отсутствовать в другой локали
   macOS; проверка `say -v '?' | grep Milena` обязательна. Качество Milena
   ниже Silero/Piper, это отладочный TTS.
4. **Формат WAV.** whisper.cpp ждёт 16-битный PCM. Другой WAV (стерео,
   48 кГц, float) не будет принят без перекодирования; `ffmpeg` на машине нет,
   есть `afconvert`.
5. **Только скиллы.** Открытые вопросы не озвучиваются: прототип не должен
   молча уходить в ollama. Это осознанное ограничение проверки, а не
   архитектуры; в боевом конвейере маршрут `small`/`big` обязателен.
6. **Нет VAD и barge-in.** В шумной комнате и при перебивании поведение не
   проверено; это отдельный слой, как и записано в ADR.
7. **Замеры на одной машине.** Числа зависят от загрузки CPU, холодного старта
   `say` и длины ответа; таблица выше — ориентир, а не SLA.
