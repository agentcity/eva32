# VTM — виртуальная троичная машина (v0.1)

Своя машина вместо bitnet.cpp: мы контролируем формат, ядра и поведение, и можем
заменить бэкенд, не переписывая модель.

## Зачем своя

bitnet.cpp — форк llama.cpp: он диктует формат весов (i2_s/tl1), прячет ядра в
своих LUT-таблицах и тянет весь llama.cpp как зависимость. Нам нужно:

1. **Формат наш** — `.trit` с 20 тритами в 32-битном слове (`docs/trit-format.md`),
   который уже умеет `qat/export.py` и `tools/trit_codec.py`.
2. **Поведение наше** — модель исполняется детерминированно, без скрытых эвристик.
3. **Третий бэкенд в будущем** — сегодня скалярный C, потом SIMD, потом троичное
   железо. Модель при этом не перекомпилируется.

## Три слоя

```
модель (.trit + manifest)  →  компилятор (Python)  →  программа (.vtm)
                                                          ↓
                                          интерпретатор (C) → бэкенд (ядро)
```

- **Компилятор** (`tools/vtm_compile.py`) — граф модели → байткод. Без него
  интерпретатор не знает, какие слои в каком порядке.
- **Интерпретатор** (`src/vtm/`) — читает `.vtm`, исполняет инструкции по одной.
- **Бэкенд** — набор ядер. v0.1: скалярный C. Позже: NEON/AVX, затем железо.

## Контейнер `.vtm`

```
┌─ заголовок (32 байта) ─────────────────────────────┐
│ "VTM1" | версия u16 | флагов u16 | n_instr u32       │
│ n_tensors u32 | n_program u32 | резерв               │
├─ таблица тензоров (n_tensors × 44 байта) ───────────┤
│ имя[24] | kind u8 | ndim u8 | dims u16×4 | offset u32│
│ scale_offset u32 | резерв u16                        │
├─ данные тензоров (выровнены на 32 байта) ───────────┤
├─ программа (n_instr × 16 байт) ─────────────────────┤
└─────────────────────────────────────────────────────┘
```

`offset` — смещение от начала секции данных, выровнено на 32 байта.
`kind`: `0` — триты (TRT1-сегмент, 160 тритов на блок, масштаб на блок),
`1` — fp32, `2` — fp16, `3` — bf16.

## Инструкция (16 байт)

```
opcode u8 | flags u8 | dst u16 | a u16 | b u16 | c u16 | imm i32
```

- тензоры адресуются индексами в таблице, не указателями — программа
  переносима между машинами;
- `imm` — целое, интерпретация зависит от операции (позиция, число голов,
  эпсилон в тысячных, температура в тысячных);
- `flags` — битовые признаки (например, `CAUSAL`, `INPLACE`).

## Набор операций v0.1

| Код | Имя | Семантика |
|---|---|---|
| 0x01 | `TMV` | `y = W_trit · x · scale` (троичная матрица на вектор) |
| 0x02 | `MM` | `Y = A · B` (fp, для attention) |
| 0x03 | `RMSN` | `y = x / rms(x) · w`, `imm` = eps×1000 |
| 0x04 | `ROPE` | поворот `x` по позиции `imm`, головы `b` |
| 0x05 | `SM` | softmax по последней оси, `flags & CAUSAL` |
| 0x06 | `SILU` | `x · sigmoid(x)` поэлементно |
| 0x07 | `MUL` | `c = a · b` поэлементно |
| 0x08 | `ADD` | `c = a + b` поэлементно |
| 0x09 | `EMB` | `y = E[token]`, `imm` = token id |
| 0x0A | `KVW` | записать K,V в кэш на позицию `imm` |
| 0x0B | `ATTN` | `out = softmax(Q·Kᵀ/√d)·V` с маской `flags` |
| 0x0C | `SAMP` | выбрать токен из логитов (`imm` = вариант сэмплинга) |
| 0x0D | `CPY` | копировать тензор |
| 0x0E | `SCAL` | `y = x · (imm/1000)` |
| 0x0F | `HALT` | останов |

Прямолинейный поток: переходов нет. Ветвление (генерация в цикле) делает
хост, вызывая `vtm_run()` на каждый токен — так проще отлаживать.

## Память

- Арена: один `malloc` на все тензоры + KV-кэш, выровненный на 64 байта.
- Тензоры не освобождаются поштучно — вся арена живёт до конца `vtm_run`.
- KV-кэш — отдельная арена (`context_len × layers × kv_dim`), аллоцируется один раз.

## Контракт бэкенда

```c
typedef struct {
    const char *name;
    int (*tmv)(float *y, const uint8_t *w, const float *scales,
               const float *x, int rows, int cols);
    int (*rmsnorm)(float *y, const float *x, const float *w, int n, float eps);
    /* … по одной функции на операцию; NULL = взять скалярную реализацию */
} vtm_backend;
```

Интерпретатор проверяет `NULL` и падает обратно на скалярный путь. Так SIMD
подключается без изменения байткода.

## Порядок работ

| Этап | Что | Готово, когда |
|---|---|---|
| 1 | Спека (этот файл) | согласована |
| 2 | Скалярный интерпретатор + `TMV`, `RMSN`, `SM`, `SILU`, `ADD/MUL` | синтетический слой 128×128 совпадает с Python-эталоном |
| 3 | Компилятор графа Qwen-слоя | один слой 1.5B даёт те же логиты, что HF |
| 4 | Полная модель + токенизатор | связный ответ на вопрос |
| 5 | SIMD-ядра | ≥2× к скаляру на `TMV` |

## Что этот путь стоит

Свой рантайм — это **месяцы**, а не дни: полная модель требует RoPE, GQA,
KV-кэш, BPE-токенизатор и отладку численных расхождений. bitnet.cpp уже умеет
это, но не даёт контроля. Мы платим временем за независимость — сознательно.

Первые два этапа дают проверяемый результат за недели, а не месяцы: если
синтетический слой совпал с эталоном, архитектура верна, и дальше это работа,
а не исследование.
