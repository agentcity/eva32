# Плагины: расширения без пересборки ядра

> Актуально на 2026-11-26.

> **Статус: в работе (задача [0209](../ai/tasks/0209-plugin-runtime.md)).**
> Решение принято — [ADR 0022](adr/0022-plugins.md); в дереве появился каркас
> `eva/plugins/` (манифест, реестр, контекст) и пустые каталоги
> `plugins/<id>/`. Рабочих `plugin.json`, включения через `config/plugins.json`
> и API плагинов пока нет. Ниже — **контракт, к которому идёт реализация**, а
> не описание того, что уже можно включить.

## Зачем

Сегодня возможности Евы размазаны по коду: скиллы — в `eva/skills`, речевые
нормализаторы — в `eva/ru_numbers.py`/`eva/ru_speech.py`/`eva/ru_gender.py`,
TTS-движки — в `eva/tts.py`. Чтобы добавить «погоду» или новый источник цифр,
нужно править ядро. Плагин должен позволять **положить каталог, включить и
пользоваться**, не трогая ядро ([ADR 0022](adr/0022-plugins.md)).

## Каталог и манифест

Плагин — каталог `plugins/<id>/` с манифестом `plugin.json` (версия контракта
`api: 1`):

```json
{
  "id": "weather",
  "name": "Погода",
  "version": "1.0.0",
  "api": 1,
  "entry": "plugin.py",
  "capabilities": ["skill.fetch"],
  "permissions": {"network": ["wttr.in"], "filesystem": []},
  "settings": {"city": "Москва"},
  "description": "Текущая погода через wttr.in",
  "owner": "eva32"
}
```

Обязательны `id`, `name`, `version`, `entry`, `capabilities`; `api` с чужой
версией отклоняется с понятным текстом («ядро поддерживает api=1»), код
плагина при этом не исполняется. Неизвестная способность — тоже ошибка
манифеста, а не «тихо ничего не делает».

## Способности

| Способность | Что делает | Куда встраивается |
|---|---|---|
| `skill.fetch(ctx, question)` | достаёт факт по вопросу (время, курсы, котировки, погода) | ядро собирает `[Факт: …]` в системный блок **до** генерации |
| `filter.run(text)` | постобработка ответа (числа в слова, женский род, чистка разметки) | после генерации, порядок — по `priority` |
| `tts.engine` | альтернативный синтез речи | выбор TTS-движка |
| `command` | слэш-команды чата (`/погода Москва`) | разбор вопроса до маршрутизации |

Позже планируется `ui.panel` — панель в EVA.app.

## Права и изоляция

Плагин объявляет `permissions`: `network` — список хостов, `filesystem` —
список путей. Рантайм не даёт ходить в сеть и читать файлы вне разрешённого
(best-effort: обёртка над `urllib`, проверка путей); отказ — явная ошибка с
именем плагина, а не тихое игнорирование. Полноценная песочница — отдельный
шаг: плагин это код, который мы запускаем.

## Жизненный цикл

1. **discovery** — обход `plugins/` (и `EVA_PLUGINS_DIR`), чтение манифестов;
2. **загрузка** — только включённых в `config/plugins.json`
   (`{"enabled": ["time", "currency"]}`); выключенный плагин не исполняется;
3. **регистрация способностей** и вызовы;
4. **включение/выключение** — без перезапуска, если плагин не объявил
   `stateful: true`; иначе требуется рестарт и это сообщается.

Ошибка одного плагина не останавливает чат: остальные продолжают работать.

## Какие плагины планируются первыми

`time`, `currency`, `stocks` — перенос скиллов из
[0208](../ai/tasks/0208-eva-tools.md) (время, курсы, котировки);
`ru-numbers` и `ru-gender` — фильтры нормализации чисел
([0205](../ai/tasks/0205-tts-numbers.md)) и женского рода
([0207](../ai/tasks/0207-feminine-speech.md)). Ядро остаётся работоспособным и
с выключенными плагинами — это критерий приёмки, а не пожелание.

## Что уже есть в дереве

- `eva/plugins/manifest.py` — чтение и проверка `plugin.json`, версия API;
- `eva/plugins/registry.py` — discovery, загрузка включённых, регистрация
  способностей, сбор фактов и фильтров;
- `eva/plugins/context.py` — `PluginContext` (настройки, лог, безопасный
  `fetch` с allowlist);
- `plugins/<id>/` — каталоги первых плагинов (пока пустые).
