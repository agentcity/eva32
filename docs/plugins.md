# Плагины: расширения без пересборки ядра

> Актуально на 2026-11-26.

> **Статус: работает (задача [0209](../ai/tasks/0209-plugin-runtime.md)).**
> Решение принято — [ADR 0022](adr/0022-plugins.md); в дереве есть рантайм
> `eva/plugins/` (манифест, реестр, контекст), рабочие `plugin.json` и
> включение через `config/plugins.json`. Ниже — контракт и описание того, что
> уже можно включить; музыка и сказки — отдельные разделы про способность
> `answer`.

## Зачем

Сегодня возможности Евы размазаны по коду: скиллы — в `eva/skills`, речевые
нормализаторы — в `eva/ru_numbers.py`/`eva/ru_speech.py`/`eva/ru_gender.py`,
TTS-движки — в `eva/tts.py`. Чтобы добавить «погоду» или новый источник цифр,
нужно править ядро. Плагин должен позволять **положить каталог, включить и
пользоваться**, не трогая ядро ([ADR 0022](adr/0022-plugins.md)).

## Каталог и манифест

Плагин — каталог `plugins/<id>/` с манифестом `plugin.json` (версия контракта
`api: 1`):

```json
{
  "id": "weather",
  "name": "Погода",
  "version": "1.0.0",
  "api": 1,
  "entry": "plugin.py",
  "capabilities": ["skill.fetch"],
  "permissions": {"network": ["wttr.in"], "filesystem": []},
  "settings": {"city": "Москва"},
  "description": "Текущая погода через wttr.in",
  "owner": "eva32"
}
```

Обязательны `id`, `name`, `version`, `entry`, `capabilities`; `api` с чужой
версией отклоняется с понятным текстом («ядро поддерживает api=1»), код
плагина при этом не исполняется. Неизвестная способность — тоже ошибка
манифеста, а не «тихо ничего не делает».

## Способности

| Способность | Что делает | Куда встраивается |
|---|---|---|
| `skill.fetch(ctx, question)` | достаёт факт по вопросу (время, курсы, котировки, погода) | ядро собирает секцию `СПРАВКА` в системный блок **до** генерации |
| `filter.run(text)` | постобработка ответа (числа в слова, женский род, чистка разметки) | после генерации, порядок — по `priority` |
| `tts.engine` | альтернативный синтез речи | выбор TTS-движка |
| `command` | слэш-команды чата (`/погода Москва`) | разбор вопроса до маршрутизации |
| `answer(ctx, question)` | плагин отвечает сам, без модели (сказка, музыкальная команда) | сервер зовёт плагины **до** генерации; при непустом ответе `finish_reason="plugin"` |

Позже планируется `ui.panel` — панель в EVA.app.

## Права и изоляция

Плагин объявляет `permissions`: `network` — список хостов, `filesystem` —
список путей. Рантайм не даёт ходить в сеть и читать файлы вне разрешённого
(best-effort: обёртка над `urllib`, проверка путей); отказ — явная ошибка с
именем плагина, а не тихое игнорирование. Полноценная песочница — отдельный
шаг: плагин это код, который мы запускаем.

## Музыка: плагин `music` (задача 0219)

`plugins/music/` — способность **`answer`**: сервер не зовёт модель, если Ева
услышала музыкальную команду. Ответ — одно короткое предложение, оно уходит и
в историю, и в озвучку. Чужие команды («включи свет», «который час») плагин не
трогает и возвращает `None` — отвечает модель или другой плагин.

| Что сказать | Что делает |
|---|---|
| «включи музыку», «включи что-нибудь», «поставь/вруби музыку» | `play` (продолжает с текущего места) |
| «включи Кино», «поставь группу Кино», «включи песню …», «хочу послушать …» | поиск в библиотеке: плейлист по имени → трек по имени → трек по исполнителю |
| «пауза», «поставь на паузу», «приостанови» | `pause` |
| «продолжи», «играй дальше», «сними с паузы» | `play` |
| «следующая», «следующий трек», «дальше» | `next track` |
| «предыдущая», «предыдущий трек», «назад» | `previous track` |
| «выключи музыку», «останови музыку», «стоп» | `stop` |
| «громче», «сделай громче», «прибавь звук» | `sound volume` +10 (потолок 100) |
| «тише», «убавь звук» | `sound volume` −10 (пол 0) |
| «заглуши», «выключи звук» / «включи звук» | mute / 50 % |
| «что играет», «какая песня играет», «что за музыка» | «Играет: <исполнитель> — <название>» |

Если в библиотеке ничего не нашлось, ответ честный: «Не нашла в библиотеке …».
Если Music.app закрыт, macOS не дала разрешение автоматизации или
`osascript` не ответил за 5 секунд (настройка `timeout`), плагин возвращает
короткое «не удалось», а не исключение и не вешает чат.

**Как управляет.** Только `/usr/bin/osascript` и AppleScript: вызов идёт
списком аргументов `["/usr/bin/osascript", "-e", script]` без `shell=True`.
Пользовательский запрос попадает в скрипт единственным строковым литералом с
экранированием `\` и `"`; кавычки/переводы строк из фразы вычищаются ещё при
нормализации. Никакие параметры не подставляются в shell.

**Интернет-радио.** «Включи радио» (или «включи европу плюс», «включи дфм»)
запускает `/usr/bin/afplay <url>` — тоже списком аргументов, без ключей и
`shell=True`; фоновый процесс останавливается командой «выключи музыку»,
«пауза» посылает `SIGSTOP`, «продолжи» — `SIGCONT`. Зашиты прямые публичные
потоки:

| Станция | URL |
|---|---|
| Европа Плюс (по умолчанию) | `http://ep128.hostingradio.ru:8030/ep128` |
| DFM | `https://dfm.hostingradio.ru/dfm96.aacp` |
| Наше Радио | `https://nashe1.hostingradio.ru/nashe-128.mp3` |

Эти хосты перечислены в `permissions.network` манифеста. Для радио
TCC-разрешение не нужно; для Music.app при первом запуске macOS показывает
диалог автоматизации — в headless-сессии его надо подтвердить один раз
вручную (иначе ответ будет «macOS не разрешила…»).

Старый прямой поток Radio Record (`rr96.aacp`) сейчас отдаёт 404, а новый HLS
(`…/record/playlist.m3u8`) `afplay` в этой среде не открывает, поэтому станция
в список не включена. Если `afplay` не смог открыть поток (нет сети, битый
URL, `AudioFileOpen failed`), плагин замечает это через 0,3 с и отвечает
«Не получилось включить радио», а не делает вид, что играет.

Включение — как у остальных плагинов, в `config/plugins.json`:

```json
{"enabled": ["time", "currency", "music"], "settings": {}}
```

## Сказки: плагин `fairy-tales` (задачи 0218/0220)

`plugins/fairy-tales/` — тоже способность **`answer`**, но источник ответа не
внешний сервис, а офлайн-корпус `tales/*.md`. Сервер вызывает плагин до
модели; при непустом ответе модель не участвует, `finish_reason="plugin"`, а
текст уходит в историю и в `/api/tts`.

| Что сказать | Что делает |
|---|---|
| «расскажи сказку», «хочу сказку», «почитай сказку» | случайная сказка не длиннее 3500 символов |
| «волшебную сказку» | случайная сказка с тегом `волшебная` |
| «сказку про бабу-ягу» | сказка с тегом `баба-яга` (по умолчанию не страшная) |
| «короткую сказку» | сказка не длиннее 800 символов |
| «сказку для малыша», «ребёнку» | сказка с `age: 3+` |
| «сказку про лису», «про колобка», «про репку», «про зиму», «про медведя» | выбор по тегу/названию |
| «сказку на ночь», «почитай перед сном» | сказка и мягкая концовка «Сладких снов» |
| «следующая сказка», «ещё сказку», «продолжи» | следующая по порядку; после последней — снова первая |
| «сколько у тебя сказок» | число сказок словами и два-три примера названий |
| «страшную сказку» | явная просьба: только тогда выбираются сказки с тегом `страшная` |
| «включи запись сказки», «поставь аудиосказку», «сказку в исполнении» | готовая запись из `audio/` — `afplay`, без синтеза |
| «выключи», «стоп сказку», «останови запись» | останавливает `afplay` (голое «выключи» — только если запись играет) |
| «медленнее», «быстрее», «обычный темп» | темп записи: −/+0.05 в границах 0.75…1.15, «обычный» — 1.0 |
| «который час», «включи музыку», «расскажи про погоду» | `None` — отвечает модель или другой плагин |

В корпусе двадцать девять сказок: «Колобок», «Репка», «Теремок», «Курочка
Ряба», «Лиса и журавль», «Вершки и корешки», «Три медведя», «Кот, петух и
лиса», «Зимовье зверей», «Мальчик с пальчик», «Сестрица Алёнушка и братец
Иванушка», «Сивко-бурко», «Царевна-лягушка», «Морозко», «Гуси-лебеди»,
«Крошечка-Хаврошечка», «Баба-яга», «Снегурушка и лиса», «Летучий корабль»,
«Никита Кожемяка», «Лиса, заяц и петух», «Кот и лиса», «Журавль и цапля»,
«Золотая рыбка», «Пузырь, соломинка и лапоть», «Лиса и рак», «Терешечка»,
«Петушок — золотой гребешок», «Грибы». У каждой сказки в шапке есть `title`,
`tags`, `age` (`3+`/`5+`/`7+`) и `source` — ссылка на страницу Викитеки.
Тексты — общественное достояние (Афанасьев, Толстой, Гатцук и фольклорные
записи XIX века). Корпус скачан один раз и лежит в репозитории: в манифесте
`permissions.network: []`, а `permissions.filesystem: ["tales", "images",
"audio"]` разрешает только чтение собственных текстов, иллюстраций и записей
через `PluginContext`.

Страшные сказки (`Морозко`, «Баба-яга», «Терешечка») помечены тегом
`страшная`; без слов «страшная», «жуткая» или «ужасная» они не попадают ни в
случайный выбор, ни в подбор по волшебному/короткому/возрасту. Явная просьба
«страшную сказку» снимает этот запрет. Возраст — ориентир для родителя, а не
жёсткий фильтр: `3+` — короткие сказки про зверей, `5+` — волшебные с
приключениями, `7+` — там, где есть смерть или ведьма.

### Картинки к сказкам (задача 0221)

Для девяти сказок рядом с текстом лежат классические иллюстрации в
общественном достоянии: `images/<slug>/NN.jpg` (Колобок, Репка, Теремок,
Лиса и журавль, Три медведя, Гуси-лебеди, Царевна-лягушка, Баба-яга,
Сивка-бурка). Автор, файл Commons и лицензия — в
[`plugins/fairy-tales/images/credits.md`](../plugins/fairy-tales/images/credits.md).
Ширина 1024 px, JPEG ≤ 300 КБ; генерации нет, только сканы и репродукции
(Билибин, Васнецов, Зворыкин, Бём, Богатов и др.).

`answer` может вернуть не строку, а словарь:

```python
{"text": "Слушай сказку…", "images": [
    {"path": "images/kolobok/01.jpg", "alt": "Иллюстрация 1 к сказке «Колобок»",
     "after_chars": 382},
]}
```

`path` — относительно каталога плагина, `after_chars` — сколько символов
текста уже показать до картинки (плагин ставит позиции на границах абзацев).
Если картинок для сказки нет, возвращается прежняя строка — старые вызовы
и тесты не ломаются.

Сервер (`tools/chat_server.py`) для словаря с `images` режет ответ на
`delta`-куски по `after_chars` и между ними шлёт SSE-событие:

```json
{"type": "image", "side": 0, "url": "/media/fairy-tales/kolobok/01.jpg",
 "alt": "Иллюстрация 1 к сказке «Колобок»"}
```

`GET /media/<plugin>/<path>` отдаёт файл **только** из
`plugins/<id>/images/`: проверяется канонический путь (никаких `..` и
симлинков наружу), плагин должен быть в реестре, расширение — картинка
(`.jpg/.jpeg/.png/.webp/.gif`). Content-Type — по расширению,
`Cache-Control: max-age=86400`. Чужой плагин, не-картинка и выход за каталог
— 404. Страница чата показывает `image`-события как `<figure>` с подписью
(`img-src 'self'` в CSP).

Ответ готовится для Silero: без markdown, числа — словами
(`eva.ru_numbers.numbers_to_words`), абзацы не длиннее 480 символов (сервер
режет озвучку на куски ≤ 600). Начало — «Слушай сказку… «Название»», конец —
«Сказке конец, а кто слушал — молодец» или «Закрывай глазки и засыпай.
Сладких снов». Суммарный объём корпуса — около 97 КБ, потолок — 120 КБ;
длинные варианты сокращены до сути, сюжет сохранён.

### Записи сказок (задача 0223)

Четыре сказки есть в готовой актёрской записи: «Кот, петух и лиса»,
«Царевна-лягушка» (другой вариант), «Баба-яга» (первая сказка) и «Теремок»
(«Теремок мышки»). Файлы лежат в `plugins/fairy-tales/audio/<slug>.mp3`,
каждый не больше 3 МБ; автор, чтец, источник и лицензия — в
[`audio/credits.md`](../plugins/fairy-tales/audio/credits.md). Это записи
LibriVox с Archive.org: `licenseurl` — Public Domain Mark 1.0, то есть
общественное достояние; «все права защищены» не используется.

«Включи запись сказки» (без названия) берёт последнюю сказку с записью или
любую из четырёх; «про бабу-ягу» — соответствующую. Запуск — только
`subprocess.Popen(["/usr/bin/afplay", "-r", "0.9", path],
start_new_session=True)`, без `shell=True`; путь всегда локальный, из каталога
плагина. Ответ плагина —
`{"text": "Включаю запись «…».", "silent": true}`: сервер отдаёт текст в SSE
(`delta`/`done` с `silent: true`), но не отправляет его в `/api/tts`, иначе
голос Евы звучал бы поверх записи. Веб-клиент по `silent` показывает текст,
но не ставит его в очередь озвучки. «Выключи»/«стоп сказку» завершает
процесс (`SIGCONT` → `terminate` → `kill` по таймауту).

Если записи для выбранной сказки нет, ответ честный и без падения:
«Записи сказки «…» нет, могу рассказать сама» (и это уже обычная строка,
`silent` не выставляется — Ева читает сказку синтезом). Если `afplay` нет или
файл не открылся, плагин так и говорит, а не делает вид, что играет.

#### Темп записи (задача 0231)

Актёрская запись в обычном темпе для ребёнка быстрая, поэтому по умолчанию
она играет на **0.9** (на 10 % медленнее): `afplay -r 0.9`. `-r` меняет
скорость без изменения тона; это не громкость — «громче/тише» по-прежнему
управляют системным звуком Mac.

| Команда | Темп |
|---|---|
| «медленнее», «помедленнее», «читай медленнее» | −0.05, не ниже **0.75** |
| «быстрее», «побыстрее», «читай быстрее» | +0.05, не выше **1.15** |
| «обычный темп», «нормальная скорость» | **1.0** |

Темп хранится в состоянии плагина (`answer` живёт в одном объекте), поэтому
выбранная скорость действует и на следующую запись. Ответ называет число:
«Читаю на 90 процентах скорости», на границе — «Медленнее уже нельзя: читаю
на 75 процентах скорости». Голая «медленнее» без игры и без слов про
чтение/темп («читай медленнее») не перехватывается: «Расскажи медленно
сказку про репку» — просьба сказки, «Включи музыку быстрее» — зона music.

Смена темпа во время игры перезапускает `afplay` с новой скоростью **с той же
позиции**: позиция считается как `прошедшее время × старый темп` (0.9 за
секунду проходит 0.9 секунды записи). `afplay` не умеет начинать файл с
середины, поэтому плагин спрашивает у `afinfo` частоту дискретизации, режет
начало командой `afconvert --offset <кадры> -f WAVE -d LEI16` во временный WAV
в системном `TMPDIR` и запускает `afplay -r <новый темп> <временный WAV>`;
временный файл удаляется при «выключи» и при следующей смене. Если `afinfo`
или `afconvert` недоступны/не справились, запись начинается сначала, и ответ
честно говорит: «…Начну запись сначала — не получилось сохранить место».
Ответ во время игры — `silent: true` (Ева не говорит поверх записи); если
запись не играет, темп просто запоминается («Хорошо, буду читать на 85
процентах скорости»).

Состояние (последняя сказка) живёт в объекте плагина: «следующая сказка»
работает в пределах одного процесса сервера. Включение:

```json
{"enabled": ["time", "currency", "fairy-tales"], "settings": {}}
```

## Жизненный цикл

1. **discovery** — обход `plugins/` (и `EVA_PLUGINS_DIR`), чтение манифестов;
2. **загрузка** — только включённых в `config/plugins.json`
   (`{"enabled": ["time", "currency"]}`); выключенный плагин не исполняется;
3. **регистрация способностей** и вызовы;
4. **включение/выключение** — без перезапуска, если плагин не объявил
   `stateful: true`; иначе требуется рестарт и это сообщается.

Ошибка одного плагина не останавливает чат: остальные продолжают работать.

## Какие плагины планируются первыми

`time`, `currency`, `stocks` — перенос скиллов из
[0208](../ai/tasks/0208-eva-tools.md) (время, курсы, котировки);
`ru-numbers` и `ru-gender` — фильтры нормализации чисел
([0205](../ai/tasks/0205-tts-numbers.md)) и женского рода
([0207](../ai/tasks/0207-feminine-speech.md)). Ядро остаётся работоспособным и
с выключенными плагинами — это критерий приёмки, а не пожелание.

## Что уже есть в дереве

- `eva/plugins/manifest.py` — чтение и проверка `plugin.json`, версия API;
- `eva/plugins/registry.py` — discovery, загрузка включённых, регистрация
  способностей, сбор фактов и фильтров;
- `eva/plugins/context.py` — `PluginContext` (настройки, лог, безопасный
  `fetch` с allowlist);
- `plugins/<id>/` — рабочие плагины `time`, `currency`, `stocks`, `ru-facts`,
  `ru-numbers`, `ru-gender`, `music` и `fairy-tales` (последние два —
  способность `answer`).

Включение — списком `enabled` в `config/plugins.json` (или
`EVA_PLUGINS_CONFIG`), без правки ядра. Список плагинов, их права и
`last_error` отдаёт `GET /api/plugins`; включить/выключить без перезапуска —
`POST /api/plugins`.
