## Правила

1. **ADR пишется до реализации**, если решение меняет архитектуру, контракт,
   формат данных или процесс. Мелочи (опечатка, формат сообщения) — без ADR.
2. **ADR не переписывается задним числом.** Устаревшее решение помечается
   `superseded` со ссылкой на новое; текст остаётся как история.
3. Статусы: `proposed` (обсуждается), `accepted` (действует), `superseded`,
   `rejected` (рассмотрено и отклонено — тоже полезно знать).
4. В ADR обязательны **альтернативы**: решение без отвергнутых вариантов —
   это не решение, а мнение.
5. **Последствия** пишутся честно: что станет дороже/сложнее, а не только выгоды.
6. Ссылка на ADR — в задаче (`ai/tasks/`) и в теле коммита, который его реализует.
