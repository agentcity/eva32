# ADR 0009: Гибридный маршрутизатор — скиллы, малая модель, большая модель

- Статус: accepted
- Дата: 2026-11-18
- Контекст: продукт «ассистент», а не только модель

## Контекст

Цель — ассистент уровня «как Алиса/GigaChat», но своими силами и на своём железе.
Считать пришлось по фактам:

- предобучение с нуля уровня Qwen2.5 требует ~18 трлн токенов; для 3B это
  ~750 GPU-часов и сотни тысяч рублей — и всё равно качество ниже готовой базы;
- наша дистилляция на 30–300 млн токенов даёт голос и дисциплину, но не общие
  знания;
- полноценный аналог Алисы — это ещё ASR, TTS, скиллы, поиск и память, а не
  только веса.

Один путь (своя большая модель) — миллионы рублей. Другой (только облако) —
зависимость и цена за каждый запрос. Нужен третий.

## Решение

**Гибрид с явным маршрутизатором.** Три источника ответа в порядке приоритета:

1. **Скиллы** — детерминированные ответы из каталога (цены, часы, возврат,
   контакты). Ноль рублей, ноль галлюцинаций.
2. **Малая троичная модель** (1.5–3B, наша, на своём железе) — тон, приветствия,
   пересказ, простые вопросы.
3. **Большая модель по API** — общие знания, код, рассуждение, всё, где малая
   не уверена или где скилл молчит.

Маршрут решается правилами (`eva/classifier.py`), причины пишутся в ответ,
у каждого ответа есть цена. Фолбэки: малая → большая при ошибке/таймауте,
большая → малая при 429 или превышении бюджета.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Только своя малая модель | общие знания не появятся: 30 млн токенов их не дают |
| Только большая модель по API | дорого на каждый запрос, нет своего голоса, зависимость |
| Предобучение с нуля | 8 млн ₽ и годы; качество всё равно ниже готовой базы |
| Дообучение 14–32B и свой сервер | 30–50 тыс ₽/мес за сервер, но без скиллов всё равно не ассистент |
| Всегда большая модель, малая «для галочки» | не даёт экономии — то есть теряется смысл гибрида |

## Последствия

- **Скиллы — главный источник точности**, и их надо писать и поддерживать:
  каталог меняется, значит меняются и они.
- Классификатор ошибается: часть простых вопросов уйдёт в облако (дороже),
  часть сложных — в малую модель (хуже). Нужна метрика доли правильных маршрутов.
- Появляется себестоимость на запрос — её надо считать и держать в бюджете.
- Малая модель становится не «сердцем», а **дешёвым слоем**: её качество важно,
  но не критично для фактов (их дают скиллы и RAG).
- Пересматриваем, если: облачный провайдер подорожает втрое, или малая модель
  покажет качество, при котором облако нужно <5% запросов.
