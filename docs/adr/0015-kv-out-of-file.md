# ADR 0015. KV-кэши вне файла контейнера и «tripwire» для старых бинарей

Дата: 2026-11-18
Статус: принято
Задачи: 0101, 0110, 0118

## Контекст

Контейнер `.vtm` хранил KV-кэши прямо в секции данных, на весь контекст. Для формы
Qwen2.5-1.5B (ctx 2048, kv_dim 256, 28 слоёв) это **112 МиБ пустых буферов** — 13% файла
(1296,1 → 1184,1 МиБ), плюс лишнее копирование при загрузке.

Задача 0101 вынесла их: тензор помечается битом `VTM_TENSOR_FLAG_KV_CACHE` (поле `flags`,
бывший резерв, смещение 50), payload в файл не пишется, загрузчик выделяет буфер в арене.

## Проблема совместимости

Старый бинарь (до 0101) не знает про флаг: он увидит `offset = 0` и загрузит в кэш
**мусор** вместо явной ошибки. Функционально это может «повезти» (KVW перезапишет слоты до
чтения ATTN), но хост до прогона увидит мусор, а контейнер с крошечной секцией данных может
не пройти bounds-check.

Версию формата поднимать не хотелось: старые **читатели** должны продолжать читать старые
контейнеры, а bump версии ломает всё сразу.

## Решение

1. **Header-флаг** `VTM_HEADER_FLAG_KV_OUT_OF_FILE = 0x0004` (бит 2) — ставится писателем,
   если в контейнере есть KV-кэши вне файла.
2. У таких тензоров `offset = 0xFFFFFFFF` (`KV_NO_OFFSET`) вместо `0`.
3. **Tripwire:** старый загрузчик первым делом проверяет `offset % 32 == 0` и падает с
   `VTM_E_FORMAT` («offset=4294967295 не кратен 32»), не читая данные. Это единственное
   свойство старого кода, на которое можно опереться без изменения формата.
4. **Кэп** `VTM_MAX_KV_BYTES = 512 МиБ` (переопределяется `-D`): сумма `n_elements*4` по
   KV-тензорам проверяется до `calloc`. Защита от амплификации (файл 192 Б не должен
   заказывать 4 ГиБ) и от опечаток в размерах.

## Следствия

- Старый бинарь на новом контейнере: **внятный отказ**, а не мусор (проверено сборкой
  бинаря из `9f15975^`).
- Новый бинарь читает и новые, и старые контейнеры (кэши в файле) — регрессии нет.
- Контейнеры **без** KV пишутся байт-в-байт как раньше.
- Кэп 512 МиБ отвергнет легитимные профили с ctx > 8192 у 1.5B (ctx 16384 = 896 МиБ) —
  поднимать через `-DVTM_MAX_KV_BYTES`.
- Инструменты, пишущие KV-кэши по-старому (`tools/bench_shape.py`), не обновлялись:
  новый C их читает, старый бинарь получит мусор — ретроактивно не исправить.

## Альтернативы

- **Поднять версию формата.** Отвергнуто: ломает чтение старых контейнеров новыми бинарями
  ради одной проверки; tripwire даёт тот же результат дешевле.
- **Хранить в файле, но разреженно.** Отвергнуто: размер файла остаётся, выигрыша нет.
