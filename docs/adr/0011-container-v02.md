# ADR 0011: Контейнер `.vtm` v0.2 — размерности u32

- Статус: accepted
- Дата: 2026-11-18
- Контекст: формат контейнера ВТМ

## Контекст

Задача 0028 при попытке загрузить настоящую модель упёрлась в формат: в записи
тензора размерности хранятся как **u16**, максимум 65 535. У Qwen2.5 словарь —
**151 936 токенов**, то есть таблицу эмбеддингов и lm_head в контейнер положить
некуда. На синтетике с 128 элементов этого не видно, на реальной модели — блокер.

## Решение

Версия формата **2**: размерности `u32 × 4` вместо `u16 × 4`.

- Запись тензора: 24 (имя) + 1 (kind) + 1 (ndim) + **16** (dims) + 4 + 4 + 2
  (резерв) = **52 байта** вместо 44.
- Заголовок не меняется, поле `version` = 2.
- Читатель v0.2 читает только v0.2; v0.1-файлы отвергаются с внятной ошибкой
  (у нас нет ценных артефактов v0.1 — синтетика пересобирается за секунды).
- Писатель (Python) и читатель (C) обновляются одновременно, плюс тесты на
  круглый словарь >65 535.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Чанкинг: разбить эмбеддинги на тензоры ≤65535 строк | работает без смены формата, но плодит сущности: EMB должен склеивать строки из 3 тензоров, lm_head — из 3 матриц; ошибки индексации трудноуловимы |
| Хранить эмбеддинги вне контейнера (отдельный файл) | два артефакта вместо одного, ломается «модель = один файл» |
| Уменьшить словарь ученика | меняет модель: токенизатор Qwen требует полный словарь |
| Оставить u16 и усечь словарь до 65535 | потеря 56% словаря, русский рассыпается |

## Последствия

- Формат несовместим с v0.1 — все тестовые `.vtm` пересобираются (они генерируются).
- Файл чуть больше: +8 байт на тензор (на модели из ~600 тензоров — +5 КБ, шум).
- Нужно обновить `docs/vtm.md`, `tools/vtm_ref.py`, `src/vtm/loader.c` и тесты
  синхронно, иначе писатель и читатель разойдутся.
- Пересматриваем, если: понадобится словарь >4 млрд (не в этой жизни).
