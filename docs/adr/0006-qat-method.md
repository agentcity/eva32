# ADR 0006: Метод QAT — STE, absmax-блок 128, fp32-мастер, 8-bit Adam

- Статус: accepted
- Дата: 2026-11-18
- Контекст: обучение троичной модели

## Контекст

Нужно обучение, которое влезает в одну 24-гигабайтную карту (RTX 4090) и не
теряет прогресс при обрыве связи. Память QAT складывается из bf16-копии, fp32-
мастера, состояний Adam и активаций.

Считать: 1.5B → 21,6 ГБ без оптимизаций, 12,3 ГБ с 8-bit Adam; 3B → 43,3 / 24,7 ГБ.

## Решение

- **Квантуем только Linear** в attention и FFN (`q/k/v/o/gate/up/down`).
  Эмбеддинги, `lm_head`, layernorm, bias и роутеры остаются в fp32/bf16.
- **Масштаб — absmax на блок 128** вдоль входной размерности; вес = `trit · scale`.
- **STE**: `w + (w_tern - w).detach()` — вперёд идёт квантованный вес, назад —
  тождественная производная.
- **Мастер-веса fp32**, bf16 только в autocast: при lr ~3e-5 обновления в bf16
  округляются до нуля и модель не учится.
- **8-bit Adam** с фолбэком на AdamW, gradient checkpointing, микро-батч 4 ×
  накопление 8, длина 2048.
- **Атомарные чекпоинты** (tmp + rename), `--resume`, SIGINT/SIGTERM сохраняют
  прогресс, `--dry-run` на 3 шага для проверки узла.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| bf16-мастер | обновления теряются, QAT не сходится (проверено расчётом) |
| Масштаб на канал вместо блока | хуже для матриц с выбросами, а на блок — проще и стабильнее |
| Полный словарь в KL-лоссе | неприменимо на больших данных: логиты 152k × батч |
| FP8-адаптеры (LoRA) | не даёт троичных весов — цель именно триты |
| FP32 Adam без 8-bit | 1.5B не влезает в 24 ГБ вместе с активациями |

## Последствия

- QAT требует GPU-окно: 6–8 часов аренды 4090 (600–900 ₽).
- Экспорт содержит только троичные слои; нетернарные остаются в `model.pt` —
  для полной модели нужен отдельный сборочный шаг.
- Одна карта: нет DDP/FSDP, нет валидации и early stopping — это следующие шаги.
- Пересматриваем, если: понадобится 3B на одной 24-ГБ карте (тогда ZeRO или 48 ГБ).
