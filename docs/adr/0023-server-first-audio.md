# ADR 0023. Пока всё на сервере: сказки, музыка, голос

Дата: 2026-11-27
Статус: принято (временно; пересмотр — по метрикам ниже)
Связано: [0020](0020-clients-and-cloud.md), [0022](0022-plugins.md)

## Контекст

Обсуждали перенос «телесных» функций на клиент, потому что при переносе сервера
в облако музыка (Music.app через AppleScript), записи сказок (afplay) и голос
(Silero, torch локально) перестанут работать: они исполняются на машине
сервера, а не на устройстве пользователя.

Рассматривали три пути: (1) действия в приложении, (2) локальный агент,
(3) оставить на сервере.

## Решение

**Оставляем на сервере.** Причины:

- сказки и картинки удобно править в одном месте, без пересборки приложения;
- Юрий работает на том же Mac, где стоит сервер, — разделение ничего не даёт
  сегодня;
- любое разделение — новый контракт (`action`), перенос логики выбора сказок в
  Swift и риск расхождения поведения; платить это сейчас не за что.

## Когда пересматриваем (критерии, не «когда-нибудь»)

1. Сервер переезжает в облако (или на другую машину) — тогда музыка и записи
   обязаны стать действиями клиента.
2. Голос: если TTS по сети даёт **первый звук > 1,5 с** или сервер не
   выдерживает параллельные озвучки — Silero переезжает в приложение
   (или системный `say` как запас).
3. Картинки: если повторный показ сказки каждый раз тянет мегабайты
   (нет дискового кэша) — добавить кэш в приложении.

## Что это меняет сейчас

Ничего в коде. Контракт `action` не вводим, пока сервер локальный. Ветка
«облако» остаётся описанной в ADR 0020 и здесь — чтобы не проектировать заново.
