# ADR 0007: Задачи в ai/tasks, отчёт исполнителя, приёмка архитектором

- Статус: accepted
- Дата: 2026-11-18
- Контекст: работа с восемью субагентами

## Контекст

Задачи велись в переписке и в теле коммита одной строкой. При восьми агентах это
не работает: не видно, кто что делает, что уже принято, а что висит. Никакой
агент не может проверить чужую работу, если критерии не сформулированы заранее.

## Решение

1. Задача — файл `ai/tasks/NNNN-<слаг>.md` с фронтматтером (`task_id`, `type`,
   `author`, `assignee`, `status`, `scope`) и разделами: Проблема, Требования,
   Критерии приёмки, Контекст и ограничения, Отчёт исполнителя.
2. Реестр `ai/tasks/index.json` обновляется в том же коммите, что и файл задачи.
3. Статусы: `pending → in_progress → review → done | blocked`. `blocked` всегда
   с причиной.
4. **Агент не коммитит.** Он сдаёт правки и заполняет отчёт; коммит делает
   архитектор после проверки критериев командами.
5. Тело коммита: `Задача: NNNN` и `Refs: ai/tasks/NNNN-<слаг>.md`.
6. Критерий, который нельзя проверить командой, — не критерий.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| GitHub Issues | нет в офлайн-репозитории, агенты не умеют в них писать |
| Только переписка | теряется при смене сессии, нет истории решений |
| Один общий TODO-файл | нет исполнителя, отчёта и критериев |
| Полная фабрика с тимлидами (как в orioncode) | избыточно: у нас один архитектор и плоский пул агентов |

## Последствия

- Накладные расходы: ~10 минут на задачу до старта.
- Зато приёмка объективна, а задача и коммит связаны в обе стороны.
- `tools/check_tasks.py` в CI не даёт завести задачу без критериев и отчёта.
- Пересматриваем, если: агентов станет больше десяти (тогда нужны тимлиды) или
  появится внешний трекер.
