# EVA.app — нативное приложение с голосом

> Актуально на 2026-11-26.

Задача: [`ai/tasks/0184-native-voice-app.md`](../ai/tasks/0184-native-voice-app.md),
большой круг — [`ai/tasks/0186-eva-circle-visual.md`](../ai/tasks/0186-eva-circle-visual.md),
wake-word — [`ai/tasks/0187-wake-word.md`](../ai/tasks/0187-wake-word.md),
слушание после ответа — [`ai/tasks/0190-followup-listening.md`](../ai/tasks/0190-followup-listening.md),
компактный круг — [`ai/tasks/0188-compact-floating-circle.md`](../ai/tasks/0188-compact-floating-circle.md),
голосовая команда «Стоп, Ева» — [`ai/tasks/0194-stop-command.md`](../ai/tasks/0194-stop-command.md).
Приложение-компаньон к чат-серверу (`tools/chat_server.py`): статус-бар, ⌥Space —
сказать, ответ печатается из SSE и по желанию звучит голосом Silero через
`/api/tts`. Всё локально, без сети и без сторонних зависимостей.

```
⌥Space или «Привет, Ева» → Apple Speech (ru-RU, on-device) → текст
       → POST /api/chat (SSE)            → окно ответа
       → POST /api/tts                   → AVAudioPlayer
       → микрофон снова открыт (follow-up) → следующий вопрос без «Привет, Ева»
       ↑ «Стоп, Ева» во время речи → тишина + POST /api/cancel → idle
```

## Сборка

Нужны macOS 13+ и `swiftc` из Xcode Command Line Tools (Swift 6.2). Больше
ничего: ни SwiftPM, ни Xcode-проекта, ни внешних пакетов. Исходники собираются
в языковом режиме Swift 6 (строгая проверка Sendable) без предупреждений.

```bash
sh tools/build_eva_app.sh          # build/EVA.app
sh tools/build_eva_app.sh --run    # собрать и сразу открыть
sh tools/build_eva_app.sh --clean  # удалить build/EVA.app
```

Что делает скрипт:

1. собирает все `apps/eva/Sources/*.swift` одним вызовом `swiftc`;
2. уводит модульный кэш Swift и Clang в `/tmp/eva-app-*` — в каталоге
   репозитория `swiftc` падает с `Operation not permitted`;
3. кладёт `apps/eva/Info.plist` в бандл (там обязательные
   `NSMicrophoneUsageDescription`, `NSSpeechRecognitionUsageDescription`,
   `LSUIElement` — статус-бар без иконки в доке);
4. подписывает бандл ad-hoc (`codesign -s -`) — без подписи arm64-бинарь не
   запустится, а без бандла Apple Speech не выдаёт авторизацию;
5. печатает размер (≈0,7 МБ, лимит задачи — 20 МБ).

Пути можно переопределить: `EVA_OUT_DIR=/tmp/eva`, `EVA_SWIFT_MODULECACHE=…`,
`EVA_CLANG_MODULECACHE=…`.

## Первый запуск и разрешения

```bash
open build/EVA.app
```

Приложение не появляется в доке — оно в статус-баре (иконка «волна»). При
обычном запуске окно открывается сразу (чтобы было видно, что приложение
запустилось); с флагом `--background` остаётся только статус-бар, а с галочкой
«Запускаться свёрнутым» — только круг в правом нижнем углу. Окно также
открывается по ⌥Space, из меню («Спросить текстом…») или при первом вопросе.

При первом нажатии ⌥Space macOS спросит **два** разрешения:

1. **Микрофон** — «Ева слушает ваш вопрос с микрофона…»;
2. **Распознавание речи** — «Ева распознаёт русскую речь прямо на этом Mac…».

Оба должны быть включены, иначе приложение честно скажет, чего не хватает:
`Системные настройки → Конфиденциальность → Микрофон / Распознавание речи`.
Распознавание идёт **только на устройстве** (`requiresOnDeviceRecognition`);
для ru-RU нужна системная офлайн-модель: `Системные настройки → Клавиатура →
Диктовка → языки → Русский`. Если её нет, приложение откажется слушать, а не
отправит звук в облако.

После пересборки ad-hoc подпись меняется, и macOS может спросить разрешения
заново — это нормально. Сбросить выданное вручную:

```bash
tccutil reset Microphone com.eva32.eva
tccutil reset SpeechRecognition com.eva32.eva
```

## Как пользоваться

| Действие | Что происходит |
|---|---|
| ⌥Space (глобально) | начать слушать: иконка становится микрофоном, статус «слушаю…», в окне живой частичный текст |
| ⌥Space ещё раз (или «Стоп») | запись останавливается, последний распознанный текст уходит в чат |
| «Озвучивать» | ответ синтезируется по фразам (`/api/tts`) и играет, пока печатается |
| «Показывать картинки сказок» (по умолчанию вкл.) | иллюстрации из SSE-события `image` появляются над текстом по ходу чтения (после 15 симв/с речи или таймера): плавно проявляются, сменяются кроссфейдом 0,35 с, последняя остаётся до нового вопроса; на круг и озвучку не влияют |
| голос | `baya — живой` (по умолчанию), `kseniya — выше`, `xenia — ниже` |
| голос в окне | то же, что в настройках, — меняется сразу |
| «Стоп» | шлёт `POST /api/cancel {"side":0}`, обрывает генерацию и речь |
| «Стоп, Ева» / «хватит» / «тише» (галочка в настройках) | пока Ева думает или говорит — то же, что «Стоп»: тишина, отмена генерации, круг в `idle` |
| «Привет, Ева» (галочка в настройках) | в `idle` слушает фразу; услышала — «слушаю…», дальше как после ⌥Space |
| «Слушать после ответа» (галочка, по умолчанию вкл.) | после ответа (и конца озвучки) микрофон открывается сам: следующий вопрос — без «Привет, Ева»; 12 с тишины → снова ждём фразу |
| «Свернуть» / `⌘M` | главное окно прячется, на экране остаётся маленький круг поверх окон |
| клик / двойной клик по кругу | развернуть окно / начать-закончить слушать (как ⌥Space); правый клик — меню «Развернуть», «Настройки…», «Выход» |
| поле ввода + Enter | вопрос с клавиатуры, без микрофона |
| «Настройки…» | адрес сервера, модель, голос, озвучка, картинки сказок, анимация круга, запуск свёрнутым, ожидание «Привет, Ева», слушание после ответа, пауза тишины и «Слушать „Стоп, Ева“» |

## Большой круг состояния

Сверху окна — круг, который показывает состояние Евы без чтения текста:

| Состояние | Как выглядит | Когда |
|---|---|---|
| `idle` | приглушённый серо-бирюзовый круг медленно «дышит» (период ~4,5 с); при включённом ожидании — едва заметная пульсация и подпись «жду „Привет, Ева“» | приложение ждёт |
| `listening` | синяя кольцевая волна и насечки по кругу; амплитуда — реальный RMS микрофона; в follow-up волны приглушены | идёт запись (⌥Space, «Привет, Ева») или follow-up после ответа |
| `thinking` | фиолетовый круг, две вращающиеся дуги, учащённая пульсация | вопрос ушёл; если включена озвучка — до первого звука (иначе до первого видимого текста) |
| `speaking` | зелёная «жидкая» волна по краю диска; амплитуда — громкость `AVAudioPlayer` | играет озвучка |
| `error` | красная вспышка ~1,2 с и текст ошибки под кругом | ошибка речи, сервера или `/api/tts` |

Под кругом — короткая подпись («слушаю», «думаю», «говорю»), полный текст
статуса и ошибок остаётся в шапке окна. Диаметр круга — доля ширины окна
(≈28 %, от 110 до 240 pt), поэтому он масштабируется вместе с окном и не
разжимает остальную вёрстку.

Как считается уровень:

* **микрофон** — RMS каждого буфера в аудио-тапе (`bufferSize = 2048`,
  ≈43 мс при 48 кГц). Тап приходит на realtime-очереди аудио, поэтому он не
  трогает `@MainActor`-состояние: RMS кладётся в неизолированный `LevelMeter`
  под коротким замком, а главный актор читает его 30 раз в секунду.
  Атака сглаживания 35 мс, отпускание 120 мс — реакция заметно быстрее 100 мс,
  но без дрожания на каждом буфере;
* **озвучка** — `AVAudioPlayer.isMeteringEnabled = true`,
  `updateMeters()`/`averagePower(forChannel:)` по таймеру 30 Гц. Тишина
  отображается как 0, обычная речь — примерно 0,4–0,8.

Круг рисуется обычным Core Graphics в `draw(_:)`; анимация — таймер 30 Гц,
который останавливается вместе с галочкой «Анимация круга». В покое с
включённой анимацией это доли процента CPU (на M-серии измерено ≈0,1 %);
если машина слабая — снимите галочку, круг станет статичным и таймер не
запустится вообще. Смена состояния плавная: цвет перетекает за 0,25 с.

Ответ приходит потоком: `start` → `delta` → `done` → `end`. Текст печатается по
мере прихода; `<think>…</think>` не показывается в ответе — он складывается в
свёрнутую строку «размышления (N симв.)» и **никогда не озвучивается**.

Если сервер выключен или модель не отвечает, в статусе будет понятная ошибка
(`HTTP 400: …`, `сеть: …`), окно и озвучка продолжат работать.

Картинки сказок (задача 0224) приходят отдельными SSE-событиями `image` и
**не являются озвучкой**: круг не переключается в `speaking` и не выходит из
`idle` из-за картинки. Это тот же принцип, что и у текста: показ иллюстрации
меняет только окно ответа.

Смена картинок привязана к прогрессу чтения, а не к приходу событий (задача
0227). Ответ плагина-сказки приходит одним куском — все `delta` и `image`
прилетают за миллисекунды, — поэтому очередь запоминает для каждой картинки,
после скольких сказанных символов её показывать. С включённой озвучкой
прогресс даёт `VoicePlayer`: завершённые фразы плюс оценка текущей по времени
(~15 символов/с). Если озвучка выключена, ответ `silent` (играет запись
`afplay`) или TTS не поднялся, картинки ведёт таймер с той же оценкой 15
символов/с; для `silent` отсчёт идёт от запуска внешней записи. «Стоп» и новый
вопрос гасят очередь и таймеры и убирают картинку из окна.

## Компактный режим: только круг (задача 0188)

Разговор не обязан занимать окно. «Свернуть» в главном окне (или `⌘M`,
или «Вид → Свернуть в круг») прячет окно и оставляет на экране маленький
круг — видно, слушает Ева или думает, а рабочее место свободно.

| Действие | Что происходит |
|---|---|
| «Свернуть» / `⌘M` | главное окно скрывается (не закрывается), справа снизу появляется круг 140 pt |
| одиночный клик по кругу | главное окно возвращается, круг прячется; ответ и статус — на месте |
| двойной клик по кругу | начать/закончить слушать, как `⌥Space`, **не разворачивая** окно |
| правый клик по кругу | меню «Развернуть», «Настройки…», «Выход» |
| перетаскивание круга | окно едет за мышью, позиция запоминается |

Как это устроено:

* **Окно**: безрамочный `NSPanel` 140×140 pt (требование 120–160), уровень
  `NSWindow.Level.floating`, прозрачный фон, без тени и анимации появления.
  `nonactivatingPanel` + `canBecomeKey = false`: клик по кругу не забирает
  фокус у активного приложения, `LSUIElement` не даёт иконке появиться в Dock.
  Показ — `orderFrontRegardless()`, без `NSApp.activate`.
* **Позиция**: по умолчанию правый нижний угол `visibleFrame` с отступом
  24 pt; перетаскивание сохраняет левый нижний угол в
  `eva.compactX`/`eva.compactY` `UserDefaults` и восстанавливает его при
  следующем показе/запуске. Каждый показ, перетаскивание и смена
  монитора/разрешения зажимают окно в `visibleFrame` (то есть за строку меню
  и Dock оно не выходит). При отключении монитора окно переезжает на основной
  экран.
* **Состояния**: второй круг — тот же класс `CircleView`, а состояние, уровень
  микрофона/озвучки, вспышка ошибки, пульсация ожидания и приглушение
  follow-up приходят из общего `CircleHub`. Логика выбора состояния осталась
  одна — `AppDelegate.refreshVisualState`; копии нет. Пока главное окно
  скрыто, его круг тоже получает значения: при развороте ничего не догоняется.
* **Клик и двойной клик**: одиночный клик ждёт `NSEvent.doubleClickInterval`
  (таймер на главном run loop), поэтому двойной успевает его отменить.
  Перетаскивание отличается от клика по смещению мыши/окна (>2 pt).
* **Ответы в свёрнутом виде**: окно не всплывает на каждый вопрос. Оно
  собирается скрытым (`prepare()`), текст вопроса и ответа копится в нём, и
  после клика человек видит тот же разговор. `⌥Space` и «Привет, Ева» в
  компактном режиме тоже не разворачивают окно — только круг показывает
  «слушаю».
* **Запуск**: галочка «Запускаться свёрнутым» в настройках (по умолчанию
  **выключена**) при старте оставляет только круг; `--background` по-прежнему
  означает «только статус-бар», а `--ask` — обычный запуск с окном.

## Ожидание «Привет, Ева»

Wake-word (задача 0187) начинает разговор словами, без хоткея. Галочка
«Слушать „Привет, Ева“» в настройках (по умолчанию **выключена** — это
постоянный микрофон и расход батареи) держит слушатель только в `idle`:

```
idle ──«Привет, Ева»──→ listening → thinking → speaking → follow-up → idle
  ↑                                           (задача 0190)    │
  └──────────── после ответа, конца озвучки и тишины ───────────┘
```

Как это устроено:

* отдельный `AVAudioEngine` и отдельный `SFSpeechRecognizer` (ru-RU,
  `requiresOnDeviceRecognition = true`); обычная запись `SpeechRecorder` в это
  время не работает;
* аудио-тап (realtime-очередь) только копирует сэмплы в кольцевой буфер на 2 с
  под коротким замком; в `SFSpeechAudioBufferRecognitionRequest` звук переносит
  отдельная очередь (25 Гц). Тап не хватает @MainActor-состояние — иначе Swift 6
  роняет процесс через dispatch_assert_queue;
* в частичных результатах ищется нормализованная фраза: нижний регистр, только
  буквы и пробелы. Триггер — «привет» + «ева» (в любом порядке, поэтому
  «Привет! Ева, ты здесь?» тоже сработает) или «эй ева» рядом. Одно слово
  «Ева» не срабатывает;
* услышали — слушатель сразу останавливается, микрофон освобождается и
  запускается обычная запись с авто-стопом по тишине; после ответа и конца
  озвучки ожидание поднимается снова (если включён follow-up, сначала на 12 с
  открывается микрофон — см. «Разговор без кнопок»);
* пока играет озвучка (и пока идёт запись), ожидание выключено: иначе Ева
  услышит собственное «Ева» и зациклится;
* в `idle` круг едва заметно пульсирует, подпись — «жду „Привет, Ева“»; с
  выключенной галочкой микрофон не держится вовсе;
* звук никуда не уходит: распознавание локальное, `POST /api/chat` получает
  только текст.

Журнал:

```text
wake: ожидание включено (микрофон 48000 Гц, каналов 1, on-device)
wake: услышала „Привет, Ева“
wake: перехожу к записи (Привет, Ева)
wake: ожидание выключено
```

Если нет прав на распознавание речи или микрофон, либо не установлена
офлайн-модель ru-RU, ожидание не поднимается: причина пишется в журнал
(`wake: …`) и в статус («ожидание: …»), а ⌥Space продолжает работать. После
выдачи прав включите галочку заново (или перезапустите приложение).

## Разговор без кнопок: follow-up (задача 0190)

После ответа Ева не отпускает разговор: как только смолкает её голос,
микрофон открывается снова — следующий вопрос можно задать, не произнося
«Привет, Ева». Это режим **follow-up**, он включается автоматически.

```
⌥Space / «Привет, Ева» → listening → thinking → speaking ─┐
        ↑                                                 │ голос смолк
        │                                                 ▼
   idle + «жду „Привет, Ева“» ←── 12 с тишины ──── follow-up listening
                                                          │ речь
                                                          ▼
                                              авто-стоп 2,2 с → вопрос
```

Правила:

* старт — **после окончания озвучки** (или сразу после ответа, если озвучка
  выключена). Пока Ева говорит, микрофон закрыт: иначе она услышит собственный
  голос и «Ева» в нём (та же причина, что и в wake-режиме). Если человек начал
  говорить раньше, запись всё равно начнётся после стопа озвучки;
* тишина до первого слова — **12 с** (настройка: 8/12/20). Истекла — микрофон
  тихо закрывается, вопроса нет, ошибки «не расслышала» нет; круг возвращается
  в прежнее ожидание «Привет, Ева» (если галочка включена) или в `idle`;
* если речь началась и замолчала — обычный авто-стоп **2,2 с** и отправка
  вопроса; ответ снова заканчивается follow-up, и так по кругу;
* круг в follow-up — то же `listening` («слушаю»), но волны приглушены: это
  «слышу вас после ответа», а не запись по ⌥Space. В ожидании фразы — прежняя
  пульсация и подпись «жду „Привет, Ева“»;
* follow-up работает **только при включённой галочке «Слушать „Привет, Ева“»**:
  без неё микрофон после ответа не открывается (прежнее поведение). Галочка
  «Слушать после ответа» (по умолчанию включена) выключает follow-up совсем;
* если ответ закончился ошибкой (сервер не отвечает, HTTP-ошибка, модель
  вернула `error`), follow-up не открывается: красная вспышка и текст ошибки
  остаются видимыми, ожидание фразы возвращается как раньше;
* «Стоп», ⌥Space или снятая галочка во время follow-up закрывают запись без
  отправки; ответ и озвучку автоматика не трогает.

Журнал:

```text
follow-up: открываю микрофон — озвучка доиграла
follow-up: слушаю
круг: speaking → listening — микрофон включён

# вариант 1: сказали следующий вопрос
follow-up: услышала вопрос, отправляю

# вариант 2: 12 секунд тишины
follow-up: тишина 12 с — ушла в ожидание
wake: ожидание включено (микрофон 48000 Гц, каналов 1, on-device)
```

Пауза считается от включения микрофона; ожидание фразы поднимается примерно
через 0,2 с после закрытия записи. CPU follow-up-записи — тот же, что у обычной
записи (распознавание on-device); отдельного таймера в покое не остаётся.

## Перебить голосом: «Стоп, Ева» (задача 0194)

Пока Ева «думает» или говорит, её можно остановить голосом — кнопка и ⌥Space
перестают быть единственным способом:

```
вопрос → thinking ──«Стоп, Ева»──┐
       → speaking ──«хватит»─────┴→ тишина + POST /api/cancel → idle/listening
                                                     ↓
                                    wake-ожидание «Привет, Ева» (если включено)
```

Команды: **«стоп»**, **«стоп, Ева»**, **«хватит»**, **«тише»** — достаточно
одного слова-триггера в нормализованной фразе (нижний регистр, только буквы и
пробелы, как у wake-слова). «Стоп!», «Стоп, хватит» и «Ева, стоп» срабатывают
так же; «останови» и «стопкран» — нет.

Как это устроено:

* отдельный `StopCommandListener` — тот же `AVAudioEngine` + `SFSpeechRecognizer`
  (ru-RU, `requiresOnDeviceRecognition = true`), кольцевой буфер на 2 с и насос,
  что у wake-слова. Слушатель живёт **только** пока Ева думает или говорит; в
  `idle` и во время записи его нет вовсе;
* **один движок на режим**: `AppDelegate.listenerPlan` выбирает ровно одного —
  `wake` в покое, `stop` во время речи; запись (`SpeechRecorder`) и вспышка
  ошибки исключают обоих. Переходы «вопрос ушёл → stop» и «озвучка кончилась →
  wake» идут через один и тот же `syncWake`, поэтому два `AVAudioEngine`
  микрофон одновременно не держат;
* **эхоподавление**: на входном узле включается
  `setVoiceProcessingEnabled(true)` (API с macOS 10.15; вызов в `do/catch`).
  Если драйвер/железо не поддержало API, слушатель пишет это в журнал и
  поднимается без AEC, а не молчит. Voice processing открывает всю микрофонную
  решётку Mac (на проверенной машине — **9 каналов**), а
  `AVAudioFormat(standardFormatWithSampleRate:channels:)` для >2 каналов
  возвращает `nil`; поэтому кольцо стоп-слушателя всегда моно, а
  `WakeAudioRing` сам сводит вход в 1 канал — распознавателю уходят 48 кГц/моно;
* **защита от самоподхвата**: если фраза, которая звучит из колонок прямо
  сейчас, сама содержит «стоп» или «хватит», совпадение с микрофона считается
  эхом и игнорируется (`VoicePlayer.currentText` →
  `StopCommandListener.shouldIgnore`). Поэтому ответ Евы «…и на этом стоп.»
  не глушит её саму. «Тише» в эхо-защиту не входит — так требует задание;
  собственный голос Евы это слово практически не произносит;
* **отклик**: распознанный частичный результат сразу глушит `AVAudioPlayer`
  (без ожидания конца фразы), затем уходит `POST /api/cancel {"side":0}` — тот
  же путь, что у кнопки «Стоп»; follow-up сбрасывается, круг возвращается в
  `idle` (или `listening`, если шла запись), «Привет, Ева» поднимается снова.
  После получения результата распознавания до тишины — единицы миллисекунд;
  собственная задержка Apple Speech (частичный результат) на этой машине
  ≈0,3–1 с, её код не отменяет;
* **настройка** «Слушать „Стоп, Ева“» (по умолчанию **включена**): сняли
  галочку — микрофон во время речи не держится вовсе, остаются кнопка и
  ⌥Space. Микрофон активен только пока Ева говорит/думает; распознавание
  локальное, звук никуда не уходит.

Журнал:

```text
стоп: слушание включается — вопрос ушёл
стоп: слушаю команду (микрофон 48000 Гц, вход 9 кан. → моно, on-device, эхоподавление=вкл)
стоп-команда: услышала „Стоп, Ева“
стоп-команда: глушу („Стоп, Ева“)
стоп: озвучка остановлена
стоп: генерация отменена
стоп: слушание выключено
wake: ожидание просит включиться — стоп по голосу
```

Если микрофон/распознавание не поднялись (нет прав, нет офлайн-модели ru-RU),
стоп-слушание пишет причину в журнал (`стоп: …`) и не перезапускается на каждой
смене состояния, но пробует снова на следующем вопросе и при смене настроек —
⌥Space, кнопка «Стоп» и озвучка продолжают работать.

## Запрос к серверу

Приложение шлёт ровно тот контракт, что у страницы чата (задачи 0182/0183):

```json
POST /api/chat
{"question": "…",
 "sides": [{"backend": "vtm", "model": "runs/q4/3b-q4k.vtm"},
           {"backend": "none"}],
 "max_tokens": 256, "use_system": true}
```

Вторая колонка всегда «нет»: в приложении один ответ. Историю диалога ведёт
сервер — приложение её не дублирует. Озвучка — `POST /api/tts`
`{"text": "фраза", "voice": "baya"}` → WAV; фразы режутся по `. ! ? …` и
переводам строк, каждая ≤560 символов (лимит сервера — 600). Неизвестный
голос сервер отклоняет с 400 и списком допустимых.

Между `delta` сервер может прислать иллюстрацию сказки:

```json
{"type": "image", "side": 0, "url": "/media/fairy-tales/kolobok/01.jpg", "alt": "…"}
```

Сервер режет текст на `delta`-куски по `after_chars` и между ними присылает
`image`, поэтому к моменту события всё, что должно быть показано до картинки,
уже в ответе. Приложение запоминает эту позицию в двух системах координат —
символы видимого текста (для таймера) и символы, ушедшие в `/api/tts` (для
прогресса речи), — и показывает картинку только когда чтение дошло до неё.

Приложение собирает абсолютный URL от адреса сервера, качает его `URLSession`
в фоне, кэширует в памяти (`NSCache` по URL, до 32 картинок) и повторяет
запрос один раз при ошибке. Ошибка загрузки не ломает ответ: просто нет
картинки. Порядок показа — порядок событий, даже если файлы скачались
вразнобой; последняя картинка остаётся до нового вопроса.

Если плагин уже запустил запись сказки (`afplay`, задача 0223), сервер ставит
в `delta`/`done` поле `"silent": true`. Тогда приложение показывает текст, но
**не отправляет ни одной фразы в `/api/tts`** — иначе сказку читают два голоса;
в журнале появляется `озвучка: пропущена (silent)`.

## Проверка без мышки и без микрофона

Внутри бандла есть самопроверки — они гоняют те же `ChatSession`, `ThinkFilter`
и `VoicePlayer.fetchWav`, что и окно, но печатают результат в stdout:

```bash
# поток /api/chat: start/delta/done, скрытие <think>, полный ответ
build/EVA.app/Contents/MacOS/EVA --selftest-chat "Привет, как тебя зовут?" \
  --model 'vtm|runs/tiny/model.vtm'

# WAV из /api/tts (заголовок RIFF, размер) → /tmp/eva-selftest.wav
build/EVA.app/Contents/MacOS/EVA --selftest-tts "Проверка голоса" --out /tmp/eva-selftest.wav

# реестр моделей сервера
build/EVA.app/Contents/MacOS/EVA --selftest-backends

# права Apple Speech и офлайн-модель ru-RU (без запроса разрешений)
build/EVA.app/Contents/MacOS/EVA --selftest-speech

# скрытие <think> на границах чанков и нарезка фраз для озвучки
build/EVA.app/Contents/MacOS/EVA --selftest-text

# wake-слово без микрофона: нормализация, триггер, кольцевой буфер
build/EVA.app/Contents/MacOS/EVA --selftest-wake

# follow-up без микрофона: паузы 2,2/6/8/12/20 с, правило
# «только вместе с ожиданием „Привет, Ева“» и запрет после ошибки ответа
build/EVA.app/Contents/MacOS/EVA --selftest-followup

# «Стоп, Ева» без микрофона: матчер («стоп», «хватит», «тише»), эхо-защита
# от собственной речи, сведение 9/3 каналов микрофона в моно и план
# «wake или stop, но не оба» (задача 0194)
build/EVA.app/Contents/MacOS/EVA --selftest-stop

# аудио-путь ожидания N секунд: микрофон и кольцевой буфер без распознавания,
# печатает кадры и CPU процесса (права на микрофон нужны, на речь — нет)
build/EVA.app/Contents/MacOS/EVA --selftest-wake-audio 20

# компактный круг: правый нижний угол/зажатие в visibleFrame (в т.ч. смена
# монитора), живое окно в CGWindowList (140 pt, floating, прозрачное),
# отсутствие перехвата фокуса, клики/меню, позиция в UserDefaults
build/EVA.app/Contents/MacOS/EVA --selftest-compact

# картинки сказок и silent без сети и звука: разбор SSE image/silent, сборка
# URL от адреса сервера, кэш, битый URL, вид и окно ответа; темп 15 симв/с:
# картинки на 300/600/900 символов меняются около 20/40/60 с (часы и темп
# подменяются в проверке, реального ожидания нет)
build/EVA.app/Contents/MacOS/EVA --selftest-images

# контракт с сервером: сколько image-событий в сказке и пропущена ли озвучка
build/EVA.app/Contents/MacOS/EVA --selftest-chat "расскажи сказку про колобка"
build/EVA.app/Contents/MacOS/EVA --selftest-chat "включи запись сказки"
```

`--selftest-compact` открывает настоящее компактное окно на ~3 секунды и
создаёт его в отдельном домене `UserDefaults` — позиция обычного круга не
меняется.

`--selftest-chat` печатает `image-событий: N` (у «Колобка» — 4) и строку
`озвучка: пропущена (silent)`, если сервер пометил ответ уже озвученным
записью. `--selftest-images` работает без сети и звука и не трогает TCC: он
проверяет разбор событий, URL, кэш и вёрстку окна, а также темп смены картинок
(900 символов, картинки на 300/600/900 — 20/40/60 с при 15 симв/с) с
подменёнными часами и темпом.

Вопрос можно отправить сразу при запуске (окно откроется и напечатает ответ):

```bash
build/EVA.app/Contents/MacOS/EVA --ask "Привет!" --no-voice
```

`--server URL`, `--model backend|id`, `--voice id` временно переопределяют
настройки; `--no-voice` выключает озвучку (удобно для тихой проверки).

Проверить, что приложение живёт в статус-баре:

```

```

круг: speaking → listening — микрофон включён      # follow-up

строками `компакт:` (показ/скрытие/зажатие).

## Ограничения и риски

- **Распознавание**: только ru-RU и только on-device. Хоткей — Carbon
  `RegisterEventHotKey`, разрешение «Универсальный доступ» не нужно; но если
  ⌥Space занят другим приложением, в журнале будет `хоткей: ⌥Space занят`,
  останется меню.
- **TCC и ad-hoc подпись**: после каждой пересборки система может спросить
  разрешения снова (cdhash меняется). Для повседневного использования собирайте
  один раз.
- **Звук**: озвучка идёт через `AVAudioPlayer` по фразам. Сервер отдаёт WAV
  (Silero/say/espeak) или MP3 (ElevenLabs, задача 0191) с правильным
  `Content-Type`; AVAudioPlayer понимает оба. Если ElevenLabs недоступен,
  сервер сам откатывается на Silero/system, поэтому 503 («голос недоступен»)
  означает, что локального голоса тоже нет; текст при этом продолжает
  печататься, в статусе появляется причина.
- **Круг и CPU**: анимация — таймер 30 Гц только на главном потоке; окно
  спрятано — кадры не рисуются. Замер `proc_pid_rusage` на этой машине:
  свёрнутый режим ≈0,22–0,26 % CPU в покое, развёрнутый — ≈0,25 %
  (`--background` — ≈0,23 %), то есть компактный круг не дороже большого.
  Совсем слабая машина: снимите «Анимация круга» в настройках — таймер не
  создаётся у обоих кругов; на состояния они всё равно реагируют цветом.
- **Wake-word**: галочка по умолчанию выключена, потому что ожидание держит
  микрофон постоянно. Пока идёт запись или озвучка, микрофон у слушателя
  выключен; с выключенной галочкой `AVAudioEngine` не создаётся. Ложное
  срабатывание возможно на «эй, Ева» в обычной речи — это пара слов, и
  приложение просто перейдёт в «слушаю». Без прав на микрофон/распознавание и
  без офлайн-модели ru-RU ожидание не поднимается (причина в журнале).
  CPU: захват и перенос звука (тап → кольцевой буфер → насос) измерены
  `--selftest-wake-audio` — ≈0,5 % на M-серии; распознавание на устройстве
  добавляет свою долю (зависит от модели и машины), поэтому итоговый процент
  проверяйте `top -l 2 -pid <pid>` на своей машине. Цель задачи — <5 %.
- **Follow-up**: микрофон открывается автоматически только при включённом
  ожидании «Привет, Ева» — без галочки поведение прежнее. Пока Ева говорит,
  записи нет; если `/api/tts` завис (запрос живёт до 120 с), follow-up начнётся
  только после ответа TTS или его ошибки — текст ответа при этом не страдает.
  Фоновый шум или ослышка распознавания может дать «вопрос» из пары слов:
  это цена автоматического микрофона, лечится снятием галочки «Слушать после
  ответа». 60-секундный предохранитель записи действует и здесь.
- **«Стоп, Ева»**: эхоподавление — best effort. `setVoiceProcessingEnabled`
  может быть недоступно на конкретном драйвере (тогда в журнале
  `эхоподавление=выкл`, а от самоподхвата остаётся только защита по тексту
  текущей фразы — «стоп»/«хватит»). Включённый AEC меняет формат входа (на
  проверенной машине 9 каналов) и может приглушать тихую речь; слушатель
  сводит каналы в моно, но не чинит плохой микрофон. Ложное срабатывание
  возможно на обычное «хватит» в разговоре — это цена короткой команды,
  лечится снятием галочки. Задержка распознавания Apple Speech (0,3–1 с) не
  входит в 300 мс отклика: код глушит звук сразу, как только слово распознано.
  Микрофон занимается на время «думаю» и озвучки (небольшой CPU и батарея);
  с выключенной галочкой `AVAudioEngine` для стоп-команды не создаётся.
- **Компактный круг**: одиночный клик разворачивает окно с задержкой
  `NSEvent.doubleClickInterval` (двойной клик должен успеть его отменить) — это
  плата за то, что один и тот же круг служит и кнопкой «Развернуть», и
  «Слушать». Клик не активирует Еву: панель `nonactivatingPanel`, поэтому меню
  и действия доступны без переключения фокуса. Правый клик и перетаскивание
  проверены только кодом и обработчиками (`--selftest-compact` вызывает те же
  `mouseDown`/`mouseUp`, но настоящие жесты с мышью проверяет человек).
  `⌘M` работает, когда главное окно активно: у неактивной `nonactivating`
  панели клавиатурные эквиваленты достаются активному приложению.
- **Картинки сказок**: колонка с иллюстрацией есть только в большом окне; в
  компактном режиме ответ и картинки обновляются в скрытом окне и появляются
  после разворота — на круге ничего не рисуется. Картинка не влияет на
  `speaking`/`idle`. Загрузка идёт в фоне (`URLSession`, base URL сервера),
  поэтому медленный диск/сервер не задерживает текст; на ошибку — один повтор,
  потом иллюстрации просто нет. Кэш в памяти живёт до выхода из приложения
  (до 32 картинок, ~64 МБ): повторная сказка не ходит в сеть. Если колонка
  отобрана у текста, он переносится уже; при узком окне текст остаётся
  читаемым — картинка занимает 190 pt.
- **Темп картинок (0227)**: при озвучке позиция берётся из `VoicePlayer`
  (завершённые фразы + оценка текущей фразы по 15 символов/с), поэтому
  картинка не может появиться раньше, чем речь дошла до её абзаца. Если
  озвучка выключена или TTS упал, работает таймер 15 символов/с; при `silent`
  он отсчитывается от запуска записи на сервере. Оценка не абсолютна: на
  очень медленной или быстрой речи смена может отставать/спешить в пределах
  одной фразы, но по границам абзацев (где плагин и ставит картинки) прогресс
  точный. Позиции в «речевых» символах считаются по фразам, ушедшим в
  `/api/tts`; пробелы и `<think>` в счёт не идут.
- **Silent и две озвучки**: если плагин сказки уже играет запись (`afplay`),
  сервер помечает ответ `silent: true`, и приложение не зовёт `/api/tts` — в
  журнале `озвучка: пропущена (silent)`. Круг при этом не ждёт несуществующий
  звук: `thinking → idle` по первому видимому тексту. Если сервер старой
  версии не присылает `silent`, приложение ведёт себя по-прежнему и озвучит
  текст — это единственный случай двух голосов, лечится обновлением сервера.
- **Сервер**: приложение обращается только к `127.0.0.1` по умолчанию;
  `http://` и произвольный порт — через настройки. Второй колонки и сравнения
  моделей в приложении нет — это отдельный стенд в браузере.
- **История**: общая с браузерным чатом (её хранит сервер). «Новый диалог» —
  кнопка в браузере или `POST /api/reset`.
- **Проверено автоматически**: сборка, подпись, запуск без терминала,
  статус-бар (`type=UIElement`), окно (CGWindowList: `Ева`, круг сверху),
  состояния круга в журнале (`круг: idle → thinking → speaking → idle`),
  запрос `POST /api/chat` с нужным телом и поток SSE, `/api/tts` → WAV RIFF,
  триггер wake-слова и кольцевой буфер (`--selftest-wake`), паузы follow-up и
  правило «только вместе с ожиданием» (`--selftest-followup`), матчер
  «Стоп, Ева», эхо-защита, сведение 9/3 каналов микрофона в моно и план
  «wake или stop, но не оба» (`--selftest-stop`), аудио-путь
  ожидания и остановка `AVAudioEngine` (`--selftest-wake-audio`), отсутствие
  строк `wake:`/`follow-up:` в журнале при выключенных галочках, порядок
  «озвучка доиграла → follow-up: слушаю» в журнале на реальном ответе,
  компактный круг (`--selftest-compact`): живое окно в `CGWindowList`
  (140×140, слой `floating`, прозрачное, без рамки и `nonactivatingPanel`),
  frame внутри `visibleFrame` и ниже строки меню, зажатие после смены/отключения
  монитора, сохранение и восстановление позиции, клик/двойной клик/состав
  правого меню, один `CircleHub` на оба круга, отсутствие перехвата фокуса и
  Dock, картинки сказок (`--selftest-images`: разбор `image`/`silent`, сборка
  URL от адреса сервера, кэш, битый и недоступный URL, окно ответа с колонкой
  картинки и её очистка на новом вопросе, темп 15 симв/с и «картинка не раньше
  позиции»), контракт с сервером
  (`--selftest-chat "расскажи сказку про колобка"` → `image-событий: 4`;
  `--selftest-chat "включи запись сказки"` → `озвучка: пропущена (silent)`),
  живой прогон сказки: 4 иллюстрации скачаны и показаны по порядку, при
  выключенной галочке — `картинка: пропущена — настройка … выключена` и
  только текст, silent-ответ не вызвал ни одного `озвучка: синтез`. В живом
  приложении
  проверены запуск свёрнутым (`вид: свёрнут — запуск свёрнутым (настройка)`,
  в `CGWindowList` только круг 140 pt в правом нижнем углу) и обычный запуск
  (только главное окно, круга нет), а также запуск с `--background`
  (`вид: запуск в фоне`).
  **Реальное распознавание речи** (фраза «Привет, Ева» и следующий вопрос без
  неё) проверяется человеком:
  1. включите «Слушать „Привет, Ева“» и «Слушать после ответа» (12 с);
  2. скажите «Привет, Ева», задайте вопрос, дождитесь ответа и конца озвучки;
  3. не произнося фразу заново, задайте следующий вопрос — круг «слушаю»
     (приглушённый), вопрос должен уйти; в журнале `follow-up: слушаю` и
     `follow-up: услышала вопрос, отправляю`;
  4. после ответа молчите 12 с — в журнале `follow-up: тишина 12 с — ушла в
     ожидание`, круг снова «жду „Привет, Ева“»;
  5. нажмите «Стоп» во время follow-up — запись закрывается без вопроса;
  6. скажите «Стоп, Ева» во время ответа (или «хватит», «тише») — звук должен
     пропасть, в журнале `стоп-команда: услышала „…“`, `стоп: озвучка
     остановлена`; круг `speaking → idle`, затем снова «жду „Привет, Ева“»;
     проверьте и во время «думаю» (до первого звука);
  7. если ответ Евы сам содержит «стоп»/«хватит», её голос из колонок не
     должен глушить озвучку — в журнале `эхо собственной фразы, игнорирую`;
  8. снимите галочку «Слушать „Стоп, Ева“» и повторите — в журнале не должно
     быть строк `стоп:` (микрофон во время речи не держится), кнопка и ⌥Space
     работают как раньше;
  9. заодно посмотрите `top -l 2 -pid <pid>` — ожидание должно укладываться
     в <5 % CPU.

Живой прогон без человека тоже возможен: фраза синтезируется локальным
`POST /api/tts` и проигрывается в колонки (`afplay`), пока приложение слушает.
Так проверены `стоп: слушаю команду (… вход 9 кан. → моно, эхоподавление=вкл)`,
`стоп-команда: услышала „Стоп“`, `стоп: озвучка остановлена`, `POST /api/cancel`
и возврат wake-ожидания. Осталось проверить **живым голосом**: тихая речь в
AEC-режиме, ложные срабатывания на «хватит» и самоподхват, если Ева сама
произносит «стоп».
