# Контракт EVA32 ⇄ orioncode

Один HTTP-эндпоинт, совместимый с OpenAI Chat Completions. Клиент — бэкенд orioncode,
сервер — vLLM с весами EVA32. Всё, что описано ниже, проверяется без модели:
`python3 eval/run_eval.py --dry-run` печатает тела запросов ровно в том виде, в каком их
собирает `build_payload()` в `eval/run_eval.py`.

## 1. Кто владеет промптом

**Предложение (подтвердить):** system-промпт применяет клиент, отправляя содержимое
`prompts/system.ru.md` в поле `messages[0]`. vLLM ничего не подмешивает.

Почему так, а не инъекцией на сервере: промпт — часть версии бандла, его хеш попадает
в `eval/results/*.json`. Если клиент подменит промпт своим, eval будет мерить не то, что
крутится в проде, и правка тона потеряется молча.

Что это накладывает на orioncode:

- файл промпта копируется при релизе байт-в-байт, без «улучшений на месте»;
- в конфиге клиента хранится `prompt_sha256`, при старте он логируется;
- если хеш не совпал с `prompts/system.ru.md` бандла — это ошибка релиза, а не мелочь.

## 2. Запрос

```
POST {base}/v1/chat/completions
Authorization: Bearer <VLLM_API_KEY>
Content-Type: application/json
```

```json
{
  "model": "eva32",
  "messages": [
    {"role": "system", "content": "<содержимое prompts/system.ru.md>"},
    {"role": "user", "content": "Контекст:\n[1] Тариф «Старт» — 990 ₽/мес, до 3 сотрудников.\n\nВопрос: Сколько стоит тариф «Старт»?"}
  ],
  "temperature": 1.0,
  "top_p": 1.0,
  "max_tokens": 1024,
  "stop": ["<|im_end|>"],
  "stream": false
}
```

Параметры генерации берутся из `config/generation.yaml`, а не из головы разработчика.
Клиент их не «подкручивает»: если нужен другой режим — меняется конфиг в бандле и версия.

## 3. Формат контекста

Источники нумеруются по порядку и передаются в user-сообщении перед вопросом:

```
Контекст:
[1] <фрагмент>
[2] <фрагмент>

Вопрос: <вопрос пользователя>
```

Модель ссылается на них как `[1]`, `[2]`. URL и названия документов она не получает и
не выдумывает — клиент сам разворачивает номер в ссылку по своему списку источников.
Если контекста нет, блок не отправляется вовсе: модель должна сказать «не нашла», а не
придумать номер.

Бюджет: всё сообщение (system + контекст + вопрос + ответ) укладывается в 65 536 токенов.
На контекст оставлять не больше ~48 000, лишние чанки отбрасывать на стороне RAG.

## 4. Ответ

Нестриминговый: `choices[0].message.content`.

Стриминговый (`"stream": true`, SSE):

```
data: {"choices":[{"delta":{"content":"Тариф"}}]}
data: {"choices":[{"delta":{"content":" «Старт»"}}]}
data: [DONE]
```

С `"stream_options": {"include_usage": true}` последний чанк приносит `usage`
(`prompt_tokens`, `completion_tokens`) — по нему клиент считает деньги, а не по своим
оценкам длины.

## 5. Ошибки

| Код | Когда | Что делает клиент |
|---|---|---|
| 401 | ключ неверный/просрочен | ошибка конфигурации, не ретраить, шуметь в лог |
| 429 | исчерпаны слоты vLLM | ретрай с backoff, пользователю — «перегружена, секунду» |
| 503 | модель грузится (старт до 15 мин) | ретрай с backoff, healthcheck не зелёный |
| таймаут > 120 с | нет первого токена | один ретрай, потом честная ошибка |

Сырой текст ошибки vLLM пользователю не показывается: в нём бывают внутренние имена
моделей и путей.

## 6. Чего клиент не делает

- не переписывает system-промпт и не добавляет свои правила поверх;
- не доверяет `[n]` как доказательству существования источника — разворачивает только
  те номера, которые сам передал;
- не кладёт в контекст персональные данные, без которых можно ответить;
- не считает ответ юридически значимым: цены и сроки — только из сервисов.

## 7. Версия

Версия бандла = `sha256(промпт + конфиг)` (печатает `make bundle`, пишется в каждый
`eval/results/*.json`). Клиент логирует её при старте и прикладывает к инцидентам:
без этого нельзя сказать, что именно крутилось в момент жалобы.

Версия весов (`MODEL_REVISION`) фиксируется отдельно в `.env` и должна совпадать
с `MODEL_CARD.md`.

## 8. Открытые вопросы (проверить на живой модели, не додумывать)

- **`stop: ["<|im_end|>"]`** унаследован от легаси-персоны на qwen. Для DeepSeek V4-Flash его
  надо сверить с шаблоном модели: если токен чужой, генерация не остановится по нему и ответы
  будут обрываться по `max_tokens`.
- **`thinking: off`** в `config/generation.yaml` — это не флаг vLLM. Скорее всего выключается
  через `chat_template_kwargs` в теле запроса, но точное имя надо посмотреть в карточке модели.
  Пока контракт его не передаёт — значит, режим размышлений не выключен.
- **`MODEL_REVISION`** в `.env.example` — заглушка `replace-with-commit`. Без закреплённой
  ревизии весов контракт верен, а модель за ним — нет.
